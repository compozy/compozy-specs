# ADR-013: Reopen history is daemon-durable closed-entry storage; frame close is one group entry

## Status

Accepted

## Date

2026-07-30

## Context

Product contract: ⌘⇧T restores closed tabs newest-first, multiple levels, with surface + navigation stack, into the original group when it exists (US-008); reopen history survives client reloads (US-008 EC-4); closing a whole frame via the traffic light closes all its tabs — and the user decided that restores as **one** unit. Today `window.close` deletes the window outright; the only restore path (`RestoreWindowID`) serves minimized windows, which still exist in the snapshot. Nothing records closed windows.

## Decision

Add bounded closed-entry storage to the aggregate and one reopen command:

```go
type ClosedEntry struct {
    Windows    []Window       `json:"windows"`              // 1 for a tab close; N for a frame close, deck order preserved
    ActiveID   *WindowID      `json:"active_id,omitempty"`  // frame close: which tab was durably active
    StackID    *NodeID        `json:"stack_id,omitempty"`   // origin stack when it still exists → rejoin target
    DesktopID  DesktopID      `json:"desktop_id"`
    Rect       NormalizedRect `json:"rect"`                 // floating fallback placement
    ClosedAt   time.Time      `json:"closed_at"`
}
// Snapshot gains: ClosedEntries []ClosedEntry `json:"closed_entries,omitempty"` — newest last, capped by closed_entry_limit
```

- Every `window.close` (non-minimize) pushes one entry; the new frame-close form (`CloseWindowCommand.CloseGroup bool`, wired to the deck traffic light and menu) closes every member of the target's stack and pushes a **single** entry with all windows.
- New durable command `window.reopen {}` pops the newest entry: windows are recreated with their `Route`, `NavStack`, and `Pinned` flags; if the origin stack still exists they rejoin it (active per the entry), otherwise a frame entry reconstructs a floating stack at its rect and a single entry becomes a floating window. Unresolvable surfaces open on the truthful parent state (PRD BR-7). Empty history → no-op success.
- The wire snapshot exposes `closed_entry_count` (for enabling ⌘⇧T affordances), not the entries themselves. Entries are excluded from `ExportLayout` (layout ≠ history).

## Alternatives Considered

### Alternative 1: Client-local reopen history

- **Description**: Browser keeps closed-tab records in memory/storage.
- **Cons**: Dies on reload (violates US-008 EC-4), invisible to agents and CLI, diverges across clients sharing a workspace.
- **Why rejected**: Fails the accepted behavior outright.

### Alternative 2: Soft-delete windows in place (`Closed bool`)

- **Description**: Keep closed windows in `Snapshot.Windows` flagged closed.
- **Pros**: Restore is a flag flip.
- **Cons**: Every consumer of the windows map (validation, normalize, projection, listing surfaces, membership-exactly-once invariant) must learn to skip closed windows; the map grows unbounded without a separate reaper.
- **Why rejected**: Poisons every existing invariant for the sake of one command.

## Consequences

### Positive

- Reopen works across clients and restarts, carries full per-tab state, and is agent-reachable (`compozy window reopen`, native tool).
- Frame close/reopen round-trips as the single unit the user chose.

### Negative

- Closed entries enlarge the persisted snapshot (bounded: `closed_entry_limit`, default 20, 1..100; oldest evicted).
- Reopen must handle collisions: IDs are reserved across live windows ∪ retained `ClosedEntries` ("unique while live or reopenable" — caller-supplied opens reject reserved IDs, generated opens regenerate), so a reopen never collides with a live window created after the close. A window revived by layout undo makes its entry stale — reopen consumes the entry and skips live IDs deterministically.

### Risks

- Entry windows referencing deleted desktops → reopen falls back to the active desktop; covered in the reducer suite.

## Implementation Notes

`window.reopen` and closes are history-eligible durable commands, and `ClosedEntries` composes with history **by exclusion**: it is not part of the history `State`, and undo/redo never mutate it. Undoing a close revives the window and leaves its entry stale (reopen's consume rule skips live IDs); undoing a reopen removes the revived windows while their consumed entry stays consumed — a bounded, documented loss. This keeps history states small (no closed-entry deep copies under the snapshot size cap). Hook events: closes emit `window_manager.window.closed`; reopen emits `window_manager.window.opened` (TechSpec §Hooks).
