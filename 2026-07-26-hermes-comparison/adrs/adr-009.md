# ADR-009: Extensibility batch — offline registry cache, conditional skill activation, installable-MCP catalog, parse snapshot

## Status

Accepted

## Date

2026-07-04

## Context

Slice 08 confirmed AGH's extension *mechanism* (out-of-process, capability-gated, typed hooks) is
the correct divergence from Hermes' in-process plugins, but Hermes' *product mechanics* expose four
real AGH gaps: every registry `search`/`info` is a live network round-trip (unusable offline;
`internal/registry` has no cache layer); all enabled skills are advertised to every agent
regardless of platform/tool availability (prompt bloat + truthful-UI violation; Hermes gates
activation conditionally); there is no installable-MCP catalog (Hermes `optional-mcps/` curates
transport/auth/git-install/default-tool subsets); and skill parsing repeats on every cold start
(Hermes persists an index-cache, `.resources/hermes/skills/index-cache/`). AGH already has the
machinery to close each gap cheaply: `MultiRegistry`, `metadata.agh` frontmatter, the `filesnap`
manifest, and the risk-flag model.

## Decision

1. **Offline registry index-cache + optional-official catalog:** TTL-bounded catalog cache in
   front of `MultiRegistry` plus an embedded seed catalog with an `official`/optional tier. Cache
   keys include source+query only — never workspace-scoped installed state.
2. **Conditional skill activation:** extend `metadata.agh` with
   `when.{platforms,environments,requires_tools,requires_capabilities}`, evaluated at catalog build
   (`ForAgent`/`ForWorkspace`, `internal/skills/registry_agent.go:27`) so unavailable skills are
   not advertised. Truthful-UI enforcement + per-turn token savings.
3. **Installable-MCP catalog:** new `mcp` registry `PackageType` with transport/auth/git-install
   manifest + curated default-tool-subset (mutating tools opt-in via the existing risk-flag
   model). Installed MCP tools flow through the existing MCP host — never the native toolset.
4. **Persisted skill parse snapshot:** serialize the parsed catalog keyed by the existing
   `filesnap` manifest; pure cold-start performance.
5. **Sequencing (two-touch):** these are independent techspec-sized units touching distinct
   packages (`internal/registry`, `internal/skills`); do not fold more than two into one patch
   series.
6. **Non-goals:** in-process extension execution, untyped hooks, text-heuristic discovery,
   hardcoded trust allow-lists (Hermes weaknesses AGH must not import); web/UI extension tabs
   (revisit only reconciled with truthful-UI); skill→automation materialization (after this batch).
