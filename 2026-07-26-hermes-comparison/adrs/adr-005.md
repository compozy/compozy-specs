# ADR-005: Shared default-on secret redaction + explicit trust-model doc; classifier and external secret sources declined

## Status

Accepted

## Date

2026-07-04

## Context

AGH redacts secrets only in diagnostics (`internal/diagnostics/item.go` — the sole redaction
boundary found by slice 05, F26). Secrets echoed into agent output, tool results, SSE/event
payloads, or logs are not scrubbed (G2); an unredacted secret in an SSE payload could surface
cross-surface. Hermes redacts broadly by default with a tamper-resistant import-time flag snapshot
and ~40 provider prefixes (`.resources/hermes/agent/redact.py:71-113`). Separately, AGH has no
trust-model document: `BackendLocal` runs agents as host subprocesses with no isolation
(`internal/sandbox/local/provider.go:135-162`) and nothing states it is not a security boundary
(G6), whereas Hermes documents this bluntly (`.resources/hermes/SECURITY.md:41-44,116-119`).

Two sibling proposals were **declined by the user** (2026-07-04 decision round): the daemon-side
command-risk classifier (05 R1 — consistent with the anti-prompt-spam stance recorded in ADR-001;
the sandbox backend remains the containment story) and the external secret-manager source
(Bitwarden/BSM, 05 R3 — the local encrypted vault + `env:` refs remain the supported sources).
These are non-goals for this program, not permanent rejections.

## Decision

1. **`internal/redact` shared boundary, default-on, tamper-resistant.** Promote diagnostics
   redaction to a shared redactor applied to agent-visible output, logs, and SSE/event payloads;
   snapshot the enable flag at process start (changing `[redact] enabled` therefore requires a
   daemon restart — config/CLI/UI surfaces state this; no live toggle that silently no-ops); seed
   with the provider-prefix table adapted from `redact.py`. **Scope boundary (peer-review round 1,
   B-003):** the heuristic engine applies only to free-text/agent-visible content fields and never
   rewrites the structured correlation/hash envelope of the canonical event ledger
   (`claim_token_hash`, session/run ids, fingerprints, idempotency keys); the existing exact
   claim_token/secret-binding redaction remains the authoritative guarantee and the heuristic
   engine is additive defense-in-depth. **Persist-vs-emit ordering (peer-review round 4, N-402):**
   content-field redaction runs BEFORE durable append — the canonical ledger and the per-session
   `events.db` store the redacted form (persist-raw/redact-on-egress forbidden), so history-query
   and resume-replay egress never surface a raw heuristic-class secret. Workspace-isolation
   relevance: prevents secret leakage across SSE/event surfaces.
2. **Author `SECURITY.md` (trust-model doc).** State which layers are boundaries vs heuristics;
   document that `BackendLocal` provides no isolation; document the approval model (ADR-001) and
   the vault/`claim_token` invariants already in `internal/CLAUDE.md`. Reuse the structure of
   Hermes' `SECURITY.md:32-135`.
3. **Non-goals recorded:** command-risk classifier (revisit only with a design that provably adds
   zero prompt classes); external secret sources (revisit on demand).
