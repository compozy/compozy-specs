# ADR-004: Shortcut strategy — grammar first, conservative defaults, personal layer as a built-in preset

## Status

Accepted

## Date

2026-08-15

## Context

The user's daily Herdr keymap is a direct alt-layer (`alt+hjkl`, `alt+o`, `alt+w`, `alt+t`), an `alt+ctrl` cycling layer, and a `cmd+ctrl` workspace layer. Compozy's shortcut system supports exactly one chord per action, has no range bindings, hides the whole tab-action group from the Settings rebind table, hardcodes part of the cheatsheet, and lacks session-navigation actions entirely. Market/platform research flags real hazards in shipping that personal layer as defaults: `ctrl+alt` is AltGr on several European layouts (Microsoft guidance: never use it), browsers reserve or unreliably intercept `cmd+W/T/N` and `cmd+1..9`, and direct alt-chords collide with macOS dead keys and Windows menu mnemonics.

## Decision

1. **Grammar before actions**: the binding vocabulary gains multi-chord arrays per action and `1..9` range chords first; new actions and defaults build on that grammar.
2. **A complete, familiar default keymap**: every new action ships bound on a collision-checked chord chosen for affinity with what users already know — VS Code/Cursor for editor concepts (⌘E sessions view, ⌘B sidebar toggle), macOS Spaces for the desktops layer (⌘⌃ chords), web conventions for help (`?`/⌘/). Weak existing defaults are revised (zoom, desktop overview/switch chords), the hardcoded shell chords (palette, new session, global scope, nav-back) migrate into the rebindable registry, and daily-flow gaps (workspace picker/cycling, desktop switch by number, desktop create) are filled — an unbound daily-flow action is a defect, and extra configuration is friction, not flexibility.
3. **The personal layer ships as a built-in, selectable preset** ("terminal preset") in Settings — the full Herdr-habit profile applied in one click and reversible in one click — instead of becoming the product default.
4. Completeness fixes ride along: every action group (tabs included) becomes rebindable in Settings, and the cheatsheet derives from the registry instead of hardcoded rows.

## Alternatives Considered

### Alternative 1: Alt-layer as product default

- **Description**: Ship the Pedro-aligned profile as everyone's defaults.
- **Pros**: Maximum Herdr parity out of the box.
- **Cons**: Exports AltGr/dead-key/browser-collision risk to every user on every layout; the exact pitfall class the research documents.
- **Why rejected**: Personal ergonomics should not become global risk; the preset delivers the same parity in one click.

### Alternative 2: Unbound-by-default new actions, preset binds them

- **Description**: Ship new actions unbound; only the terminal preset assigns chords.
- **Pros**: Zero collision risk for existing users.
- **Cons**: Default experience stays weak — "almost unusable" was the explicit complaint; forces configuration before daily flows work.
- **Why rejected**: User decision (surface grill K1): strong familiar defaults are the product; the preset is a variant, not the enabler.

### Alternative 3: Config-only personal profile (no preset)

- **Description**: Keep defaults; users hand-author the profile in the configuration file.
- **Pros**: Zero product surface.
- **Cons**: Parity requires manual transcription of ~20 bindings; nothing discoverable; the arrays/ranges grammar exists but nobody benefits by default.
- **Why rejected**: One-click parity is the point; a preset is cheap once arrays exist.

## Consequences

### Positive

- Every user keeps safe defaults; terminal-multiplexer users get the full layer instantly.
- Arrays + ranges unblock both the preset and future per-user layering without grammar rework.
- Settings and cheatsheet finally tell the truth about every binding.

### Negative

- Preset application semantics (conflict handling, revert) become a product behavior to define and test.
- The binding value shape widens — a breaking configuration change with delete targets (greenfield hard cut, no dual shapes).

### Risks

- Preset vs existing custom bindings conflicts → applying a preset must show what changes and win explicitly, reversibly.
- Range chords colliding with single bindings → validation must diagnose across expanded ranges.

## Implementation Notes

Stage 2 fixes the exact default chords per new action (avoiding `ctrl+alt` where layouts break), the preset contents, and the registry/cheatsheet derivation. Both sides of the mirrored grammar change in the same cut.
