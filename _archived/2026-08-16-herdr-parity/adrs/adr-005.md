# ADR-005: Attention truth pipeline — durable projection columns, badge-derived classes, transition events on the existing catalog stream

## Status

Accepted

## Date

2026-08-15

## Context

Attention today is a three-layer hole: pending clarifications never feed `CanonicalBadge` (`internal/session/badge.go`), the catalog SSE wake filter passes only permission events (`internal/session/session_catalog_stream.go:119-124`), and the web bell keys on a single badge value. `PendingPermission` and the clarify broker are boot-scoped process memory, so `waiting-for-auth` and any needs-input state silently vanish on daemon restart. The catalog SSE payload is deliberately a wake signal (`{kind, workspace_id, session_id}` — clients must reconcile snapshots), so no client can observe a state transition, yet notifications are edge-driven by definition. Three near-identical SSE stream stores already exist on the web side; a fourth is a consolidation risk.

## Decision

1. **Truth flows one way, extended in place**: pending-clarify and unseen-finish become `BadgeInputs` fields; `CanonicalBadge` derives the two new tokens (`waiting-for-input`, `done`) under a total precedence order; every surface keeps consuming `SessionPayload.badge`. No surface computes attention independently.
2. **Canonical pending-interaction records live in the global catalog store** (amended, rounds 1–2): a `session_pending_interactions` side-table holds the full restart-recoverable request under a daemon-owned `interaction_id` (provider request ids are process-local; unique per session/kind among pending rows only), with allowlisted, bounded, secret-redacted content, real multi-request cardinality (badge derives from `pending_*_count` columns), and terminal statuses `resolved | timed_out | canceled` plus the `orphaned` pending-variant. Everything commits in **one transaction** with the `sessions` projections; transcript events are observational projections appended after — never authority. Orphaned resolution commits resolution + queued prompt atomically against the existing `session_input_queue` (queue-full aborts with a retryable outcome); discovery is public (interactions route, CLI verb, embedded in session detail/status payloads).
3. **Seen state is maintained through a per-client operator presence lease** (amended, rounds 1–2): acquire returns an opaque `lease_id`; leases key on `(session_id, lease_id)` so no client can release another's; settle evaluation is linearized against the lease map (TTL 15s, ~5s renewal); a settle under any live lease marks seen — never `done`. `MarkSessionSeen` remains the sole mutation path.
4. **Attention causality is catalog-owned** (amended, rounds 1–2): a monotonic `attention_revision` fence plus `last_settled_revision`/`last_seen_revision` define `Unseen` with zero dependence on transcript sequences; `attention_changed_at` (same transaction) is the cross-session ordering key exposed on `SessionPayload`. Seen-clears publish the normal catalog wake before the attention event, so every client's read model refetches.
5. **Transitions publish as a new event type on the existing catalog stream**: `session_attention_changed` carrying `{session_id, workspace_id, from, to, class, at}`. Clients use it exclusively for ephemeral delivery (toast/system/sound decisions stay client-side, where focus is known) and continue refetching authoritative state on wake events — the wake-only contract of `session_catalog_changed` is untouched.
6. **The catalog wake filter widens** to clarify, done, and error events so list surfaces repaint on every attention-relevant edge.

## Alternatives Considered

### Alternative 1: Boot-time replay to rebuild in-memory brokers

- **Description**: Keep pending state in memory; rebuild it by replaying durable events at boot.
- **Pros**: No schema change.
- **Cons**: Boot cost grows with history; permission requests are not durable events today, so persistence work is needed anyway; badge stays dishonest until replay completes.
- **Why rejected**: Columns give an honest badge at boot for the cost of one migration (user decision, grill T1).

### Alternative 2: Per-operator read-marker side-table

- **Description**: `session_read_markers(session_id, operator_id, seq)` for multi-operator futures.
- **Pros**: Models concurrent operators.
- **Cons**: The product models a single operator; no operator identity exists to key on; every read pays a join for a future that is an explicit non-goal.
- **Why rejected**: Columns match the current model (user decision, grill T2).

### Alternative 3: Dedicated attention stream endpoint

- **Description**: `GET /api/attention/stream` separate from the catalog stream.
- **Pros**: Domain isolation.
- **Cons**: A fourth near-identical web stream store; a second connection to manage; the catalog stream is already global and carries workspace ids.
- **Why rejected**: One stream, one store (user decision, grill T3).

### Alternative 4: Enrich the existing catalog event with badge data

- **Description**: Add from/to fields to `session_catalog_changed`.
- **Pros**: No new event type.
- **Cons**: Breaks the documented wake-only contract that clients must not count or interpret catalog events.
- **Why rejected**: Contract doctrine wins; a distinct event type keeps both contracts honest.

## Consequences

### Positive

- Badge honesty survives restarts; `session list --attention` is answerable from the store; the bell inherits correctness by consuming the badge.
- Edge-driven notifications with zero client-side state reconstruction; focus suppression stays where focus is known.
- No new stream store, no new endpoint, no parallel attention state path.

### Negative

- A schema migration on the hottest table (append-only Goose, `eng-schema-migration` discipline).
- Wider wake filter means more list refetches; the web must keep coalescing invalidations.

### Risks

- Presence-lease renewal gaps (tab throttling) could briefly drop a lease for a viewer → TTL (15s) is 3× the renewal cadence; the invariant suite covers settle-at-expiry boundaries.
- The canonical transaction must hold on every path (numbered safety invariant); transcript-append failures are repairable and never corrupt canonical state.

## Implementation Notes

Badge recompute and transition publish ride the existing lifecycle choke point (`persistSessionLifecycleStateLocked`) and the prompt event-storage paths; publish only after the canonical global-catalog commit. `class` values: `needs-you`, `finished`, `none`. Wait registration subscribes before snapshotting (no lost edges, round-1 B-008); unbounded waiting is a CLI loop over bounded waits.
