# ADR-010: DSL failure-vocabulary surface — direct `on_*` triggers, `effects` entries, promoted `retry:`/`timeout:` + new `deadline:`

## Status

Accepted

## Date

2026-08-01

## Context

The node envelope (`dsl/graph.go:28-56`) already carries `Timeout string` (consumed as an
attempt-scoped context deadline by `action_toolcall.go:34`, `action_runagent.go:42`,
`action_runloop.go:29`) and `Retry *RetrySpec` (`dsl/node_params.go:68`, consumed only by the goal
executor at `goal/executor.go:314-321`). The failure vocabulary from PRD ADR-002/003/006 — error
route, explicit absorption, per-trigger side effects, total time budget — has no authoring surface.
The grammar decision shapes the linter, the compiler, docs, the visual editor, and every example a
human or agent ever writes.

Grill outcome (2026-08-01): wrapper keys (`error:` + `react:`) were rejected as verbose; the field
holding the list of things a trigger runs is named `effects` (matching PRD ADR-006's own effect
vocabulary and the Temporal-derived commit-gated effect dispatch internals); `on_error` keeps a
single deterministic shape (no polymorphic list shorthand) because agents are the primary authors
and one schema per key yields the best diagnostics.

## Decision

1. **Triggers are direct keys on the node envelope** — no wrapper blocks. Node-level:
   `on_success`, `on_error`, `on_retry`, `on_pause`, `on_timeout`, `on_cancel`, `on_quarantine`.
   Contract-level (loop terminal outcomes): `contract.on_done`, `on_noop`, `on_blocked`,
   `on_failed`, `on_exhausted`, `on_stalled`, `on_canceled` (the run-level cancel/kill terminal
   — round-2 B-001).
2. **`on_error` is always an object** `{route? | allow_fail?, effects?}` — `route` and
   `allow_fail` are mutually exclusive (validation error when both present); `route` is a
   forward-only edge target. Every other trigger, node- and contract-level, is always a plain
   **list of effect entries**.
3. **An effect entry is `{emit: {kind, payload?}}` or `{tool: <tool_id>, with: {...}}`** — one of
   the two per entry, template-rendered against the namespace plus the pre-bound trigger context.
4. **`retry:` is promoted from goal-only to every action-class node.** `RetrySpec` gains
   `Backoff *BackoffSpec` and `NonRetryable []string`; the goal-only `on_failure: fresh_session`
   member stays goal-scoped (linted exactly as today).
5. **`timeout:` keeps its existing attempt-scoped meaning; new `deadline:` is the total budget**
   (all attempts plus backoff waits, anchored at first schedule). `deadline < timeout` is a
   validation error. Neither has a default — both are pure opt-in (PRD ADR-004).

## Alternatives Considered

### Alternative 1: Separate `error:` (flow) + `react:` (observation) wrappers

- **Description**: `error: {route|allow_fail}` for flow; all seven triggers nested under `react:`.
- **Pros**: Structural mirror of "routes direct flow, reactions observe"; uniform list shapes.
- **Cons**: Two wrapper keys for one mental model ("when this errors, do X"); the flagship
  one-liner lands three levels deep (`react.on_error[0].tool`).
- **Why rejected**: User judgment — more verbose and complex than the value of the structural
  separation, which survives intact *inside* `on_error` (route/allow_fail = flow, effects =
  observation).

### Alternative 2: Uniform object shape for every `on_*`

- **Description**: Every trigger is `{route?, allow_fail?, effects?}`; lint forbids flow fields
  outside `on_error`.
- **Pros**: One shape everywhere.
- **Cons**: Six of seven triggers carry dead fields; the common case (`on_retry: [emit]`) grows a
  mandatory `effects:` nesting level.
- **Why rejected**: Uniformity that only adds boilerplate; the DSL already mixes per-key shapes
  (`on_result` map vs `criteria` list).

### Alternative 3: Polymorphic `on_error` (list shorthand for effects-only)

- **Description**: `on_error` decodes as object or as a bare effect list.
- **Pros**: Saves one line in the pure-notification case.
- **Cons**: Two decode shapes forever; worse diagnostics for agent authors; marginal gain.
- **Why rejected**: Grill decision — deterministic schema per key wins.

## Consequences

### Positive

- The failure story of a node reads top-to-bottom in one place; the flagship notification is three
  lines; agents get one JSON-schema shape per key.
- `retry:`/`timeout:` reuse existing envelope fields — promotion, not new surface.

### Negative

- `dsl.Node` grows five fields (`Deadline`, `ResultContract`, `OnError`, the trigger lists via
  one `Triggers` member, and `OnParentClose`) — the envelope is a flat struct by design, so
  this is accepted.

### Risks

- Trigger keys are near the gate `on_result` map in spirit but different in shape — docs must
  contrast them explicitly (routes on gates come from verdicts; `on_error.route` comes from node
  failure).
