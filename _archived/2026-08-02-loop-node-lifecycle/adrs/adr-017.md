# ADR-017: Parked states — `wait` control kind, governed resume, node pause with auto-pause rules, loud admission dedupe

## Status

Accepted

## Date

2026-08-01

## Context

The engine has four dormancy mechanisms, none generic: `plan.Yield` (unpersisted, wake-driven),
run-level `needs-approval` (gate escalation), run-level `paused` (two-stage flag + reactivation),
and goal-only `awaiting_goal` with epoch-fenced grants (`GoalGrant*` — the strongest precedent:
atomic grant, monotonic `ControlEpoch`, `Existing` flag for exactly-once). There is no timer wait,
no node-level pause, no per-pause-point identity, and no admission dedupe (`loop_admission_claims`
does not exist; watch redelivery double-runs loops today). Sim supplies the wait mechanics worth
copying (iteration-scoped pause ids, single-writer resume claim, 3×60s admission retries →
`intervention_required`) and the gap to close (expiry column never written); PRD ADR-005 fixes the
posture: indefinite by default, visible always, escalation authorable, waiting suspends
work-accounting.

## Decision

1. **New control kind `wait`.** `ControlKind` gains `wait` with params
   `{for: <duration> | until: <timestamp-template> | event: <subscription>, expect?: <schema>,
   ahead_arrival?: consume_on_entry | reject (default consume_on_entry), expires?:
   {after: <duration>, escalate?: [ladder], route?: <node_id>}}`. Reaching the node parks the
   cell as `waiting`, writes the `loop_node_waits` row (identity = node + item_index +
   generation — Sim's iteration-scoped id), and yields. Timer waits set `resume_at`; event waits
   subscribe through the watch-events registry; approval escalation ladders on gates reuse the
   same row with `next_escalation_at`.
2. **Governed resume, exactly once, in one transaction.** `ResumeWait` is a single
   `BEGIN IMMEDIATE` store operation (the `ReactivateGoalRun`/`ReactivateLoopCoordinator`
   precedent, made explicit by round-1 review B-003): payload validation against `expect` →
   claim win/observe on `claim_state` → wait/output/control transition → provenance + lifecycle
   event append → deterministic coordinator `task_run` reservation — all before commit. A
   claimed-without-enqueue state is unrepresentable; replay returns the existing winner;
   concurrent attempts get deterministic `already_resolved`/`queued` answers with the winner's
   provenance; invalid payloads reject with a diagnostic and the wait stays parked; admission
   failures retry 3×60s then flip the row to `intervention_required` — visible, never limbo.
   The due-scan (ADR-012) re-arms timers after restart.
3. **Node pause is a control-row verb, rule-drivable.** `pause` marks
   `loop_node_controls.paused` with provenance (actor, reason, manual-vs-rule); the coordinator
   excludes paused nodes from scheduling, rerun sets, stall/no-progress signatures, and due-scans;
   in-flight attempts drain or cancel per the verb's `drain|cancel` choice. `resume` variants:
   plain, `reset_attempts`, `immediate` (skip pending backoff). Auto-pause rules live in loop
   defaults config: ordered `[{match: <CEL over {node_id, family, target, class, attempt}>,
   action: pause}]`, validated at write (compile + field check), first match wins, named in
   provenance, no re-fire on the same episode without recurrence (PRD Rules 26–28).
4. **Clock suspension is one rule applied to one state set.** `paused | waiting |
   awaiting-approval | quarantined` cells: excluded from stall arithmetic and no-progress
   signatures, excluded from due-scans (except their own escalation), suspend authored node
   clocks (anchors shift on resume), and suspend the run's wall-clock budget accounting; token
   spend always counts (PRD ADR-005.4, Rule 27). One predicate function owns this classification
   so no path can diverge.
5. **Admission dedupe is a claims table in the start transaction.** Watch-triggered starts derive
   `(workspace_id, loop_name, source_key, event_key)` — `watch-events` from the committed event's
   stable id, `watch-source` from a new required identity field in `PollResponse`
   (`event_key`; extensions must populate it) — and `INSERT OR IGNORE` into
   `loop_admission_claims` inside `CreateLoopRunForStart`'s transaction. Conflict → no run, a
   `duplicate_suppressed` diagnostic event on the original run, and a structured suppression
   answer with the original `loop_run_id`. Tombstones persist ≥ the configured horizon (default
   7d). A source that cannot yield `event_key` fails definition validation
   (`watch_identity_required` lint); at runtime an empty/oversized/malformed `event_key`
   (normalized NFC, ≤ 256 bytes) fails closed before admission with a `watch_identity_invalid`
   diagnostic (round-1 review N-004) — no random fallback, no silent pass-through (v0/Sim holes
   closed).

## Alternatives Considered

### Alternative 1: Model waits as gate escalation only (no `wait` kind)

- **Description**: Overload human gates for timers/events.
- **Pros**: No new node kind.
- **Cons**: Gates are verdict machinery with revisions and approval semantics; a timer is not a
  verdict; authors would encode `sleep` as a fake approval — dishonest vocabulary.
- **Why rejected**: A first-class parked primitive is the honest shape; it reuses the gate plane's
  reactivation, not its semantics.

### Alternative 2: In-memory pause (flag on the coordinator runtime)

- **Description**: Pause as runtime state, not rows.
- **Pros**: No schema.
- **Cons**: Restart loses pauses; inventories impossible; provenance unrecordable — everything
  US-019/022 requires.
- **Why rejected**: Parked runs must be as durable as running ones (PRD US-021 heading).

### Alternative 3: Dedupe claim outside the start transaction (Sim's shape)

- **Description**: Claim first, start later, release on failure.
- **Pros**: Matches the reference.
- **Cons**: Sim needed a compensating `finally` because claim and start could diverge; same-tx
  `INSERT OR IGNORE` makes the race unrepresentable.
- **Why rejected**: ADR-009 (PRD) demands claim-with-start atomicity; SQLite gives it in one
  statement.

## Consequences

### Positive

- Approvals, timers, and event waits share one durable row shape, one claim discipline, one
  inventory; redelivery after restart becomes one run + N loud suppressions.

### Negative

- Extension watch sources must add `event_key` — a breaking contract change for the
  `loop.watch_source` provide surface (greenfield: manifest/spec docs updated, no compat).

### Risks

- The clock-suspension rule touches budget accounting semantics — the single classifier function
  plus invariant tests keep pause/wait/approval/quarantine consistent (PRD ADR-005 risk owned
  here).
