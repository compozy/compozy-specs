# ADR-006: Flat `.compozy/` Namespace and Explicit Config Migration

## Status

Accepted

## Date

2026-07-11

## Context

The `.agh/` to `.compozy/` hard cut merges AGH runtime state with existing
legacy workspace artifacts and legacy configuration at the same paths. Legacy
global homes also contain daemon state that cannot be carried forward. The
configuration reference has drifted, so the migration baseline is the legacy
`ProjectConfig` Go struct at stable tag v0.2.15 (`8f8908afd70c731b815e20282bacad05aa026827`), plus the explicitly audited post-tag HEAD (`c202311c8430fc0d4a7442e2dc715cabfbdc68a1`), not prose documentation.

## Decision

1. **The namespace is flat.** One `DirName` changes `.agh/*` to `.compozy/*`.
   A workspace contains `.compozy/{workspace.toml,compozy.db,skills/,agents/}`
   alongside committable `tasks/` and `config.toml`; runtime-state entries are
   gitignored. Database names change to `compozy.db`. There is no state-data
   migration or compatibility shim.
2. **Migration targets are explicit; no current-directory discovery occurs.**
   `compozy migrate config` migrates the global config by default. An optional
   `--workspace <absolute-path>` selects exactly one workspace config instead.
   It never infers a workspace from the current directory. Global and workspace
   files are migrated by separate, independently reported invocations.
3. **Every decoded legacy key has one recorded disposition.** The migrator
   uses the pinned v0.2.15 `ProjectConfig` schema and audits every post-tag HEAD addition separately, emitting a report entry
   for every recognized key: `translated` with an exact target, or `dropped`
   with a guide reference. In particular:
   - `defaults.ide`, `defaults.model`, and supported `defaults.reasoning_effort`
     expand to worker and judge runtime defaults in both delivery and watch
     categories; `defaults.timeout` maps to `session.limits.timeout`, and
     `defaults.auto_commit` maps to the declared `software-delivery` and
     `review-and-fix` inputs;
   - `[defaults.by_complexity.{low,medium,high,critical}]` translates to ordered complexity runtime rules;
   - ordered `tasks.run.task_runtime_rules` translate as type-only rules to `[loops.defaults.delivery].runtime_rules` without inventing persisted id/workflow selectors;
   - ~~`fetch_reviews.nitpicks` translates to `include_nitpicks`, and `watch_reviews.{auto_push,push_remote,poll_interval,quiet_period}` translate to the identically declared `[loops.inputs.review-and-fix]` inputs;~~ **[amended by ADR-008: those inputs no longer exist — `defaults.auto_commit` is the only review-related key with a declared destination;]**
   - every `fix_reviews` key, `fetch_reviews.{provider,nitpicks}`, and `watch_reviews.{auto_push,push_remote,poll_interval,quiet_period,max_rounds,review_timeout,until_clean,push_branch}` is dropped with its guide reference **[amended by ADR-008: the entire external-review family drops because v0.3 review is agent-authored]**. The legacy schema has no persisted `defaults.provider` or `defaults.pr`, so the migrator never fabricates either;
   - the provider map is `codex -> codex`, `claude -> claude`,
     `cursor-agent -> cursor`, `opencode -> opencode`, `pi -> pi`,
     `gemini -> gemini`, `copilot -> copilot`, and `kiro -> kiro`; `droid`,
     `devin`, and legacy-only reasoning `ultra` are reported as unsupported
     destination values rather than silently aliased or weakened;
   - every other leaf enumerated by `ProjectConfig` -- including the remaining
     defaults and stall fields, task-selection/multiple/parallel fields,
     `recovery`, `sound`, `runs`, and `exec` -- is dropped individually according
     to the canonical matrix owned by Task 09.
   Unknown/unparseable input is a structural error, not a silent drop.
4. **Migration is non-destructive and idempotent.** Before an in-place rewrite,
   the migrator writes a timestamped backup and durable marker. A second run
   for that target refuses rather than translating twice. It never deletes
   legacy daemon directories.
5. **Legacy-format and namespace-collision detection precede strict runtime decoding.** A lightweight
   format/topology probe runs before the new loader in daemon startup and in the local
   CLI bootstrap for `status` and `doctor`. It recognizes the legacy shape and
   legacy-owned `agents/` or `extensions/` at colliding global/workspace
   `.compozy` paths without interpreting or enrolling them as v0.3 resources, emits
   `legacy.state_detected {paths}`, and points to `migrate config`; normal
   startup remains blocked until strict v0.3 configuration can load. HTTP and
   UDS are truthfully unavailable while that daemon cannot boot. After config
   migration, retained orphan-state warnings are emitted by the running daemon
   through the shared CLI/HTTP/UDS status/doctor payload without deleting data.
   Config migration does not rewrite `agents/` or `extensions/`; their manual
   relocation/removal is explicit guidance because their legacy formats are not
   compatibility inputs.
6. **Configuration is not CLI-only agent management.** The migrator is a
   local, file-oriented CLI operation because it can run before the daemon.
   That exception does not make dynamic loop configuration CLI-only: its
   inspect/update/delete surfaces remain available through the managed CLI,
   HTTP, UDS, and native-tool contract defined by ADR-007.

## Alternatives Considered

### A separate runtime-state directory

It would make the split cleaner but turns the hard rename into divergent home
layouts. The flat cut is the smaller, consistent change.

### Comment out unsupported keys

Commented or inert legacy keys imply support and violate strict configuration
validation and zero-legacy policy.

### Load the legacy config as a fallback

That would be compatibility code. The pre-decode probe is diagnostic only;
the migrator is the single translation path.

## Consequences

- Runtime history and daemon state restart cleanly, while legacy files remain
  available for inspection and cleanup.
- The guide can mirror a deterministic per-key migration receipt.
- Workspace choice is explicit, preventing an agent or shell from modifying an
  unintended repository configuration.
- Legacy resource directories cannot be silently interpreted under a new owner
  merely because the hard cut reuses the `.compozy` namespace.

## Implementation Notes

Update home and database constants, implement the probe before normal config
load, and keep migration parsing/reporting separate from runtime config
decoding. Test separate global and explicit-workspace invocations, including
v0.2.15 and separately audited post-tag HEAD fields, backup refusal, every translation/drop, and
legacy-state diagnostics.
