# ADR-008: Agent-Authored Review — `review-and-fix` Without External Providers

## Status

Accepted

## Date

2026-07-26

## Context

ADR-003 made the artifact writer source-agnostic but kept CodeRabbit as the
only fetched review source: the loop graph watched a PR, fetched unresolved
CodeRabbit threads, resolved them on GitHub after remediation, and optionally
pushed the branch. The reviewer agent appeared only as a verification judge,
and the agent-authored `ReviewIssue[]` path existed as a writer contract
(IT-011), not as the product flow.

That inverts the intended product. `review-and-fix` must be a simple internal
journey — a Compozy agent reviews the work and a following node remediates the
findings — useful with zero external services, zero `gh` calls, and zero PR
context. Brief round 12 (2026-07-26) closed this decision.

## Decision

1. **The reviewer agent is the round's source.** Each generation starts with a
   `run-agent` node executing the dev-cycle `reviewer` agent, which reviews
   the current work for the named task and emits source-agnostic
   `ReviewIssue[]` through its `output_schema`. There is no fetched provider,
   no watch source, and no poll/quiet cadence.
2. **The graph is review → write → fix → finalize.** When the review returns
   issues, `ext__dev_cycle__write_review_artifacts` writes the round,
   the fixer fan-out remediates by issue-file paths (activating
   `cy-fix-reviews`), and `ext__dev_cycle__finalize_review_round` rewrites
   statuses. A clean review round (zero issues) terminates the loop. The next
   round's review verifies the previous round's fixes, so the loop has no
   separate judge/verify gate and no thread-resolution or push tail.
3. **ADR-003's writer authority stands, minus provider provenance.** The Go
   writer exclusively owns round allocation, timestamps, serialization,
   status transitions, containment, and exclusive round creation (ADR-003
   decisions 2–4, 6–7). `ReviewIssue` drops the fields only a fetched
   provider ever filled — `provider`, provider reference, `review_hash`,
   source review ID, source submitted-at — and the provenance-based history
   dedupe goes with them. Rounds remain append-only; re-running the loop
   creates a new round and never mutates an earlier one.
4. **The issue schema is validated, not defaulted.** The reviewer's
   `output_schema` requires `title`, `body`, and `severity`; `file` and
   `line` stay optional so general findings (missing tests, contract drift)
   remain expressible. The writer normalizes a missing `file` to `unknown`
   for batching and rejects schema-invalid records with a structured error
   instead of inventing legacy provider fallbacks (`Review comment`,
   `_No review comment body provided by provider._`).
5. **Deterministic bytes stay; legacy byte-parity goes.** Artifacts keep the
   inspectable `.compozy/tasks/<task>/reviews-NNN/issue_NNN.md` layout,
   deterministic frontmatter order, fixed body headings, the unreviewed
   triage marker, and the monotonic `pending → valid|invalid → resolved`
   lifecycle — verified against v0.3-owned golden fixtures. Byte-identity
   with v0.2.15 is no longer a contract; the migration guide documents the
   deliberate non-parity.
6. **Inputs shrink to the internal journey.** `task_name` is required (no
   `pr-<N>` derivation), `reviewer`/`fixer` agent inputs keep their defaults,
   and `auto_commit` remains the only execution-mode input because it is
   local-only. `pr`, `include_nitpicks`, `poll_interval`, `quiet_period`,
   `auto_push`, and `push_remote` are delete targets. Round caps use the loop
   contract (`iteration_cap`, `no_progress`), not a new input.
7. **Hard cut, no abstraction.** All CodeRabbit code, types, tool
   descriptors, the `gh`-shim test dependency, and the watch/resolve/push
   nodes are deleted. No review-provider abstraction replaces them; v0.3.0
   ships no external review fetch/resolve surface at all.

## Alternatives Considered

### Keep CodeRabbit as an optional secondary source

Keeping fetch/resolve behind a flag preserves the external dependency, the
`gh` shim, and the dual-source graph complexity for a path the product does
not want as its journey. Rejected.

### Reviewer as judge over provider-fetched issues (status quo)

The specified v0.3 graph. It makes the P0 review journey unusable without
CodeRabbit and GitHub, and demotes the intended agent review to a
verification gate. Rejected.

### A review-provider abstraction with an agent provider

Re-introduces the legacy abstraction that round 1 deliberately deferred,
with exactly one implementation. Rejected.

## Consequences

- The dev-cycle extension loses the CodeRabbit fetch/resolve tools and their
  schemas/digests; the manifest re-enrolls with only the writer/finalizer
  tool additions.
- The generic loop-engine watch-source capability (`internal/loop/watch`,
  the extension watch-source contract) is explicitly NOT a delete target:
  it remains a supported product surface for user-authored loops. This
  decision removes only dev-cycle's CodeRabbit usage of it; after the cut
  no bundled extension provides a watch-source kind, and that is
  acceptable.
- IT-011's agent-authored writer path is promoted from side contract to the
  canonical loop flow; provider-fetch test contracts (`gh` shim journeys)
  are deleted rather than rewritten.
- The migrator (task 14) drops every `watch_reviews.*`/`fetch_reviews.*` key
  report-only; only `defaults.auto_commit` still translates to a
  `review-and-fix` input.
- `[loops.inputs.review-and-fix]` examples across specs use surviving inputs
  (`task_name`, `auto_commit`).

## Amends

- **ADR-003** — the source-agnostic writer, containment, round, and
  finalization decisions remain in force; its CodeRabbit-as-fetched-provider
  context, provenance dedupe, and graph note are superseded by this record.
