# ADR-004: Dev-Cycle Bundles Nine Skills From `.agents/skills`; Authoring Runs in Managed Sessions

## Status

Accepted

## Date

2026-07-11

## Context

The legacy setup command distributed skills into many external coding-agent
homes. The runtime has no supported writer for those homes. Its established
extension resource path can instead publish bundled skills to managed AGH
sessions through the extension manifest, MCP projection, and prompt
augmentation.

The source of truth for the migrated development skills is the repository's
`.agents/skills/` tree, not the legacy repository's `compozy/skills/` path.
The official runtime product-overview skill is separately renamed from
`skills/agh/` to `skills/compozy/`; it must not collide with a bundled skill of
the same name.

## Decision

1. **Bundle exactly nine skills.** Dev-cycle embeds these directories from
   `.agents/skills/`: `cy-create-prd`, `cy-create-techspec`, `cy-create-tasks`,
   `cy-execute-task`, `cy-workflow-memory`, `cy-review-round`,
   `cy-fix-reviews`, `cy-final-verify`, and `git-rebase`. They land at
   `extensions/dev-cycle/skills/<name>/SKILL.md`, are declared by
   `resources.skills: ["skills"]`, and are included by `go:embed`.
   The legacy `compozy` skill is retired; the official `skills/compozy/` skill
   owns that product-overview name. `cy-capture-decisions` is explicitly
   excluded and deferred: it is not part of the locked nine-skill migration.
2. **Managed-session projection is the supported delivery path.** A user
   authors through `compozy session new`, `prompt`, `resume`, or the web UI;
   the spawned agent CLI receives the extension-projected skills. v0.3.0 does
   not recreate `compozy setup` or add external-CLI install targeting. Manual
   download/copy guidance remains documentation, not a product API.
3. **Publication is global but workspace behavior is explicit.** Bundled
   resources publish globally once per installed extension version, then project
   into managed sessions in every eligible workspace. The two-workspace case
   must prove that one global publication does not duplicate, leak mutable
   workspace state, or make one workspace's configuration authoritative for
   another. Skills are immutable embedded resources; their visibility is
   intentional first-party global scope, not workspace data.
4. **Content and dependency sweep co-ship.** Bundled skill bodies remove
   retired CLI/config/setup instructions and use the loop-based CompozyOS
   surface. `embed_test.go` updates references used by dev-cycle agents; in
   particular, the review fixer uses the file-path artifact contract of
   ADR-003.

## Alternatives Considered

### External CLI install targeting

Extending `skill install` to detect and write many external agent homes creates
a new product surface and maintenance matrix. It is deferred.

### Technical bundles

`resources.bundles` cannot carry skills in the current projection model, so it
is structurally the wrong mechanism.

### Postponing skills

Dev-cycle agents already name these skills. Shipping loops without their skill
authority would be a silent functional gap.

## Consequences

- `SourceBundled` keeps its immutability/content-scan semantics, and a manifest
  checksum/version change re-enrolls the extension.
- All workspaces can see the nine first-party development skills, while
  workspace-specific data remains isolated.
- Users of external personal CLIs lose native slash-command installation unless
  they follow manual documentation; the migration guide states this plainly.

## Implementation Notes

Copy the locked nine source directories from `.agents/skills/`, preserve each
skill's valid frontmatter, update `extension.json` and `embed.go`, then test
manifest loading, all nine parsed files, two-workspace publication, and the
absence of retired commands or a bundled `compozy` skill.
