# ADR-007: Palette views are a Go-owned typed descriptor vocabulary with JSON Patch live updates

## Status

Accepted

## Date

2026-08-17

## Context

ADR-004 fixed the view kinds (List, Detail, Form, Grid); ADR-002 requires extension views to cross the daemon boundary as data with no extension code in the renderer. Dedicated research (2026-08-17, `ext-views-research`) compared three architectures for the serialization/rendering contract — (a) fixed typed descriptor vocabulary owned by Go, (b) `json-render.dev` with a curated component registry, (c) sandboxed iframe views — scoring security, keyboard/a11y integration with cmdk, design-system fidelity, schema evolution, Go authoring ergonomics, and testability: **29 vs 17 vs 15**. json-render's value is constraining LLM output — a guarantee our typed Go daemon already provides — its catalog is TS/Zod-first with no JSON Schema export (permanent dual source of truth), and its generic tree renderer fights cmdk's ownership of focus and item registration. Raycast (JSON render tree + JSON Patch over JSON-RPC) and Zed's visual-extension RFC ("extensions compose primitives, they don't draw pixels") independently converged on host-rendered fixed vocabularies; Stripe ended up banning arbitrary markup even inside full iframe sandboxing; Figma's Realms sandbox escapes show sandboxes are not free security.

## Decision

The view contract is a **fixed, versioned, Go-owned descriptor vocabulary**:

- **Vocabulary**: typed Go structs (JSON tags = wire format) for the four kinds — sections, rows, chips, detail metadata/rich text, form fields, grid tiles, and named actions. Host React components (`@compozy/ui`-composed) are the only renderers; cmdk keeps ownership of lists, focus, and filtering.
- **Versioning**: Adaptive-Cards-style — a contract `version` plus per-element `requires`/`fallback` (including `"drop"`); unknown elements hit a Null-Object renderer that logs a capability gap instead of crashing; authored manifests fail validate on unknown kinds.
- **Live data**: view payloads update via **RFC 6902 JSON Patch** over the existing SSE/UDS channels — the same mechanism serves streaming fills and live refresh, and enables host-driven virtualized row windows.
- **Actions**: rows/tiles/forms carry **named actions** resolved and dispatched by the daemon (the ADR-002 action union); extensions never define host-side handlers.
- **No `@json-render/*` dependency.** Sandboxed iframe views remain a possible future, explicitly opt-in "rich view" tier under its own ADR; if a wire standard ever matters, A2UI is the one to track.

## Alternatives Considered

### Alternative 1: json-render.dev with curated registry

- **Description**: `@json-render/react` rendering specs against a registry of Compozy components.
- **Pros**: Ready runtime; streaming (SpecStream) built in; schema-agnostic core.
- **Cons**: Solves LLM-constraint (a problem we don't have); TS/Zod source of truth with no JSON Schema export → Go side hand-mirrored (drift generator); pre-1.0 churn (~200 releases/8 months); docs silent on keyboard/focus/virtualization/a11y; ~1.5 MB dependency; fights cmdk.
- **Why rejected**: Research verdict 17/29; user confirmed rejection (internals grill, 2026-08-17).

### Alternative 2: Sandboxed iframe views in v1

- **Description**: Extensions ship UI into isolated frames with postMessage bridges.
- **Pros**: Maximum expressiveness; host contract stays tiny; extension owns its evolution.
- **Cons**: Cross-document focus/arrow-key handoff is the hardest keyboard problem; token/theme duplication; CSP/null-origin/postMessage hardening on us; Playwright-only testability; Figma's sandbox-escape history.
- **Why rejected**: 15/29; expressiveness beyond the fixed kit is exactly what ADR-004 excludes for this cycle.

## Consequences

### Positive

- One source of truth: Go structs define the wire; web types are generated; validation is compile-time + schema.
- Keyboard, a11y, virtualization, and design tokens stay entirely host-owned — extension views are indistinguishable from built-ins.
- Table-driven Go tests for descriptors; Storybook/RTL for renderers — independently testable layers.

### Negative

- We own a (small) rendering-engine contract: vocabulary evolution, fallback semantics, and patch application are ours to maintain.
- Expressiveness is capped at the vocabulary — deliberate, but authors will ask for more.

### Risks

- Vocabulary creep — mitigated: new element kinds require an ADR (inherited from ADR-004).
- Patch/stream ordering bugs — mitigated: revision-fenced patches, full-payload resync on gap detection.

## Implementation Notes

Struct definitions, patch envelope, and the generated TS types land in Part II Core Interfaces / Data Models. The web renderer reuses the existing view-shell chrome (`_uiux.md` S2).
