# ADR-006: v1 extras — ⌘K tab search, menu-based merge/move, pinned tabs; peek deferred

## Status

Accepted

## Date

2026-07-30

## Context

Beyond the core deck contract (reference D1–D8), market research surfaced candidate enhancements: cross-window tab search, menu-based merge/move (the macOS four-verb contract), pinned tabs, hover peek-without-attach, live sub-labels, and ephemeral preview tabs. The user selected which enter v1. Ephemeral preview tabs were not offered: the reference contract already prevents the problem they solve (drill-in navigates within the tab and never spawns tabs, rule D2). Live sub-labels don't fit 96–180px tab segments; tooltips carry the detail instead.

## Decision

**In v1:**

1. **⌘K tab search** — the palette lists every open tab across windows and desktops; choosing one focuses its window, activates the tab, and switches desktop when needed. This is the overflow escape hatch that always works.
2. **Menu-based merge/move** — "Merge all windows" (combine the current desktop's windows into one group) and "Move tab to new window", available from the tab context menu and palette, completing the macOS four-verb contract without requiring drag.
3. **Pinned tabs** — browser semantics: pinned tabs collate at the left of the deck, shrink toward glyph-only, persist durably, and refuse ⌘W/hover-close (unpin first). Lifecycle semantics are irrelevant here — sessions survive tab close regardless (ADR-004).

**Deferred (explicit non-goals for v1):** hover peek-without-attach (inline preview/answer without switching), live sub-labels on tabs, ephemeral preview tabs.

## Alternatives Considered

### Alternative 1: Core deck only (no extras)

- **Description**: Ship D1–D8 alone.
- **Pros**: Smallest scope.
- **Cons**: No always-works overflow escape (a market table-stake), incomplete merge verbs, no protection for long-lived tabs.
- **Why rejected**: The three selected extras are cheap relative to their leverage and two are table stakes, not delights.

### Alternative 2: Include peek in v1

- **Description**: Ship hover peek with inline reply.
- **Pros**: Highest-delight differentiator for an agent OS.
- **Cons**: A large feature (preview rendering, inline composer, focus rules) riding on an unshipped foundation.
- **Why rejected**: User deferred it; it layers cleanly on top of v1 later.

## Consequences

### Positive

- Overflow never strands a tab (search), merge verbs match Mac muscle memory, and long-lived tabs get accidental-close protection.

### Negative

- Pinning adds a durable per-tab flag and a distinct visual class to the deck spec.

### Risks

- Pin + multi-instance can crowd decks with glyph-only stubs — mitigated by pin being manual-only and reversible.

## Implementation Notes

Merge-all scope is the current desktop. Pinned state is durable workspace state (rides ADR-003's durable side).
