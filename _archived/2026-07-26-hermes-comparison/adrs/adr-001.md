# ADR-001: Durable approval grants + `agh__clarify`, under the three-mode ceiling

## Status

Accepted

## Date

2026-07-04

## Context

Two confirmed defects share one surface. First, the ACP tool-approval prompt advertises "Allow
always"/"Reject always" (`internal/daemon/tool_approval_bridge.go:196-203`) but the outcome handler
collapses both to their one-shot variants and persists nothing
(`internal/daemon/tool_approval_bridge.go:183-193`); the only durable-ish path consumes single-use
tokens (`internal/daemon/tool_approval_bridge.go:151-163`). The user's durable choice is a lie —
every subsequent call re-prompts (defect D1, `analysis/summary.md`). Second,
`RequiresInteraction` forces approval but no channel exists for an agent to actually ask the user
anything; extensions can declare `requires_interaction` tools (`internal/extension/manifest.go:187`)
that AGH cannot service (defect D7). Hermes ships both halves: a persisted `command_allowlist`
(`.resources/hermes/tools/approval.py`) and a blocking `clarify` tool (question + ≤4 choices,
`.resources/hermes/tools/clarify_tool.py`, `.resources/hermes/tools/clarify_gateway.py`).

The binding constraint (explicit user directive, 2026-07-04): Hermes' approval UX is prompt-spam
and AGH must not import it. AGH's three-mode policy — `deny-all`/`approve-reads`/`approve-all`
(`internal/tools/policy.go:21-31`, default `approve-reads` at `:118`) — is the registered system
authority (archived ADR-005, `.compozy/tasks/_archived/1777917998846-32668a9b-tools-registry/adrs/`
`adr-005-acp-approval-policy-integration.md`): registry/tool policy integrates with it, never
bypasses it and never forms a parallel approval system.

## Decision

1. **Durable approval store.** Persist `allow_always`/`reject_always` selections in a scoped store
   keyed by `{workspace_id, agent_name?, tool_id, input_digest?}`; consult it BEFORE prompting.
   Management surfaces: `agh__tool_approvals_{list,revoke}` native tools + CLI/HTTP/UDS parity.
   **Default persistence width (peer-review round 1, B-001):** a prompt answer always persists the
   most-specific key (`workspace_id + agent_name + tool_id + input_digest`); wider grants
   (agent-wide or tool-wide) are created only through the explicit management surfaces — never as
   the default effect of answering a single prompt (least-privilege + truthful-UI).
2. **Anti-spam invariants (non-negotiable).** The three modes remain the sole ceiling; the durable
   store only *widens* auto-approval (remembers grants) — it never introduces a new prompt class,
   never re-prompts on a remembered grant, and never adds dynamic per-command classification
   (the Hermes-style command-risk classifier was explicitly declined in this program).
3. **`agh__clarify` native tool.** `{question, choices[≤4]}` blocks for a user answer returned as
   the tool result, modeled on the pending-request/resolve channel of `internal/acp/permission.go`,
   with a config timeout. **Timeout fallback contract (peer-review round 1, B-002):** on timeout
   the broker resolves with the explicit unanswered sentinel (`Choice=nil`, `Text=""`,
   `Fallback=true`) — it never synthesizes a selection, and callers (including
   `RequiresInteraction` routing) must treat the sentinel as "the user did not answer".
   `RequiresInteraction` tools route through it. Clarify is a question channel initiated by the
   agent — it is NOT an approval prompt and does not change approval frequency.
4. Sandbox-level `PermissionDecisionAllowAlways` (`internal/sandbox/types.go`) is a distinct,
   already-persistent surface and is untouched.
