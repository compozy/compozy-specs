# ADR-004: Workspace checkpoint/restore scoped to AGH-native mutating tools

## Status

Accepted

## Date

2026-07-04

## Context

AGH has no daemon-level undo: a destructive `agh__*` operation on the workspace has no rollback
path (slice 02 §5 "No workspace rewind"). Hermes auto-snapshots the workspace with a shadow git
before mutating turns (`.resources/hermes/tools/checkpoint_manager.py`). But Hermes owns its
file-write path; AGH does not — delegated ACP agents run their own edit tooling, often in their own
worktrees/sandboxes, so AGH cannot transparently checkpoint *their* mutations
(`analysis/04_analysis_reliability-resilience.md` §5: "applicable only to AGH-native tools").
Slice 03 §3.7 independently lists file-change checkpoints among lifecycle affordances users lack.

## Decision

1. Add daemon-level shadow-git checkpoints **only around AGH-native tools that mutate the
   workspace** — never around delegated-agent edits (their tooling owns that path).
2. Surfaces: `agh__checkpoint_{list,diff,restore}` native tools + CLI/HTTP/UDS parity; store under
   `$AGH_HOME` keyed per workspace (workspace-isolation audit required); retention by
   count/size/age via config.
3. Adapt Hermes' git-redirection + pre-rollback-snapshot design (a restore itself snapshots
   first). **Restore blast radius (peer-review round 3, N-301):** restore is diff-scoped — it
   reverts only the paths captured in the snapshot being restored; unrelated working-tree changes
   (including delegated-agent edits made after the snapshot) survive, and overlapping paths are
   surfaced in a restore preview before applying.
4. Reconcile with the existing worktree-isolation model to avoid double bookkeeping — if a native
   tool operates inside an isolated worktree, one snapshot mechanism must own that surface,
   enforced mechanically (the checkpoint manager consults the worktree-isolation resolver before
   every snapshot and skips isolated-worktree surfaces).
