# ADR-010: Reliability batch — lifecycle self-protection, memory observability, draining state, health action loop, dead-entity registry

## Status

Accepted

## Date

2026-07-04

## Context

Slice 04's governing insight: Hermes protects one long-lived process under an external respawn
supervisor; AGH is a daemon delegating LLM work to ACP subprocesses — so Hermes' in-process LLM
resilience is rejected for the delegated path, while its *process self-protection* maps onto AGH's
daemon. Five gaps confirmed: (1) nothing blocks an agent-authored schedule/tool call from
restarting the AGH daemon itself — under any respawn supervisor this reproduces Hermes' SIGTERM
loop incident (`.resources/hermes/cron/lifecycle_guard.py:48-66`; converges with slice 06 rec 3 on
the `agh__automation_jobs_create` path); (2) no daemon RSS/heap observability — a slow leak is
invisible until OOM (`.resources/hermes/gateway/memory_monitor.py`); (3) no graceful drain — AGH
quiesces by killing subprocess groups (`.resources/hermes/gateway/drain_control.py`, file-marker
mechanism rejected since AGH has a real control channel); (4) `internal/subprocess/health.go`
computes an unhealthy verdict nothing consumes (defect D5); (5) repeatedly-probed dead externals
(extensions/bridges/MCP sidecars) are hammered cyclically with no self-healing dead-set
(`.resources/hermes/gateway/dead_targets.py`).

## Decision

1. **Agent-lifecycle self-protection guard:** creation-time validator rejecting agent-authored
   schedules/tool calls containing AGH-daemon lifecycle commands (`agh daemon stop|restart`,
   service-manager operations on the agh unit, `pkill … agh`), enforced at the schedule-creation
   seam in `internal/automation` covering CLI and the native-tool path. Command-shaped regex (not
   prose matching) to avoid false positives. One implementation serves 04 R1 + 06 rec 3.
2. **Daemon memory observability:** background goroutine logging structured `[memory]` lines (RSS
   via `runtime/metrics`, heap, goroutines, uptime) at a configurable interval (default 5m, `0`
   disables) + baseline/shutdown snapshots + a `runtime.memory` doctor probe.
3. **First-class `draining` state:** gates new prompt/run admission, lets in-flight work finish,
   driven by `drain`/`undrain` HTTP+UDS+CLI endpoints (never a file marker); existing
   subprocess-group teardown becomes the post-drain step; status/doctor reflect `draining`. If
   drain intent is ever persisted, stamp with a per-boot nonce.
4. **Close detection→action for subprocess health:** unhealthy verdicts surface as a doctor probe
   + status degradation; config-gated escalation of persistently-unhealthy agents to
   `needs_attention` via the existing scheduler escalator (`internal/scheduler/starvation.go`).
   No subprocess auto-restart in this program (restart-loop budget deferred until auto-restart
   exists).
5. **Self-healing dead-entity registry** for extensions/bridges/MCP sidecars: durable set, mark on
   confirmed-permanent failure, auto-clear on success, exposed via CLI + doctor probe;
   workspace-scoped so one workspace's dead sidecar doesn't suppress another's.
6. **Scoped extras:** bridgesdk error-taxonomy split (`overloaded` 529 vs generic transient) +
   decorrelated jitter applied ONLY to first-party outbound calls — and per the two-touch rule, if
   this is the third change to the retry surface it must consolidate toward one shared retry
   package, not add a fourth helper.
7. **Non-goals:** `cgroup_cleanup.py` (procutil covers it), `code_skew.py` (Python-specific),
   wholesale LLM failover import into the orchestrator, `batch_runner`/`checkpoint_manager` as-is.
