# ADR-005: Operator-presence boundary — daemon-verified process ancestry, nonce-bootstrapped web authority, and a DB-backed toggle

## Status

Superseded by ADR-006 (2026-07-28 — beta posture: instructional enforcement; technical boundary deferred to a future security ADR. Kept as the design record for that future work; round-3 review found the ancestry mechanism escapable via `setsid`/double-fork, see `qa/peer-review-findings-round3.md` B-001)

## Date

2026-07-28

## Context

Peer review round 2 (B-001, B-006) demonstrated that the round-1 operator token is itself an escalation path on the current runtime substrate: managed sessions inherit `COMPOZY_HOME` in their environment, `home_policy = operator` is the default, and the default local sandbox does not isolate the filesystem — so a `0600` token file under `$COMPOZY_HOME` is agent-readable. The SPA shell (and any bootstrap payload embedded in it) is agent-fetchable over loopback because the HTTP guard validates the daemon's bind address, not the client. Direct edits to `~/.compozy/config.toml` bypass any daemon-mediated mutation gate entirely. The reviewer's structural conclusion: same-UID execution, loopback HTTP, UDS, and provider-home policy must be solved as **one** operator/managed-agent boundary, not as independent patches.

The boundary must answer one question with daemon-verifiable evidence: *is this request from the operator, or from (a descendant of) a managed agent session?* — without ever serializing a reusable raw secret into agent-reachable storage.

## Decision

Three coordinated cuts:

1. **The toggle becomes daemon-owned DB state, not a config key.** `workspace_access.cross_workspace` in `config.toml` is dropped entirely (no struct, no overlay, no lifecycle entry). The global toggle lives in a singleton `workspace_access_state` row in the global DB (`cross_workspace`, `revision`, `updated_at`, `updated_by`), mutated only through the operator-authorized surface below — the exact pattern `workspace_network_coordination` already ships (revision-checked, authorizer-gated, agent-manageable). Direct file edits can no longer flip the boundary; the policy's `ToggleSource` reads this row and fails closed on read errors by construction.

2. **Operator authority on UDS = process-ancestry verification.** The daemon already spawns and supervises every managed session subprocess (process-group ownership in `internal/procutil`). On a UDS connection, the daemon resolves the peer PID (`SO_PEERCRED` / `LOCAL_PEERCRED`), walks its ancestry, and classifies the connection **agent-origin** if any ancestor belongs to a managed session's process tree (registry of session PIDs/process groups + start times, checked per connection to defeat PID reuse). Operator-restricted operations (toggle mutation, grant set/revoke, global grant listing, global status, owner projection) require an operator-classified UDS peer — or the web authority below. There is no secret to steal: authority derives from verifiable process lineage. Agent identity headers, when present, additionally force agent-origin regardless of ancestry (defense in depth); their absence proves nothing.

3. **The web inherits authority through a one-time nonce.** `compozy open` (running on an operator-classified UDS connection) asks the daemon to mint a single-use, short-TTL nonce and opens `http://127.0.0.1:<port>/?operator_nonce=<n>`. The SPA exchanges the nonce for an HttpOnly, SameSite=Strict, boot-scoped operator session cookie; the nonce is consumed on first exchange. HTTP requests carrying the cookie are operator-classified; all other loopback HTTP is unprivileged (can browse, cannot mutate workspace access or read its global surfaces). A browser without the cookie sees the Settings section read-only with the exact `compozy open` hint. No reusable credential ever lands in `$COMPOZY_HOME`, the SPA shell, or session-visible state.

## Alternatives Considered

### Alternative 1: Static operator token file (round-1 design)

- **Description**: `$COMPOZY_HOME/operator.token`, 0600, required header on mutations.
- **Pros**: Trivial to implement; transport-agnostic.
- **Cons**: Agent-readable under default `home_policy=operator` + non-isolating local sandbox; sessions literally receive `COMPOZY_HOME`; refuted by round-2 B-001 with file-level evidence.
- **Why rejected**: The credential's storage sits inside the adversary's reach; a boundary that depends on optional isolation policies is not a boundary.

### Alternative 2: Keep the toggle in `config.toml`, watch and re-guard the file

- **Description**: Config key stays; daemon detects out-of-band edits and re-applies policy checks.
- **Pros**: Preserves the original "uma config" shape.
- **Cons**: The global config file is agent-reachable under the same defaults; watching cannot distinguish operator edits from agent edits; adds reconciliation machinery to defend a location that is simply wrong for security state.
- **Why rejected**: Storage location is the vulnerability; moving the state is a hard cut, watching is a bridge. The CLI/Settings UX is preserved by the DB-backed design anyway.

### Alternative 3: Operator surface restricted to CLI/UDS only (no web authority)

- **Description**: Ancestry-verified UDS is the only operator surface; web Settings is read-only v1.
- **Pros**: Smallest sound design; no nonce/cookie machinery.
- **Cons**: Violates surface parity expectations (SD-011: HTTP/UDS parity for daemon-state mutations) and degrades the Settings UX the user selected.
- **Why rejected**: The nonce bootstrap is small, and parity matters; kept as the documented fallback if the cookie flow slips.

## Consequences

### Positive

- No stealable operator credential exists at rest; authority is process lineage (UDS) or a browser-held boot-scoped cookie bootstrapped through that lineage.
- The direct-file-edit bypass disappears structurally; every toggle transition is revisioned, attributed (`updated_by`), and evented.
- B-006's read-surface leak closes with the same primitive: global reads require the same operator classification as mutations.
- One boundary, one classification function, one test surface.

### Negative

- UDS peer-PID ancestry walking is platform-specific (`/proc` on Linux, `sysctl kinfo_proc` on macOS) — new `procutil` surface with per-OS code and Windows fallback semantics to define.
- The web flow adds a nonce exchange + cookie session store (in-memory, boot-scoped) to the daemon.
- An agent-driven CLI (`compozy` run inside a session via its shell tool) is operator-denied by ancestry even for read verbs that are operator-restricted — intentional, but it changes the error surface for agents (deterministic diagnostic + hint).

### Risks

- **PID reuse / ancestry races**: mitigated by resolving peer credentials per connection, comparing against the live session-process registry with start-time validation; when ancestry cannot be determined, classify agent-origin (fail closed).
- **Detached/orphaned agent processes** (double-fork escaping the session tree): the session registry tracks process groups; processes that escape supervision are outside the managed-session set and classify as operator — residual risk documented as part of the same-UID threat-model limitation (a hostile same-UID escapee is outside this spec's model, as in round 1, but now nothing it can *read* grants standing authority; it would need to originate requests, which audit records).
- **Cookie theft from browser storage**: boot-scoped and HttpOnly; a same-UID process reading browser cookie jars is again the documented threat-model boundary.

## Implementation Notes

New pieces: `workspace_access_state` singleton table (+ Goose migration, sqlc, repo); `internal/daemon` operator classifier (UDS peer → ancestry → classification; HTTP cookie session store; nonce mint/exchange endpoints); `procutil` ancestry helpers with per-OS implementations; `compozy open` gains the nonce request; core handlers take a resolved `OperatorPresence` instead of transport guards. `privilegedMutationGuard()` (loopback check) is superseded for workspace-access surfaces by the classifier. The classifier is also the gate for `GET /api/workspace-access`, global grant listing, and the session owner projection (B-006).
