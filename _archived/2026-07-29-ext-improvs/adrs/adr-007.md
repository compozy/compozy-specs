# ADR-007: Extension config consolidation — `[extensions.trust]` + `[extensions.sources]`; `[extensions.marketplace]` deleted

## Status

Accepted

## Date

2026-07-28

## Context

Two config families govern "where extensions come from and what may install": `[marketplace.catalog]` (cross-kind curated feed: `base_url`/`ttl`/`timeout` — `internal/config/marketplace.go:24`) and `[extensions.marketplace]` (`registry`, `base_url`, `allow_unverified` — `extensions_marketplace.go:4`). The audit flagged this as one mental model split across two sections, with docs round-tripping between pages to find the canonical `config set` key. The `extensions.resources.*` family is settable via CLI but documented nowhere. ADR-002 collapses trust affordances to policy + consent; ADR-005 introduces the source union (curated/github/git/local_path — dev is a lifecycle overlay, not a source), which `registry = "github"` (a single string) cannot express.

## Decision

Hard-cut restructure of the extension config surface:

```toml
[extensions.trust]
allow_unverified = true      # operator policy; per-install consent still required (ADR-002)

[extensions.sources.github]
enabled  = true              # default on (ADR-005)
base_url = "https://api.github.com"

[extensions.sources.git]
enabled = true

[extensions.dev]
watch_interval = "2s"        # CLI-side watch poll cadence

[extensions.resources]        # unchanged shape — now documented
```

- `[extensions.marketplace]` is **deleted** (delete target): `registry` is superseded by per-source `enabled` flags; `base_url` moves under `sources.github`; `allow_unverified` moves to `trust`.
- `[marketplace.catalog]` **stays as-is** — it is the cross-kind curated feed (mcp/extension/skill), not an extension-only concern; renaming it under `[extensions]` would misname the skills/MCP catalog.
- `allow_unverified` default flips to `true` **because consent remains mandatory per install** (the flag is the consent; policy exists as the operator opt-out for locked-down installs). The pre-ADR-002 default (`false` + consent + `--yes`) is the fail-closed-twice behavior the audit scored 2/5.
- Full lifecycle in the same change: structs, defaults, merge/overlay, validation, `compozy config set` key registry, examples, generated CLI/site docs, and tests.

## Alternatives Considered

### Alternative 1: Everything under `[extensions]` including the curated catalog

- **Description**: Move `[marketplace.catalog]` to `[extensions.catalog]`.
- **Pros**: One section prefix.
- **Cons**: The curated feed serves skills and MCP servers too; the rename would be a lie and would force skill/MCP docs to reference an `extensions.*` key.
- **Why rejected**: Misnames a cross-kind subsystem to serve a prefix aesthetic.

### Alternative 2: Keep `[extensions.marketplace]`, add keys

- **Description**: Grow the existing section with `sources.*` sub-keys.
- **Pros**: No key deletions.
- **Cons**: "Marketplace" is the wrong word for the union (dev and git are not marketplaces); SD-002 forbids preserving misnamed sections for continuity in alpha.
- **Why rejected**: Greenfield naming discipline; the section name is part of the concept bill.

## Consequences

### Positive

- One prefix answers "extension install behavior"; every key documented; `config set extensions.trust.allow_unverified` is discoverable from the error remediation text.

### Negative

- Breaking config change — operators with the old keys get a validation error naming the new key (no alias, no fallback, per SD-002).

### Risks

- Default-on GitHub source surprising locked-down operators → `enabled = false` is one key; consent gates still apply to every unverified install.

## Implementation Notes

`ExtensionsConfig` gains `Trust ExtensionsTrustConfig`, `Sources ExtensionsSourcesConfig`, `Dev ExtensionsDevConfig`; `ExtensionsMarketplaceConfig` deleted; `config_extensions.go` CLI key registry updated; validation rejects unknown legacy keys with the replacement named in the error.
