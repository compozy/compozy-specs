# ADR-002: Discovery Lists Every Git-Known Worktree; Adoption Is Selection With Identity Validation

## Status

Accepted

## Date

2026-08-11

## Context

Users arrive with worktrees created by plain `git worktree add`, by other tools (Claude Code's own worktree feature, Conductor, hand-rolled sibling checkouts), or by previous Compozy runs. The stated requirement is that Compozy "identifies the worktrees created from that workspace so they can be selected".

All three competitor repos treat git itself as the discovery source of truth (`git worktree list --porcelain`), never an internal index (`.resources/synara/apps/server/src/git/Layers/GitCore.ts:2056-2113`; `.resources/t3code/apps/server/src/vcs/GitVcsDriverCore.ts:240-268`; `.resources/herdr/src/worktree.rs:404-492`). They diverge on attachment: herdr lists external worktrees but attaches only on explicit open; Superset ships a dedicated Import tab with bulk import; nobody auto-attaches ambiently. Claude Code contributes the safety half: it refuses to adopt a directory whose git metadata resolves back into the main checkout (where a `git reset --hard` would destroy the parent) and leaves refused directories on disk because they may hold work (analysis `05_analysis_market-worktree-ux.md`, Mechanisms "Discovery / adoption").

## Decision

- The daemon lists **every worktree git knows about** for a workspace's repository — Compozy-created and external alike — and navigation renders all of them nested under the parent workspace.
- External worktrees appear in a **discovered** state, visually distinct from adopted ones.
- **Selecting a discovered worktree adopts it**: Compozy mints its identity and it becomes a first-class worktree from that moment. Adoption never re-runs environment bootstrap by default (an existing worktree is already set up).
- Adoption is gated by **identity validation**: a directory whose git metadata does not resolve to the workspace's repository — or resolves into the main checkout — is refused with a deterministic error, and the directory is left untouched.
- Worktrees whose directory disappeared (pruned or deleted out-of-band) are reported truthfully as missing/stale, never silently dropped and never cascaded into runtime-state deletion.
- Discovery never mutates git state on its own (no implicit prune, no implicit fetch).

## Alternatives Considered

### Alternative 1: Import-only (Superset model)

- **Description**: Navigation shows only Compozy-created/adopted worktrees; external ones surface exclusively through an explicit import flow (individual or bulk).
- **Pros**: Cleaner navigation for repos with many stray worktrees; import is an auditable moment.
- **Cons**: Existing worktrees are invisible until the user finds the import flow — the exact opposite of "Compozy identifies the worktrees of that workspace"; extra flow to build.
- **Why rejected**: Fails the stated discovery requirement; hides daemon-known truth from navigation.

### Alternative 2: Compozy-created only

- **Description**: External worktrees never appear and cannot be adopted.
- **Pros**: Simplest possible model.
- **Cons**: Walled garden; punishes every user with a pre-existing workflow; contradicts git-as-source-of-truth.
- **Why rejected**: Fails the requirement outright.

### Alternative 3: Ambient auto-attach

- **Description**: Any discovered worktree is silently registered as a full Compozy worktree.
- **Pros**: Zero-friction.
- **Cons**: Mints identities and runtime records the user never asked for; no consent moment for validation refusals; no competitor does this.
- **Why rejected**: Registration without a user gesture creates state the user must later clean up; the selection gesture is the natural, zero-extra-UI consent point.

## Consequences

### Positive

- The navigation answers "what worktrees does this workspace have" completely and truthfully, including tool-agnostic ones.
- Migration from other tools is free: select the worktree, it is adopted.
- The identity-validation refusal closes the known data-loss vector (metadata resolving into the main checkout).

### Negative

- Repos with many stale external worktrees produce longer nested lists; the discovered/adopted distinction and stale reporting must carry the disambiguation.

### Risks

- Discovery latency: enumerating worktrees shells out to git; list surfaces must not block on it or hammer it per render. Mitigation belongs to the TechSpec (caching + explicit refresh), bounded by the truthfulness rule: stale data must be marked, not presented as current.

## Implementation Notes

Discovery parsing, caching, and refusal diagnostics are TechSpec scope. The refusal semantics to preserve verbatim: validate before adopting, refuse with a named reason, never delete or modify the refused directory.
