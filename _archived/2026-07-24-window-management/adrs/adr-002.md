# ADR-002: Owner-Bound Focus Desktops and Client-State Format Identity

## Status

Accepted

## Date

2026-07-27

## Context

Focus desktops were originally reusable. Unzoom cleared `focus_owner` but kept the empty desktop in
the workspace snapshot. Tightening topology validation so every focus desktop requires an owner then
made those already-persisted snapshots unreadable: both snapshot reads and client registration
returned `window_manager_invalid_topology` before a semantic command could run.

Command-specific cleanup covered close, minimize, and unzoom but left other owner-exit paths such as
individual move, group move, swap, and layout replacement able to produce the same invalid state.
Repairing snapshots in `NormalizeSnapshot` or while loading persistence would hide those producers and
keep the old persisted contract alive.

The Window Manager is currently the only production consumer of `clientstate.db`. Compozy is still a
greenfield alpha, so local pre-contract state may be discarded instead of migrated.

## Decision

A focus desktop exists only while its declared owner belongs to it. After every successful durable
reduction, `releaseDetachedFocusDesktops` applies the lifecycle once:

- an empty detached focus desktop is deleted;
- a detached focus desktop with resident windows is converted to a standard desktop;
- the final desktop is converted to standard rather than deleted.

The same primitive runs on layout replacement candidates before equality and topology validation.
`NormalizeSnapshot` remains limited to deterministic representation cleanup and never repairs focus
ownership. Snapshot validation includes both the current topology and every undo/redo state, so
history cannot restore an ownerless focus desktop.

`clientstate.db` now has an explicit bbolt store-format identity. Opening an empty file writes format
version 1. Opening an unversioned or older file atomically deletes all pre-contract buckets and writes
the current identity before the Engine becomes available. Opening a newer format fails without
changing the file. No obsolete payload is decoded, normalized, or copied forward.

The public Window Manager snapshot label remains version 2 because it is the current unshipped
contract and is hard-cut in place. The new store-format identity, rather than a compatibility reader,
separates snapshots written before and after this invariant.

## Alternatives Considered

### Weaken Focus Validation

Rejected. An ownerless focus desktop rejects later placements and has no valid lifecycle meaning.

### Normalize Persisted Snapshots on Read

Rejected. Read-time repair would preserve an obsolete contract, hide invalid producers, and mutate
meaning outside the semantic command pipeline.

### Delete Only the Known Local Snapshot Key

Rejected. Manual cleanup repairs one machine and recurs for every existing development database.

### Change Only the Repository Namespace

Rejected. Ignoring old bytes without explicitly disposing of them leaves ambiguous state in the
authoritative store.

## Consequences

### Positive

- Every durable command path shares one focus-owner lifecycle.
- Invalid focus topology cannot remain hidden in undo or redo history.
- Existing pre-contract development state is removed once, before repository reads.
- Current-format state remains durable across daemon restarts.
- Ahead-format files fail closed and retain their contents.

### Negative

- The first daemon start after this hard cut removes all existing `clientstate.db` workspace state.
- A structured `clientstate.store.hard_cut` warning is emitted when pre-contract data is discarded.

## Delete Targets

- Reusable empty focus-desktop selection.
- Command-specific focus release branches.
- Ownerless-focus repair in `NormalizeSnapshot`.
- Unversioned client-state storage without an explicit format identity.
