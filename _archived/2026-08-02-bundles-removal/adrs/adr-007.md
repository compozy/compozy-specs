# ADR-007: Dir-per-agent static agent contract with SOUL/HEARTBEAT sidecars

## Status

Accepted

## Date

2026-07-29

## Context

Static extension agents load via `collectMarkdownFiles`, which recursively parses **every** `.md` under `resources.agents` paths as an `AgentDef` (`internal/extension/manager_resource_loading.go:127-155`). Consequences: a `SOUL.md`/`HEARTBEAT.md` placed beside `AGENT.md` fails the register phase (strict frontmatter parse), so static extension agents cannot ship authored-context sidecars at all — sidecar packaging exists only on the bundle path, which uses a strict per-directory contract (`bundle_agent_loader.go:16-51`: path must be a directory containing `AGENT.md`; `SOUL.md`/`HEARTBEAT.md` optional, parsed and validated at load).

Everywhere else in the product the agent unit is already a directory: `$COMPOZY_HOME/agents/<name>/AGENT.md` with sidecars beside it, and `dev-cycle` itself already ships `agents/{code_implementer,review_fixer,reviewer}/AGENT.md`.

## Decision

Hard-cut `resources.agents` to the dir-per-agent contract, absorbing the bundle loader semantics:

- Each `resources.agents` entry is a directory whose immediate subdirectories are agent dirs: `<entry>/<agent>/AGENT.md` (required) + optional `SOUL.md`, `HEARTBEAT.md`, `mcp.json`, `capabilities.toml`.
- `SOUL.md`/`HEARTBEAT.md` are parsed and validated at register time (`soul.Parse`/`heartbeat.Parse` with default configs); a malformed sidecar fails the register phase deterministically, naming the file.
- On enable, the publisher emits `agent` + `agent.soul` + `agent.heartbeat` records sharing `Owner{Kind:"extension", ID:<name>}` and scope, so catalog sidecar matching works and heartbeat policy is honored (`PackageOwned`, ADR-004).
- Loose `.md` files directly under a `resources.agents` entry are rejected with a deterministic validation error naming the expected layout (no dual-shape acceptance).
- Package-owned agents remain read-only through the authored-context API (existing `PackageOwned` rule), now applying to extension-owned agents.

## Alternatives Considered

### Alternative 1: Dual-shape acceptance (flat files and dirs)

- **Description**: Keep flat `.md` agent files working; treat directories as the sidecar-capable form.
- **Pros**: No fixture updates; softer transition.
- **Cons**: Two authoring shapes forever, one of which silently cannot carry sidecars; greenfield policy forbids keeping the old shape (SD-002); the flat walk still mis-parses stray markdown.
- **Why rejected**: Zero-legacy: one contract, and the repo's real kit (`dev-cycle`) already uses dirs.

### Alternative 2: Flat files + sidecar naming convention (`<agent>.soul.md`)

- **Description**: Keep flat files and add sibling sidecars by filename convention.
- **Pros**: Flat layout preserved.
- **Cons**: Invents a third sidecar convention diverging from `$COMPOZY_HOME/agents/<name>/` and the authored-context API path resolution; `mcp.json`/`capabilities.toml` sidecars have no home.
- **Why rejected**: Diverges from the product-wide agent-directory format for no benefit.

## Consequences

### Positive

- Extension agents reach parity with home/workspace agents: one directory format, full sidecar support, live on enable with no second step (P0.1 satisfied).
- The mis-parse failure class (`every .md is an AgentDef`) is deleted.

### Negative

- Breaking authoring change for any flat-file extension agents — in-repo cost is test fixtures only (`internal/daemon/agent_skill_resources_integration_test.go` uses `agents/ext-agent.md`); `dev-cycle` is already conformant.

### Risks

- Code-first packaging: generated manifests must be able to declare the agents dirs — covered by ADR-008.

## Implementation Notes

`collectMarkdownFiles` remains for any other consumer; the agents loader stops using it. The loader is a rehome of `bundle_agent_loader.go` logic (which is deleted with the bundle schema): dir validation, `AGENT.md` load, sidecar read+parse, path containment. Docs (`develop.mdx`) teach the directory layout; `compozy extension init` agent-bearing guidance and examples follow it.
