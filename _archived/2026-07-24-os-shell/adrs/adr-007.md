# ADR-007: v1 operator-load posture — attention via bell + badges + rail; anti-clutter via minimize + spaces + palette + zoom

## Status

Accepted — amended by [ADR-009](adr-009.md) (2026-07-20): the edge-snapping follow-up is pulled into the program (task_09, window snap layer). The attention queue and auto-arrange ("tidy") remain post-MVP follow-ups.

## Date

2026-07-19

## Context

The market's documented pains for multi-agent supervision are "which agent needs me now" (attention) and cognitive overload from managing many surfaces (the exact failure mode that made Figma revert floating panels). The v1 scope is already fixed by the TechSpec's MVP boundary; the PRD must declare how v1 answers both pains within that scope, and which stronger answers are deliberate follow-ups rather than accidental gaps.

## Decision

- **Attention (v1 answer):** three truthful surfaces — the menubar approvals bell (count + approve/deny), dock badges on sessions/tasks (runtime-backed counts), and the sessions rail status vocabulary (running / waiting / failed / done / idle). No new attention primitive in v1.
- **Anti-clutter (v1 answer):** four declared tools — minimize-to-dock, per-workspace spaces, the ⌘K palette as zero-spatial-cost navigation, and window zoom for temporary single-window focus.
- **Named follow-ups (post-MVP, pulled in only with usage evidence):** a first-class "needs you" attention queue that aggregates approvals + waiting sessions + reviews and focuses the right window in one action; edge snapping / half-screen tiling; an auto-arrange ("tidy") command.

## Alternatives Considered

### Alternative 1: First-class attention queue in v1

- **Pros**: Attacks the market's #1 pain head-on.
- **Cons**: Reopens the closed TechSpec (new surface, stories, tests) with no prototype design; risks shipping a guessed design for the program's most sensitive surface.
- **Why rejected**: v1 ships the proven prototype surfaces; the queue is designed later against real usage.

### Alternative 2: Edge snapping or auto-arrange in v1

- **Pros**: Direct mitigation of the desk-clutter criticism; snapping is trained OS muscle memory.
- **Cons**: No prototype design; drop zones/preview/persistence are real scope; the TechSpec names both as post-MVP.
- **Why rejected**: Same reopen cost; minimize + spaces + palette + zoom already give v1 a defensible clutter answer.

## Consequences

### Positive

- PRD and TechSpec stay consistent — no scope reopen; the operator-load story is declared, not implied.
- Follow-ups are recorded as deliberate bets with explicit pull-in triggers.

### Negative

- v1's attention answer is distributed across three surfaces rather than one aggregated queue; heavy multi-agent operators may feel that seam first.

### Risks

- If real usage shows attention fragmentation quickly, the follow-up queue becomes the first post-v1 TechSpec — the PRD's Open Questions name the trigger.

## Implementation Notes

All v1 surfaces here are already specified in `_techspec.md` (menubar bell, dock badge adapter, rail status vocabulary, minimize/zoom, spaces, palette). This ADR only fixes the product posture and the follow-up ledger.
