# ADR-001: Generation-boundary repair context instead of in-body cycles

## Status

Accepted

## Date

2026-08-01

## Context

arXiv 2607.19297 (LangGraph recipes) demonstrates repair loops as statically declared back-edges
(`sql_validation → sql_generation`, `retry_or_clarify → retrieve`) with a state-carried bound
(`attempts <= retry_limit()`). Its own doctrine (§6): "Immediate retries are appropriate when the
failure message is useful input for the next attempt." A full re-read (2026-08-01) established that
**nothing in the paper requires a runtime-generated graph** — all three recipes compile a fixed node
set and fixed route map; the only delta vs Compozy is declared, bounded back-edges.

Compozy's loop body is a strict DAG (`internal/loop/linter.go` `detectCycles` → `CodeCycle`,
blocking). Iteration happens at the generation boundary — but today no repair context crosses it:

- The namespace is a closed root set (`inputs`, `nodes`, `generation`, `item`, `index`;
  `internal/loop/control_namespace.go:25-39`, enforced by `dsl/refs/namespace.go:77-109`).
- Fresh generations zero all node outputs (`control_plan.go:101-120`); revised nodes get blank
  outputs (`coordinator_generation_reattempt.go:240-245`).
- Gate verdicts are readable only in the same generation after the gate ran; the DoD verdict never
  reaches any namespace (`control_contract_gate.go:113-133`).
- Prior generations are read exclusively by stall detection (`coordinator_terminal_helpers.go`).

Without the failure payload crossing the boundary, a generation restart is a blind retry — which the
paper explicitly says does not justify a graph (Table 1: a plain retry wrapper already covers it).

Prior art exists one level down: `internal/loop/goal` injects `lastVerdict` + blocking issues into
the next turn prompt (`goal/route.go:219-220`, `goal/templates.go:102-119`).

## Decision

1. Add two read-only namespace roots, valid in node templates and CEL conditions:
   - `previous.*` — the immediately preceding generation: `previous.generation`,
     `previous.nodes.<id>.{status,output}`, and LOSSLESS verdicts keyed by gate ID —
     `previous.verdicts.<gate_id>.{outcome,score,blocking_issues,criteria}` plus
     `previous.route_causes` (the persisted, deterministically ordered gate-ID list whose
     verdicts caused the route, including the DoD contract gate). A generation can evaluate
     several gates; a singular `previous.verdict` would be lossy and order-undefined
     (peer-review B-003), so it does not exist.
   - `best.*` — the ratchet target (ADR-003): `best.generation`, `best.score`,
     `best.nodes.<id>.output` (output-only projection type).
   Both are empty objects on generation 1 / when no metric gate exists. Static validation
   (`ValidatePath`, CEL var set, linter reference builders) is extended in the same change.
2. Keep the strict-DAG lint. In-body cycles are **rejected** — repair is expressed at the
   generation boundary, which with (1) is functionally equivalent to the paper's declared
   back-edges while preserving static lintability, closed terminal outcomes, per-generation audit,
   and generation-scoped budget accounting.

## Alternatives Considered

### Alternative 1: Declared back-edges with mandatory bound (paper option)

- **Description**: Allow `route: retry → <ancestor>` edges to already-executed nodes, bound by a
  state-carried counter, keeping the graph statically checkable.
- **Pros**: Direct 1:1 with the paper; finer-grained than a whole-generation restart.
- **Cons**: Breaks the DAG invariant every layer relies on (linter, compiler inlining of sub-loops,
  topology-ordered planning, stall arithmetic, UI timeline); creates two iteration mechanisms
  (in-body cycle + generations) with overlapping semantics; revision/audit becomes edge-scoped
  instead of generation-scoped.
- **Why rejected**: The paper's cycles are only a delivery vehicle for "failure feeds the next
  attempt". The generation boundary already exists as Compozy's iteration mechanism; adding context
  transfer achieves the same behavior without a second mechanism.

### Alternative 2: Status quo (session-reuse implicit continuity)

- **Description**: Rely on managed-binding session reuse (`{WorkspaceID, LoopRunID, Handle}` key,
  no generation component) — generation N+1 talks to the same ACP session and "remembers".
- **Pros**: Zero work.
- **Cons**: Conversational, un-inspectable, not templatable, not lintable, absent for non-goal
  nodes and fresh bindings; invisible to CEL routing; not auditable.
- **Why rejected**: Violates the paper's own standard — route-relevant state must live in typed
  state, "not model prose alone" (§6).

## Consequences

### Positive

- Closes the paper's core repair pattern with one grammar extension; revise/re-attempt generations
  can cite exactly what failed and why.
- Static DAG advantages retained (lint, audit, closed outcomes) — the documented divergence from
  LangGraph becomes a documented equivalence.

### Negative

- Namespace grammar grows by two roots — docs (`reference-grammar`, `dsl-reference`), linter, CEL
  environment, and 8 namespace-builder call sites must move together.
- Larger prompts when templates interpolate `previous.*` payloads (bounded by existing output-size
  budgets).

### Risks

- Payload bloat if templates dump whole `previous.nodes.*` objects — mitigated by documenting
  field-level interpolation and existing blob-size caps.
- Grammar drift between `ValidatePath`, CEL vars, and linter builders — mitigated by
  route-contract tests asserting all three accept/reject the same paths.
