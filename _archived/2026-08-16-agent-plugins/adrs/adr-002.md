# ADR-002: Plugin-format packages enter the marketplace through the existing curated feeds

## Status

Accepted

## Date

2026-08-15

## Context

Phase 1 must decide whether Agent Plugins packages are discoverable inside Compozy or only installable by operators who already know a source URL. Compozy's marketplace catalog is a set of curated in-repo feeds; every entry today points at a package in the native extension layout. Installs from published sources run under the marketplace trust ceiling — and an ingested plugin synthesizes to a resource-only extension, which fits any tier including that ceiling (verified 2026-08-15: empty permission requests short-circuit before ceilings apply). The flagship ecosystem content (AWS Agent Toolkit) currently ships client-specific layouts (`.claude-plugin/`, `.codex-plugin/`), not the standard's root layout, so third-party conformant content is thin at launch.

## Decision

The existing curated feeds accept entries that point at plugin-format packages. A feed entry carries a format marker; marketplace cards and the extension detail surface render a read-only format badge; the install flow is unchanged — the daemon auto-detects the layout exactly as it does for CLI installs. No dedicated marketplace section, tab, or separate catalog is created.

## Alternatives Considered

### Alternative 1: CLI/local discovery only (no catalog presence)

- **Description**: Phase 1 ships ingestion without any marketplace surfacing.
- **Pros**: Smallest scope; zero feed/web changes beyond the inventory badge.
- **Cons**: Plugin-format content is undiscoverable inside Compozy; users must hunt GitHub for URLs.
- **Why rejected**: The user decided catalog discovery ships in Phase 1 (grill Round 1, Q4).

### Alternative 2: Dedicated "Agent Plugins" marketplace section

- **Description**: A separate area listing ecosystem content apart from native extensions.
- **Pros**: Visible positioning statement.
- **Cons**: Launches nearly empty (flagship vendors are not root-layout conformant yet); creates a second browsing taxonomy for what is deliberately one product concept.
- **Why rejected**: Contradicts the no-new-concept posture (ADR-001) and buys shelf space with no stock; revisit if the conformant ecosystem fills out.

## Consequences

### Positive

- Discovery and installation of portable content without leaving Compozy; one browsing surface, one install flow.
- The trust pipeline is untouched: unverified-source consent, provenance, and the marketplace permission ceiling apply as-is — and a resource-only synthesis sits strictly below that ceiling.

### Negative

- Feed curation remains manual; catalog breadth depends on the conformant ecosystem growing.
- The feed entry shape gains a format marker — a small, additive schema change to the catalog contract.

### Risks

- Curated entries can drift non-conformant upstream (a repo restructures away from the standard layout); the install-time validator is the backstop, failing with the deterministic layout diagnostic.

## Implementation Notes

Feed schema, badge placement, and install-dialog copy are Stage 2 surface decisions (`_dx.md` / `_uiux.md`). Catalog entries are hand-curated; no automatic ecosystem crawling (Non-Goal).
