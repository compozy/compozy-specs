# ADR-004: Ingested package names are preserved verbatim, dots included

## Status

Accepted

## Date

2026-08-15

## Context

The standard allows periods in package names (`acme.tools` is valid; rules: 1–64 chars, `a-z0-9.-`, alphanumeric edges, no `--`/`..`). Compozy extension names have no character validation at manifest load; install-path containment accepts a dotted name as a single normalized segment; only the model-catalog source-slug derivation rejects dots — a surface a resource-only synthesis never touches (it declares no provide surface). The scaffold-only pattern (`^[a-z][a-z0-9-]*$`) applies to `compozy extension init`, not to install. Hermes namespaces adapted components as `agent-plugin-<slug>-<sha256[:8]>` because it flattens them into a shared skill namespace; Compozy's resources are already namespaced per extension instance, so no such flattening pressure exists.

## Decision

The installed extension identity is the package's manifest name, byte-for-byte — in CLI arguments, API routes, structured output, and the web UI. No dot-to-hyphen normalization, no hash suffixing, no aliasing. Ingestion enforces the standard's own name constraints (which already exclude path-hostile shapes like `..`) and rejects violations as fatal manifest errors.

## Alternatives Considered

### Alternative 1: Normalize dots to hyphens

- **Description**: `acme.tools` installs as `acme-tools`.
- **Pros**: Names match the scaffold pattern used for native extensions.
- **Cons**: Dual identity (docs and upstream README say one name, Compozy says another); collision risk (`acme.tools` and `acme-tools` both map to `acme-tools`); breaks the mental model of "what I installed is what I remove".
- **Why rejected**: Worse UX for zero safety gain — containment is already safe with dots.

### Alternative 2: Hash-suffixed namespace (Hermes model)

- **Description**: Derive `agent-plugin-<slug>-<hash>` identities.
- **Pros**: Collision-proof under flattening.
- **Cons**: Unreadable identities in every user-facing command; solves a flattening problem Compozy does not have.
- **Why rejected**: Compozy resources are namespaced per extension instance already.

## Consequences

### Positive

- One identity everywhere: install output, `remove`, `status`, routes, badges, upstream docs all agree.

### Negative

- A dotted-name extension could never later declare a model-source provide surface (slug derivation rejects dots). Irrelevant for resource-only ingests; documented so nobody trips on it if synthesis ever widens.

### Risks

- None beyond the documented model-source constraint; the standard's own name rules exclude traversal-shaped names.
