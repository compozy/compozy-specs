# ADR-005: Single beta channel at launch, stable identity reserved from day one

## Status

Accepted

## Date

2026-08-09

## Context

CompozyOS currently ships on a beta track only; the "stable" version line (0.2.15) belongs to the legacy product and has nothing to do with CompozyOS. Desktop channel identity (product name per channel, install paths, uninstall keys, feed URLs) is retrofit-hostile: it must be pinned before the first public build, and retrofitting channels later strands users with duplicate installs. Reference products that got this right (Open-Design's four channels with distinct app identities; the version-pattern channel selection in T3Code) pinned identity up front.

## Decision

1. The desktop app launches with a **single active channel: beta**, matching the actual state of the product.
2. The **stable channel's identity is designed and reserved now** — naming, feed paths, and identity scheme all account for a `stable` channel that is simply inactive — so graduation is an activation, not a migration.
3. The legacy stable line (0.2.15) is a different product; the desktop namespace is new and shares nothing with it.

## Alternatives Considered

### Alternative 1: Launch with both channels active

- **Description**: Ship beta and stable feeds from day one.
- **Pros**: No later activation step.
- **Cons**: There is no stable product to publish; an empty or lying stable channel confuses users and violates the truthful-surface principle.
- **Why rejected**: Publishes a promise the product cannot keep yet.

### Alternative 2: Beta-only with no reserved stable identity

- **Description**: Decide stable identity later, at graduation.
- **Pros**: Zero design work now.
- **Cons**: Channel identity retrofits strand installed users (duplicate installs, orphaned uninstall entries) — the exact failure the reference evidence documents.
- **Why rejected**: Saves nothing now, costs users later.

## Consequences

### Positive

- Channel model is honest today and graduation-ready tomorrow.
- No collision surface with the legacy product's version line.

### Negative

- Beta users at graduation need a defined path (stay on beta vs move to stable) — deferred as an explicit open question until stable activation is planned.

### Risks

- Accidental publication to the reserved stable path before graduation — the release pipeline must treat stable as locked until explicitly activated.

## Implementation Notes

Feed layout should be channel-scoped from the first release (e.g., `<distribution-domain>/desktop/<channel>/…`) with `stable` present in the design and absent in publication.
