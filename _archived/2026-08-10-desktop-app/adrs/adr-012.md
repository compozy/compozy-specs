# ADR-012: Product-language hard cut to CompozyOS absorbed into this workstream; command identifiers stay `compozy`

## Status

Accepted (supersedes ADR-006 decision 2)

## Date

2026-08-10

## Context

Peer review round 1 (B-010) found that shipping a durable CompozyOS identity (app name, bundle identifier, URI scheme) while the rest of the product's surfaces keep saying Compozy is dual product naming — prohibited by the greenfield hard-cut rule (L-006) — and that the task artifacts themselves had drifted (`compozy://` in the brief vs `compozyos://` in ADR-009). ADR-006 had deferred the wider brand migration to a separate initiative; the operator has now decided to absorb it into this workstream. A full identifier rename (binary, env vars, Go module path, package names) has a blast radius measured in weeks and re-breaks every local environment; the product-language rename does not.

## Decision

1. **This workstream absorbs the Compozy → CompozyOS product-language hard cut.** Every product-language surface renames in one sweep: `packages/site` (marketing + docs prose), `COPY.md`, `docs/_memory/glossary.md`, `PRODUCT.md`, web UI display strings, the official skill (`skills/compozy/` content), README/product prose, and release display names. No surface keeps "Compozy" as the product name after the cut.
2. **Command identifiers are not product language and stay `compozy`**: the CLI binary/command, `COMPOZY_*` environment variables, the Go module path, `@compozy/cli` npm package, Homebrew formula, UDS socket names, native tool IDs (`compozy__*`), and config file paths. The boundary is codified in the glossary: *CompozyOS is the product; `compozy` is its command* (Docker Desktop / `docker` precedent).
3. **The URI scheme is `compozyos://`** (dev: `compozyos-dev://`) everywhere, per ADR-009; the brief's `compozy://` mention is superseded.
4. The cut ships with enumerated delete targets (the TechSpec's Delete Targets section lists them); no alias, dual naming, or transition prose survives the change.

## Alternatives Considered

### Alternative 1: Keep the split-brand state (ADR-006 decision 2 as accepted)

- **Description**: Desktop says CompozyOS; site/docs keep Compozy until a later initiative.
- **Pros**: Smallest immediate scope.
- **Cons**: Dual product naming in shipping surfaces — exactly what the hard-cut rule and L-006 forbid; every week of the split deepens the docs/copy drift the later initiative must clean.
- **Why rejected**: Peer review correctly identified it as prohibited alpha-state compatibility; the operator opted to close it now.

### Alternative 2: Total rename including command identifiers

- **Description**: Also rename the binary (`compozyos`), env vars, module path, packages, tool IDs.
- **Pros**: Absolute naming uniformity.
- **Cons**: Weeks of churn across CI, installers, QA runbooks, local environments, and generated artifacts; breaks the stable command surface agents and docs script against; command names are technical identifiers, not product language.
- **Why rejected**: Cost is enormous and the payoff is nominal — the documented product/command boundary achieves naming truth without the churn.

## Consequences

### Positive

- One product name everywhere users read prose; the reviewer-flagged dual naming is gone.
- The identity the desktop app pins (name, bundle id, scheme) is consistent with every other surface on day one.

### Negative

- This workstream grows a rename phase (site/docs/copy/UI-string sweep + glossary/COPY.md updates) with its own tasks and QA.
- The shell's "zero web changes" property is unchanged (the shell still requires none), but the absorbed rename phase itself edits `web/` display strings — the constraint is restated precisely in the TechSpec.

### Risks

- Missed occurrences create silent dual naming — bounded by a repo-wide sweep with an enumerated surface list and a lint-style occurrence check in the rename tasks.
- Brand marks in `@compozy/ui` are design-system-owned — the sweep routes mark changes through the designer lane (SD-007/L-032), never invents marks.

## Implementation Notes

Glossary and COPY.md changes land in the same commit batch as the surface sweep. Package/identifier names remain untouched by rule; a follow-up initiative may revisit command naming only as its own hard cut. ADR-006 decisions 1 and 3 (CompozyOS durable identity; `compozy app` verb) stand unchanged.
