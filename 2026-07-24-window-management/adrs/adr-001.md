# ADR-001: Daemon-authoritative hybrid layout topology

## Status

Accepted

## Date

2026-07-22

## Context

The OS shell stores every snapped window as independent fractions and reconstructs adjacency from
rendered rectangles. This cannot express a shared boundary across one-to-many descendants, atomic
multi-window operations, persistent virtual desktops, deterministic focus, or semantic management by
agents. The existing public desktop-state contract exposes opaque JSON rather than the behavior users
and agents intend.

AGH runs the same workspace through multiple web clients. The daemon must preserve workspace-owned
topology while active desktop, focus, and temporary presentation order remain client-owned. Only a
browser client knows its measured viewport and content minimums.

## Decision

Introduce `internal/windowmanager` as the sole authority for a typed workspace snapshot and semantic
command pipeline.

- A workspace owns persistent desktops, windows, each window's canonical deep route, tiled groups,
  topology, history, and one monotonic revision.
- A desktop owns zero or more non-overlapping group frames plus floating windows.
- A group tree contains `leaf`, n-ary weighted `split`, and tabbed `stack` nodes.
- Every command executes `read -> clone -> reduce -> normalize -> validate -> one commit -> one event`
  and records exactly one undo history entry when it changes durable layout topology. Navigation is
  durable and revisioned but excluded from layout history.
- The web receives normalized frames and projects them into pixels with measured work-area gaps and
  minimum sizes. An impossible branch adapts to stack presentation without corrupting stored topology.
- Client presentation state is transient and indexed by stable explicit `client_id`. Commands that
  change a remote client's active desktop or focus require that ID.
- Structural `placement` (`tiled|stacked|floating`) is distinct from durable application `route`
  (`pathname` plus canonical search object). Layout undo/redo preserves current routes for surviving
  windows; `window.navigate` can optionally focus one explicit client in the same operation.
- HTTP, UDS, CLI, native tools, pointer gestures, shortcuts, the command palette, and the layout
  editor all invoke the same command registry.
- Raw layout replacement is a validated semantic command with workspace binding, expected revision,
  dry-run support, and normal validation; it never bypasses invariants.
- The old public desktop-state contract and v1 payload reader are deleted. The internal bbolt
  persistence mechanism may be reused behind the typed service, but its opaque JSON surface is not.

## Alternatives considered

### Continue improving independent snap rectangles

Rejected. Pairwise seams and sequential writes are consequences of the representation. Additional
heuristics would be a third patch to the same behavior and violate the two-touch rule.

### Move all geometry into the daemon

Rejected. The daemon cannot know client viewport dimensions, browser zoom, font loading, or measured
content minimums. It owns normalized intent and topology; clients own faithful projection.

### Keep public desktop-state as a compatibility layer

Rejected. AGH is greenfield alpha, and dual write/read paths would let agents corrupt invariants or
observe two authorities.

### Use executable custom layouts

Rejected. Executable geometry expands the attack and determinism surface. Extensions contribute
validated declarative `window_layout` resources instead.

## Consequences

### Positive

- Shared seams, structural reflow, undo/redo, and desktop operations become deterministic.
- Every management surface has semantic parity and structured diagnostics.
- Workspace topology cannot leak through client-local focus state.
- The web can retain application state across desktop switches without owning durable truth.

### Negative

- This is a hard contract replacement across daemon, generated clients, CLI, tools, web, docs, and
  the official skill.
- Golden fixtures are required to keep Go normalization and TypeScript projection aligned.
- Browser clients need a stable local client identifier and explicit reconnect registration.

## Safety invariants

1. A window belongs to exactly one desktop and appears at most once in topology.
2. Group frames within a desktop never overlap and contain finite normalized coordinates.
3. Split children and weights have equal non-zero length; every weight is finite and positive.
4. A committed tree has no cycles, empty containers, or non-root single-child containers.
5. One accepted semantic command increments revision once and emits one ordered event; layout
   topology commands also emit one history record, while navigation never enters layout history.
6. A rejected or previewed command performs no write and emits no durable event.
7. Workspace reads, streams, caches, history, and writes are keyed and authorized by `workspace_id`.
8. Client presentation mutations require a connected explicit `client_id` when invoked remotely.
9. Stale gestures commit only after an unambiguous revision rebase; otherwise they fail closed.
10. Removing a non-empty desktop transfers all windows atomically to an explicit destination.
11. Every route is an internal absolute pathname plus canonical JSON-object search, and it survives
    reload, daemon restart, export/apply, and peer-client synchronization.
