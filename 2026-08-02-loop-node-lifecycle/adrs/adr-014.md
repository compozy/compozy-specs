# ADR-014: Target health reuses `internal/deadentity`; quarantine redirects the same-node breaker arithmetic

## Status

Accepted

## Date

2026-08-01

## Context

`internal/deadentity` is the repo's circuit breaker in everything but name: workspace-scoped
failure streaks with durable open marks (`DefaultPermanentFailureThreshold = 5`; pre-threshold
streaks are in-memory), half-open probes
(`DefaultRecoveryInterval = 1m`, one probe per interval), fail-open on store errors, transition
events, three consumers (MCP sidecars with stale-descriptor fallback, bridges, MCP runtime
probes). The loop plane's current "breaker" is different machinery: `terminalForFailedGeneration`
trips `{stalled, no_progress, "circuit_breaker"}` when the same node fails in
`LoopFailureBreakerLimit = 2` consecutive generations, or when an uncapped watch loop has any
failure in 2 consecutive generations — a run-terminal verdict, not a call-admission gate. The two
concepts collide on the word "circuit breaker" (seams report warning). PRD ADR-007 demands:
breaker per (node family, target), transport-only counting, fail-fast with explicit cause, and
quarantine with full repair context replacing run death for repeat offenders.

## Decision

1. **Target health = `deadentity` with a new kind.** `DeadEntityKind` gains
   `DeadEntityKindLoopTarget = "loop_target"`; `EntityID = "<family>:<target>"` where family is
   the node family (`toolcall | run-agent | run-loop`) and target is the resolved external
   identity (tool id, MCP server, agent runtime). The `dead_entities.kind` SQL CHECK
   (`41_reliability.sql`) is rebuilt to accept the new value in the same Goose migration as the
   loop tables (round-2 B-002 — without it the fail-open service could never persist an open
   mark). Workspace scoping, the 5-failure streak, the 60s half-open probe, transition events,
   and fail-open persistence come unchanged from the service. **Durability contract stated
   plainly:** open/half-open marks are durable rows; pre-threshold streaks are in-memory and
   reset on daemon restart — the documented, tested behavior of every existing deadentity
   consumer, accepted here too (restart tests cover before-threshold, while-open, and half-open
   phases). **Policy is daemon-global** (`[loops.breaker]` threshold + probe interval): shared state per
   `(workspace, family, target)` cannot obey run-pinned policy, so breaker knobs are
   deliberately excluded from node/loop/per-kind resolution (round-2 B-003). The loop plane
   constructs its OWN `deadentity.Service` instance with that policy over the shared store and
   event sink — the existing shared instance (bridges, MCP, sidecars) keeps its defaults, and a
   regression proves loop settings never change their thresholds or probe cadence (round-3
   B-003). Only `transport`-class failures record as breaker failures;
   every other class and every handled failure records success (PRD Business Rule 31).
2. **Admission check at node dispatch.** Before enqueuing/executing a target-bound attempt, the
   runtime asks `BeforeProbe`; `Allowed=false` fails the attempt immediately with class
   `target_unavailable`, reason code **`target_unavailable`** (never the existing
   `circuit_breaker` string), entering the normal precedence chain. An allowed probe during
   half-open executes normally and its outcome closes or re-opens the target.
3. **The run-level arithmetic is redirected, not deleted.** The same-node-2-consecutive-
   generations detection stops producing the run-terminal `stalled/circuit_breaker` and instead
   **quarantines the node**: control row marked quarantined, quarantine entry assembled from the
   attempt ledger (classified chain, timestamps, hints, target, input ref — Temporal DLQ
   anti-lesson closed), run continues on independent branches. The uncapped-watch-loop arm
   (any-failure across 2 generations) keeps its existing run-terminal behavior — a watch loop with
   no cap needs a global stop. The `"circuit_breaker"` reason code survives only on that watch
   arm.
4. **Quarantine semantics.** Quarantine is per-node terminal-until-requeued: succession planning
   excludes quarantined nodes from rerun sets; a generation whose forward progress (including a
   gate-driven rerun root) requires a quarantined producer parks the run as needs-attention naming
   the dependency (Business Rule 30). `requeue` clears the control row with provenance, appends a
   `requeue`-origin generation through the normal succession planner, all bounds applying;
   repeated episodes append to the entry history.
5. **`on_quarantine` effects and the `needs_attention` vocabulary** mirror the task plane
   (`internal/task` `needs_attention`, `NeedsAttention{Reason, At, By}`) so operators and agents
   see one language across queues and loops.

## Alternatives Considered

### Alternative 1: New loop-owned breaker tables and state machine

- **Description**: `loop_target_health` table + bespoke open/half-open logic.
- **Pros**: Loop-local control over thresholds and shapes.
- **Cons**: Reimplements a battle-tested service (streaks, probes, fail-open store semantics,
  events) that three subsystems already trust; two breaker implementations to keep honest.
- **Why rejected**: Authoritative-primitive discipline — reuse the existing authority.

### Alternative 2: Delete the run-level arithmetic entirely (quarantine covers everything)

- **Description**: Remove `perNodeFailureLimitReached` and the watch arm.
- **Pros**: One mechanism.
- **Cons**: An uncapped watch loop where *different* nodes fail each generation would burn budget
  forever with no global stop; quarantine is per-node and cannot see that pattern.
- **Why rejected**: The watch arm guards a real unbounded case; only the same-node arm is
  superseded by quarantine.

### Alternative 3: Count semantic failures toward the target breaker

- **Description**: Any failure against a target trips it eventually.
- **Pros**: Simpler classification.
- **Cons**: A tool correctly rejecting invalid requests would be declared unhealthy — Temporal's
  documented rationale refutes this directly.
- **Why rejected**: PRD ADR-007 already decided transport-only; health is about the transport,
  not the answer.

## Consequences

### Positive

- One sick MCP server degrades its own lane while healthy targets keep working; the breaker comes
  with durability, probes, and events for free; quarantine turns "run death" into
  "repair-and-continue" with an entry an agent can act on.

### Negative

- Two vocabularies coexist during review: `target_unavailable` (admission gate) vs the residual
  watch-arm `circuit_breaker` (run terminal) — docs must draw the line once.

### Risks

- Bounds re-verification (briefing constraint on Safety Invariant 7): requeue and post-breaker
  retries must count against `iteration_cap`/budgets identically — the invariant list restates it
  and the test contract induces it.
