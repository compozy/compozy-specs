# ADR-013: Loop-owned failure classification — closed class enum, result contracts, hint propagation

## Status

Accepted

## Date

2026-08-01

## Context

`ActionFailure.Code` is an open string (`action_failure.go:11`); the only recognized values are
three magic dependency blockers (`coordinator_terminal_helpers.go:249`). Three classifiers already
diverge in the repo — `internal/bridgesdk/errors.go:194` (`ErrorClass` with typed/HTTP/runtime/text
cascade, `RetryAfter`, `IsCommittedMutation → Permanent`), `internal/tools/errors.go` (outcome
codes, no retryability), and `internal/tools/mcp_reliability.go:169` (reason → deadentity class).
The whole contract keys on classification (PRD Feature 1): retry eligibility, breaker accounting,
route activation, and repair context all read the class. v0's payload-detection rules
(`behavior-defaults.md` §compozy-v0) supply the truth table for "the body said it failed".

## Decision

1. **A closed `FailureClass` enum, owned by `internal/loop`:**
   `transport | payload_declared | quality_rejection | authoring | cancellation |
   attempt_timeout | budget_exhausted | target_unavailable`. Automatic behavior per class is fixed
   (PRD Business Rule 7): only `transport` and `attempt_timeout` are retry-eligible;
   `target_unavailable` fails fast into the normal chain; `quality_rejection` stays gate-owned;
   kill produces no classification (the kill event is the record).
2. **Classification is a pure function over the failure evidence**, evaluated at the coordinator
   boundary in fixed order: cancellation (from cancel provenance) → payload contract (below) →
   authoring (`refs` diagnostic codes) → timeout/budget (from lifecycle anchors) →
   target-unavailable (breaker verdict) → transport (typed transport/net errors, `ToolError`
   codes `tool_unavailable | tool_backend_failed | tool_timed_out`, lease-expiry sweep) →
   default `payload_declared` for application errors. The bridgesdk cascade is the reference
   implementation pattern; the bridge package itself is untouched (consolidation is idea 33's
   refactor, not this spec).
3. **Payload-declared failure detection (v0 rules, adopted verbatim):** on transport-level
   success, inspect the result body — `error` key wins over `success` indicator; non-empty
   string / map / list error → fail with the body's message; `error: "" | null` → not a failure;
   empty containers (`{}`/`[]`) → fail with a "declared error was empty" cause; `success:
   false` (bool or case-insensitive string) → fail. A node may declare `result_contract:
   {failure_field, message_field?}` naming its own shape; built-ins apply otherwise; oversized or
   non-inspectable bodies skip detection with a recorded diagnostic (US-001 EC-3).
4. **Remediation hints ride the existing slot.** `ActionFailure.Recovery` is the hint carrier;
   classification copies it into the attempt-ledger row and the repair context
   (`previous.nodes.<id>` projection gains the classified failure summary); absent hints render
   the generic guidance (US-003 AC-2). All causes and hints pass the single sanitization boundary
   (loops-paper-adoption Safety Invariant 11) before persistence.
5. **Authoring vs runtime split extends the existing refs machinery.** Reference resolution
   failures carry the `refs` error codes; skipped-branch references resolve absent (already true);
   a ran-node bad-field reference raises an authoring-class diagnostic listing available fields
   from the node's `Produces` schema — surfaced identically at lint time and run time (US-002).
6. **Predicate failure policy** is PRD ADR-002.4 mechanized: continuation predicates
   (`stop_when`, watch constraints) fail open to exit; routing predicates (`branch` condition,
   gate criterion expressions) raise a routable `authoring`-class failure; both always append a
   diagnostic event; CEL cost overrun (existing `CostLimit`) is the same broken-predicate path,
   with a warn diagnostic at 80% via cost tracking.

## Alternatives Considered

### Alternative 1: Lift `bridgesdk.ErrorClass` into a shared package now

- **Description**: One repo-wide classification package consumed by loop, tools, bridges.
- **Pros**: Retires a three-way divergence.
- **Cons**: Cross-domain refactor of bridge retry semantics inside an already-large spec; bridge
  classes (auth/rate-limit/overloaded) are transport-tuning detail the loop contract does not
  route on.
- **Why rejected here**: Scope discipline — recorded as the consolidation candidate for the
  node-family state-machine refactor (idea 33), not this delivery.

### Alternative 2: Open string classes with convention

- **Description**: Keep `ActionFailure.Code` free-form; document recommended values.
- **Pros**: No enum to maintain.
- **Cons**: Routing, retry, and breaker behavior keyed on unvalidated strings reproduces the
  "three magic values" hole this spec exists to close.
- **Why rejected**: The class is load-bearing contract state; closed enums with SQL CHECKs are
  the house rule for such state.

## Consequences

### Positive

- "200 OK with a failing body" stops lying to retry and routing (the dominant real-world agent
  failure); every failure carries one class, one sanitized cause, one optional hint, everywhere.

### Negative

- Every executor's error surface must map into the classifier — a per-family conformance test
  matrix is mandatory.

### Risks

- Misclassification burning retries on deterministic errors (PRD ADR-003 risk) — mitigated by
  shipping payload detection in the same change as retry, and by `non_retryable` author override.
