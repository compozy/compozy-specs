# ADR-003: Family-asymmetric automatic retry

## Status

Accepted

## Date

2026-08-01

## Context

The engine has no per-node retry today: a transient network blip on a tool call escalates a whole generation. Market baseline (Inngest, Restate, Zapier autoreplay) treats automatic per-step retry as the assumed default. Agent-native frameworks (Mastra, Sim) ship zero retries by default. Temporal is deliberately asymmetric: activities with no policy retry indefinitely, while child workflows with no policy get no retries at all — mechanical work retries by default, composite/expensive work does not. Our engine adds a wrinkle none of them have: an outer generation-repair loop that is already the semantically correct retry for agent work.

## Decision

1. **Mechanical nodes (tool calls, transforms) retry transient-classified failures automatically** with exponential backoff and a small default attempt cap. No author configuration needed.
2. **Expensive/composite nodes (agent nodes, sub-loops) do not auto-retry by default.** Their recovery is the generation repair loop — plus checkpoint-based resume when the author opts in (see ADR-004 for death-triggered resume, which is not a retry).
3. **Classification gates retry, not error shape alone:** cancellation never retries; payload-declared semantic failure ("the tool said no") never retries; authoring errors never retry; only transport/infrastructure-class failures are transient. A failing attempt may carry its own "retry after" hint, honored within the node's bounds.
4. **Retries are never free:** every attempt counts toward the node's total budget and the run's caps and budgets.
5. **Authors can widen, narrow, or disable** retry per node (attempt caps, backoff shape, non-retryable failure classes), and operators can tune the family defaults.

## Alternatives Considered

### Alternative 1: Retry-on for everything (Inngest/Restate posture)

- **Description**: Every node retries transient failures by default, including agents and sub-loops.
- **Pros**: Maximum resilience; full market-floor compliance.
- **Cons**: Re-runs expensive work (paid in tokens, not just time) for failures the generation repair loop would handle more intelligently; two overlapping recovery loops on the same failure.
- **Why rejected**: The repair loop is the smarter retry for semantic work; blind re-execution of agents is the most expensive failure mode in the system.

### Alternative 2: Retry-off for everything (Mastra/Sim/today)

- **Description**: No automatic retry; authors declare per node.
- **Pros**: Predictable, cheap.
- **Cons**: Below market expectation for mechanical nodes; a network blip needlessly escalates generation-level repair.
- **Why rejected**: Punishes every loop for the platform's most recoverable failure class.

## Consequences

### Positive

- A network blip costs one backoff delay instead of a generation.
- Agent work is never re-executed blindly; token spend stays intentional.
- Matches the strongest available precedent (Temporal's activity/child asymmetry) while exploiting our repair loop.

### Negative

- Two defaults to document instead of one; authors must learn which family their node belongs to (mitigated: the asymmetry follows cost intuition).

### Risks

- Misclassification is the failure mode: a semantic failure classified transient burns retries on a deterministic error. Payload-level failure detection (idea 5) must land with retry in the same spec so classification has truthful input.
