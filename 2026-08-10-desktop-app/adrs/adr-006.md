# ADR-006: CompozyOS durable app identity; `compozy app` CLI verb

## Status

Accepted — decision 2 superseded by [ADR-012](adr-012.md) (peer review round 1): the product-language brand migration is absorbed into this workstream instead of deferred. Decisions 1 and 3 stand.

## Date

2026-08-09

## Context

Two naming forks existed. (1) Product name: the operator states the current name is **CompozyOS** — "Compozy" is the old name — while the repo glossary still defines "Compozy" as the public product name; desktop identifiers (display name, bundle identifier, deep-link scheme, install paths, uninstall keys) are pinned at the first public build and cannot be changed without stranding users. (2) CLI verb: `compozy desktop` and `compozy window` are already shipped verbs of the web UI's window-manager domain, so the native app needs a non-colliding verb or a heavy domain rename.

## Decision

1. **The desktop app's durable identity is 100% CompozyOS from the first build**: "CompozyOS" as the user-facing app name (dock, launcher, installer), with bundle identifier, deep-link scheme, install paths, and uninstall identity derived from CompozyOS.
2. ~~**The wider brand migration (site, docs, prose, eventual CLI binary naming) is a separate initiative**, out of this PRD's scope, recorded as an open naming-consistency question (glossary update included).~~ **SUPERSEDED by ADR-012:** this workstream owns the product-language hard cut; command identifiers remain `compozy`.
3. **The CLI verb for the native app is `compozy app`** (e.g., open, status). The window-manager verb tree (`compozy desktop`, `compozy window`) stays untouched.

## Alternatives Considered

### Alternative 1: Name the app "Compozy" (or "Compozy Desktop")

- **Description**: Keep the current public name for the app.
- **Pros**: Matches today's glossary and site copy.
- **Cons**: Pins the *old* name into the identifiers that cannot be changed later; contradicts the operator's stated naming direction.
- **Why rejected**: Retrofit-hostile surfaces should carry the destination name, not the departure one.

### Alternative 2: Rename the window-manager CLI domain to free `compozy desktop`

- **Description**: Hard-cut rename of the window-manager verbs (allowed by greenfield rules) so the native app takes `desktop`.
- **Pros**: The most literal verb for a desktop app.
- **Cons**: Sweeps CLI, APIs, docs, and skills of a shipped, documented domain to free a word; `app` reads just as naturally at zero cost.
- **Why rejected**: High blast radius for purely nominal gain.

## Consequences

### Positive

- The identifiers users keep forever carry the correct name from day one.
- No collision, no rename sweep; window-manager domain undisturbed.

### Negative

- The product-language hard cut expands this workstream across site, docs, copy, UI display strings, and release display names (ADR-012).

### Risks

- Missed product-language occurrences could reintroduce dual naming; ADR-012 requires an occurrence gate.

## Implementation Notes

Channel identity (ADR-005) composes with this: per-channel display identity derives from CompozyOS (e.g., "CompozyOS Beta") when channel-distinct identity is required.
