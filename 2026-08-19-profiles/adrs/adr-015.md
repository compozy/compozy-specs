# ADR-015: Stamp 17 roots, inherit the rest; two read modes enforced at the store layer

## Status

Accepted

## Date

2026-08-20

## Context

D2 tags work with an owning profile and filters server-side, fail-closed. The scope contract (analysis/10) shows the schema already pins children to parents with composite FKs, so ownership can be stamped once per creation root and inherited by 61 descendant tables. The enforcement mechanism still had freedom: middleware/context injection vs explicit parameters; column-per-table vs join-through-parent for reads.

## Decision

- **Stamp exactly the 17 creation roots** (sessions, tasks, loop_runs, automation_jobs/triggers/suggestions, bridge_instances, worktrees, network_channels/direct_rooms/threads/work, notification_cursors, tool_approval_grants, event_summaries, dead_entities, token_usage_daily) with `profile_id NOT NULL REFERENCES profiles(id)` + an update-ABORT trigger. Children get no column; child reads scope by joining/deriving through their root.
- **Two read modes, explicit parameters**: every A-class store read takes `(profileID, allProfiles)` in its signature. No context-value defaults below the API boundary — handlers/CLI/resolver decide, stores obey. Aggregate mode joins profile identity for owner labels.
- **Migration `00079`** *(amended round 2: `00078` is the phase-0 workspace disposition; profiles land in `00079`)*: seeds the `default` row (fixed zero-ULID id, ADR-012), then per root: add nullable → backfill to `default` → rebuild NOT NULL; PK rebuilds for `token_usage_daily` and `notification_cursors`; immutability + active-owner creation triggers; equivalence suites mandatory.
- **Streams**: subscriber-level filters (workspace + profile axes) at the catalog stream's subscribe/publish seam — the phase-0 enforcement point extended, replay included.
- Cursors fingerprint the profile predicate; caches keyed with ProfileID (`PreStartScope`, bridge instance cache).

## Alternatives Considered

### Alternative 1: profile_id column on every A-class table (~78 tables)

- **Pros**: every read filters locally without joins.
- **Cons**: 4× the migration surface; denormalized ownership can drift from the root; contradicts the composite-FK design already in place.
- **Why rejected**: inheritance is already structurally guaranteed; the column adds risk, not safety.

### Alternative 2: Context-injected scope (middleware sets profile on ctx; stores read it)

- **Pros**: few signature changes.
- **Cons**: invisible dependency; a missing middleware silently yields unscoped reads — the opposite of fail-closed; unforgeable-at-boundary is hard to prove.
- **Why rejected**: explicit parameters make the leak a compile error, not a runtime hope.

## Consequences

### Positive

- Bounded schema change; leak-resistant by construction; aggregate labels come from one join.

### Negative

- Wide mechanical signature sweep through store/service/handler layers (phase 3) — mechanical, testable.

### Risks

- Child-read paths that bypass their root (raw queries) → the scope contract's A-inh table is the review checklist; integration tests enumerate listing surfaces.
