# ADR-008: Bare "Profile" names only the new concept; existing compounds keep their names

## Status

Accepted

## Date

2026-08-20 (decided in grill-me D8)

## Context

"Profile" is the most over-subscribed noun in the product: Task Execution Profile, layout profile, sandbox profile, Trust Profile, gateway connection profile, session creation profile, env profile grants — seven senses, two already CLI command groups. The sandbox/"environments" incident (L-014) is the precedent for what an unsettled noun costs once it reaches contracts. Candidate replacement nouns (Space, Area, Context, Desk) were considered.

## Decision

- The new concept is called **Profile** — bare, capitalized in prose. One new glossary entry defines it; from then on, unqualified "profile" in docs/UI/CLI means only this concept.
- **No renames of existing compounds now.** "Task profile", "layout-profile", "sandbox profile", "Trust Profile", "connection profile", "session creation profile" stay as-is: the operator judged the compounds unambiguous in context ("dá pra entender bem o que é 'task profile'"). Revisit only with evidence of real confusion.
- Reserved profile names: `default`, `all`, `global` (they collide with the uniform fallback, the aggregate state, and the Global lens).
- Profile names are short lowercase identifiers (letters/digits/hyphens, letter-first) because they double as folder names in repos and as binding keys for extensions.
- Scope-word mapping: what shipped documentation calls the "global" tier of resources and memory corresponds to the **machine** layer in this spec's prose; after the foundation fix, "Global" names only the cross-workspace view. Whether stored scope values are renamed — and the delete targets if so — is resolved in Part II under the hard-cut rule.

## Alternatives Considered

### Alternative 1: A fresh noun (Space / Area / Context / Desk)

- **Description**: sidestep the collision entirely.
- **Pros**: zero ambiguity with the seven existing senses.
- **Cons**: abandons the strongest market convention (Chrome/VS Code/Arc operators already know "profile" = isolated working context); the Hermes lineage and the operator's own vocabulary both say profile.
- **Why rejected**: operator decision — the market meaning is the feature's meaning.

### Alternative 2: Rename the compounds in the same change (full hard cut)

- **Description**: sweep task profile → task execution preset, etc.
- **Pros**: leaves exactly one "profile" in the product.
- **Cons**: a multi-surface rename across contracts, CLI, docs, and specs bought with zero evidence of real confusion today.
- **Why rejected**: cost without demonstrated confusion; the door stays open if evidence appears.

## Consequences

### Positive

- Docs and UI can say "profile" plainly; the glossary line arbitrates every future collision.

### Negative

- `compozy profile …` will sit adjacent to `compozy task profile …` — accepted, monitored for support confusion.

### Risks

- Drift back into ambiguity → the glossary entry plus copy review (COPY.md checklist) own the line.
