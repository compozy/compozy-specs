# ADR-007: The two foundation fixes land inside this spec, as phase 0

## Status

Accepted

## Date

2026-08-20 (prerequisites decided in grill-me D3/D4; in-spec inclusion confirmed spec round 1, Q4)

## Context

Two pre-existing defects block Profiles and stand alone as product fixes: (1) "Global" behaves as a pseudo-workspace pointing at the home directory — machine resources appear only under it, and it conflates three meanings; (2) the session-catalog live stream fans out unfiltered, with scoping applied only client-side — the exact enforcement point profile filtering must reuse. The question was packaging: same spec or separate mini-specs.

## Decision

Both fixes are **phase 0 of this spec**:

- **Global becomes a concept, not a workspace**: machine resources are visible in every workspace, always; the home directory becomes non-registrable (its boot auto-registration is a named delete target); the Global toggle becomes an aggregate view across workspaces; creating under it produces work with no workspace, owned by the active profile.
- **Session-catalog live updates are filtered server-side, fail-closed** — the shared enforcement point that profile scoping then extends with a second axis.

Task generation orders them first; profile work builds on the enforcement point they create.

## Alternatives Considered

### Alternative 1: Separate mini-specs shipped before this one

- **Description**: two small standalone specs, then the Profiles spec.
- **Pros**: smaller review units; fixes land sooner in principle.
- **Cons**: three approval cycles for one contract; the fixes' acceptance criteria are exactly the invariants Profiles relies on — splitting invites drift between documents.
- **Why rejected**: operator decision (Q4): one spec, ordered phases.

### Alternative 2: Land Profiles first, fix the leaks within it opportunistically

- **Description**: treat the defects as implementation details of profile filtering.
- **Pros**: no phase ceremony.
- **Cons**: the current leak is a live workspace-isolation defect regardless of Profiles; burying it removes its own verifiable acceptance criteria.
- **Why rejected**: the fixes deserve their own verification gates (they are testable invariants on their own).

## Consequences

### Positive

- One decision record, one dependency graph; the enforcement point exists and is tested before the profile axis widens it.

### Negative

- The spec grows (two features' worth of phase-0 surface); accepted — task decomposition handles size.

### Risks

- Phase-0 scope creep into profile mechanics → phase 0 is defined by its two acceptance criteria only (US-030/US-031).
