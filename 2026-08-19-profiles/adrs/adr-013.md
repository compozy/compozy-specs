# ADR-013: Scope vocabulary hard cut — stored `global` becomes `user`; memory's global tier becomes `profile`

## Status

Accepted

## Date

2026-08-20

## Context

Phase 0 redefines "Global" as the cross-workspace view (D3), and the operator chose `--scope user` (Claude Code convention) for the home-level layer. The word `global` is stored today in `resource_records.scope_kind`, config `WriteScope`, `settings.ScopeKind`, memory scope values, vault ref segments (`vault:mcp/global/...`), and API payloads. Keeping stored `global` while surfaces say `user` would be a permanent two-name tier; SD-002 forbids dual naming.

## Decision

- One hard cut, in the same change that widens each enum: stored/CLI/API scope value `global` → `user` across `resource_records.scope_kind`, config `WriteScope`, `settings.ScopeKind`, vault scope segments, and generated contract types. No aliases, no dual acceptance, no compat readers.
- Memory is the exception with a different target: the former `global` memory tier becomes **`profile`** (D14 — that tier is per-profile now); memory scopes end as `profile | workspace | agent`.
- "Machine" survives only as prose for daemon identity (denylisted keys) and machine-scoped commands — never as a stored scope value.
- Delete targets are listed in Part II Impact Analysis; migrations rewrite stored values with equivalence tests.
- **Every physical stream owns its own append-only migration**: globaldb (`resource_records.scope_kind`, MCP scope-bearing tables, stored `vault:mcp/global/…` and `vault:extensions/global/…` refs rewritten to `user`), and the memory stream (scope values + indexes rewritten `global`→`profile`). No stream is changed by another stream's migration; no boot-time repair.
- **The memory directory move is durably coupled to the stream version** *(amended round 2: the memory stream is embedded SQL — no Go callback exists)*: the memory-stream SQL migration writes a pending row into `memory_maintenance_ops`; the memory store's open path executes the atomic same-volume rename `$COMPOZY_HOME/memory` → `$COMPOZY_HOME/profiles/default/memory` (idempotency guard: target exists ∧ source absent ⇒ done), marks the row done, and refuses profile-tier reads while the row is pending (fail-closed). Row-driven and convergent on re-run — reconcile-shaped, not boot repair. The old path is a delete target, never a fallback read location.

## Alternatives Considered

### Alternative 1: Keep stored `global`, present `user` in surfaces

- **Pros**: no migration.
- **Cons**: permanent translation layer; every new reader learns two names; the exact drift SD-002 exists to kill.
- **Why rejected**: alpha with zero users is the only cheap moment for this cut.

### Alternative 2: Rename everything to `machine`

- **Pros**: crisp against "profile".
- **Cons**: operator chose `user` (market convention); "machine" then means two things (layer + daemon identity).
- **Why rejected**: operator ruling (surface grill Q2).

## Consequences

### Positive

- One vocabulary end to end: user / profile / workspace (+ workspace-profile for the repo per-name layer).

### Negative

- Wide mechanical sweep (SQL CHECKs, Go enums, payloads, docs, web types) — bounded by codegen and equivalence suites.

### Risks

- A missed reader rejects the new value → fail-closed validators surface it immediately in tests, not silently in prod.
