# ADR-008: Live Activation — Deterministic Admission Plus Budgets Settled from Aggregate Per-Turn Usage

## Status

Accepted

## Date

2026-07-11

## Context

Today an accepted delivery calls the model directly — one full turn per recipient per envelope, control traffic included, with no admission gate, no budget, and every ACP outcome discarded (`internal/network/delivery.go:672-682,885`). The PRD requires Live to be bounded by design with visible bounds and graceful exhaustion (rules 8–9), and truthful usage attribution (rule 13).

The corpus proposed gating public Live on a provider-attempt accounting program: a capability-negotiated adapter extension intercepting every internal provider call, backed by a trusted adapter registry (manifests, artifact digests, conformance suite, credentialed real-provider smoke). The operator rejected that as the release gate: it is the largest new subsystem in the corpus, serves accounting precision rather than practical safety, and restricts which providers can be Live at launch.

Key architectural fact: work in a coordinated run is driven by the task engine (claims, synthetic coordinator wakes, local turns reading conversations) — none of which consumes activation budget. The budget governs only message-triggered wakes of otherwise-idle Live participants.

## Decision

1. **Deterministic admission before any model call.** A Live wake is admitted only when: the trigger is a direct message or mention resolved to the participant (control/status/presence traffic is structurally ineligible); the envelope passes dedup and causation-depth checks; burst arrivals within the coalescing window collapse into one admission; and the participation's remaining budget covers it.
2. **Budgets: wakes + wall-time + tokens.** Each Live participation carries finite resolved bounds — maximum admitted wakes, a per-wake wall-time deadline, a per-participation wall-time ceiling, and input/output token ceilings. Zero never means unlimited.
3. **Settlement from aggregate per-turn usage.** The runtime already receives per-turn aggregate usage; each admitted wake's turn settles its actual usage against the budget (or marks it unavailable and keeps the conservative reservation consumed). Provider-internal retries within a turn are bounded by the wall-time deadline, which cancels the turn at expiry.
4. **Exhaustion accumulates.** When bounds run out, further eligible messages persist in the conversation (readable on the participant's own later turns); the exhaustion and its reason are visible on the participation and in events.
5. **Terminal truthfulness.** A failed or cancelled wake is classified from its terminal events — never marked delivered-successfully — and its consumed portion is attributed (fixes audit C-03's outcome half).
6. **Per-attempt provider accounting is future telemetry**, not a release gate: when richer per-attempt evidence becomes available it refines attribution, but Live's safety never depends on it.

## Alternatives Considered

### Alternative 1: Provider-attempt adapter program as the Live gate (corpus)

- **Description**: Live selectable only for profiles running a verified interception adapter (registry + digests + conformance + credentialed smoke).
- **Pros**: Attempt-level precision; hidden retries observable and stoppable mid-turn.
- **Cons**: Months of infrastructure on the critical path; restricts launch providers; precision gain over deadline-bounded turns is marginal for practical safety.
- **Why rejected**: Operator decision — same practical safety via wakes + deadline + token settlement; viability of the single release (ADR-004) wins.

### Alternative 2: Visibility without budgets

- **Description**: Meter the spend, impose no per-participation ceilings.
- **Cons**: Violates the PRD's bounded-by-design rule; leaves the ping-pong/burst runaway class open — the documented trust-destroying failure.
- **Why rejected**: Bounded activation is a contract property, not an optimization.

## Consequences

### Positive

- Live works with every provider from day one; the runaway class (loops, bursts, sticky fan-out) is closed by admission + budgets.
- Long coordinated jobs are unaffected: task-engine-driven work never touches the activation budget.

### Negative

- Mid-turn overruns are bounded by time, not by exact token count — a turn can exceed its token estimate until the deadline fires; settlement trues it up afterward.

### Risks

- Deadline cancellation depends on provider cancel support → where cancel is unsupported, the turn stays charged and observed to its terminal; a wake can never be re-admitted for the same envelope.

## Implementation Notes

Default bound values are TechSpec-owned configuration (defaults + administrative ceilings); their existence, visibility, and exhaustion behavior are contract. Also deleted with this decision: capability-scored auto-activation of unaddressed recipients (`activation_top_k` routing) — only direct/mention wakes exist (PRD rule 8).
