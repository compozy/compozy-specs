# ADR-003: The `compozy` preset is always on and implicit

## Status

Accepted

## Date

2026-08-20

## Context

`.compozy/skills` and `$COMPOZY_HOME/skills` are the runtime's canonical skill homes: the marketplace installs into `$COMPOZY_HOME/skills` (`internal/cli/skill_marketplace.go:131,168,208`), `compozy skill create` writes into `<ws>/.compozy/skills` (`skill_commands_mutation.go:102-103`), and bundled/marketplace provenance flows assume those roots. If a user could disable the `compozy` source, install/create/marketplace flows would write to directories the scanner no longer reads.

## Decision

The `compozy` preset never appears in `skills.sources` and cannot be disabled. It is resolved implicitly ahead of every configured preset. `sources = []` is a valid state meaning "compozy roots only". The UI renders it as a row without a switch, marked always-on.

## Alternatives Considered

### Alternative 1: Toggleable with guard rails

- **Description**: Listable and disableable, with daemon errors blocking install/create/marketplace while disabled.
- **Pros**: Maximum flexibility for `.agents`-only purists.
- **Cons**: Introduces a reachable degraded state; every install/create path needs a guard and an error message; QA surface grows for a state nobody asked for.
- **Why rejected**: All cost, no demonstrated benefit.

### Alternative 2: Visible in the list but rejected on removal

- **Description**: `sources` defaults to `["compozy", "agents"]`; validation rejects removing `compozy`.
- **Pros**: More explicit in the TOML.
- **Cons**: A mandatory element inside an editable list is awkward validation and confusing UX ("why can I see it but not remove it?").
- **Why rejected**: Implicit always-on states the same fact with less machinery.

## Consequences

### Positive

- Marketplace/create/install can never be configured into a broken state.
- Empty `sources` is safe and meaningful.

### Negative

- The effective root set is not fully spelled out in the TOML — mitigated by the settings UI, `compozy skill where`, and the daemon-reported sources envelope showing the effective list.

### Risks

- None beyond documentation clarity.

## Implementation Notes

Preset resolution prepends `compozy` internally; intra-tier ordering loads compozy roots last so they win ties (see ADR-007 notes on precedence).
