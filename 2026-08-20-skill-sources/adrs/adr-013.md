# ADR-013: Skill origin is visible where skills are chosen and managed — picker chip, settings, CLI

## Status

Accepted

## Date

2026-08-20

## Context

With multiple sources, two same-named skills from different roots become a real scenario, and today nothing user-facing distinguishes them: the session `/` picker groups by lane with no origin marker (gap G5 in `analysis/slash-picker-injection.md`), and skills lists show tier but not the human-meaningful source. Truthful UI demands the daemon-known origin be visible where the user acts on skills.

## Decision

Skills originating outside the `compozy` preset carry a discreet origin label (`agents`, `claude`, custom root name) in:

- the session `/` picker rows (trailing slot — the menu model already has one),
- Settings > Skills lists and diagnostics,
- `compozy skill list`/`where` output (structured fields included).

Skills from the `compozy` preset stay unlabeled — the default carries no badge noise.

## Alternatives Considered

### Alternative 1: Management surfaces only (no picker chip)

- **Description**: Origin in settings/CLI; picker unchanged.
- **Pros**: Cleaner menu.
- **Cons**: The picker is exactly where a user must distinguish homonyms at invocation time; ambiguity lands at the worst moment.
- **Why rejected**: The trailing-slot cost is trivial and the shadow scenario is real.

### Alternative 2: Defer entirely to v1.x

- **Why rejected**: Origin data ships in the payloads anyway (source identity is needed for qualified tokens); hiding it is a UI choice that buys nothing.

## Consequences

### Positive

- Homonym skills are distinguishable at invocation; shadow debugging moves from CLI-only to glanceable.

### Negative

- One more piece of metadata on picker rows — kept discreet (mono label, no color signal; signal palette stays informational).

### Risks

- Label real estate in narrow menus — truncation rules follow existing menu-model conventions.

## Implementation Notes

Web changes live in `sessionCommandMenuCatalog` grouping/trailing (`use-session-commands.ts:92`, `session-command-menu-model.ts:242`) and the settings section components; no new primitives (reuse `Pill`/mono text per the `@compozy/ui` inventory).
