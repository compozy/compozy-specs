# ADR-005: Source configuration applies live — no daemon restart

## Status

Accepted

## Date

2026-08-20

## Context

Today `skills.*` config is restart-required except `disabled_skills` (`internal/config/lifecycle/lifecycle.go:82,145`). The skills watcher polls every 3s and already exposes `SetRootsProvider` for dynamic roots per poll (`internal/skills/watcher.go:95-100`), and `boot_resource_watchers.go` can restart the watcher on live config changes. A settings page whose primary control is a toggle table implicitly promises immediate effect; a restart-required toggle table is weak UX for the page's headline feature.

## Decision

`skills.sources` and `skills.custom_sources` are `Live` in the lifecycle matrix. Saving re-derives scan roots (watcher roots provider reads current config), triggers a refresh, invalidates per-workspace skill caches, and republishes skill resource records in the same apply.

## Alternatives Considered

### Alternative 1: Restart-required in v1, live later

- **Description**: Fall into the existing `skills.*` = RestartRequired rule; UI honestly shows "Saved · restart required".
- **Pros**: Zero cache-invalidation risk; smaller change.
- **Cons**: The core interaction (toggle a source, see its skills appear) breaks into save → restart daemon → check; undermines the picker/coverage story.
- **Why rejected**: The plumbing for live roots already exists; the UX gap is not worth the saved effort.

## Consequences

### Positive

- Toggle → skills appear within one poll interval (~3s); counts in the settings envelope update without restart.
- Matches the existing live behavior of `disabled_skills`.

### Negative

- The apply path must coordinate three consumers of root lists (workspace resolver scan, registry global load, registry workspace load) plus watcher reseeding — more moving parts in one change.

### Risks

- Resource-authority projections going stale after a source change — mitigation: republish via `DiscoverGlobal`/`DiscoverWorkspace` on apply (the same handoff mapped in `analysis/slash-picker-injection.md`).
- Workspace cache serving pre-change results — mitigation: explicit cache invalidation keyed on config generation in the apply path; covered by dedicated tests in `_tests.md`.

## Implementation Notes

The UI never hardcodes lifecycle copy: it reads `restart_required` from the mutation result, so if implementation later downgrades a path to restart-required, the UI stays truthful automatically.

**Amendment (round 1, B-009):** live apply is owned by a single coordinator holding a monotonic config generation; every asynchronous commit point (registry swap, resource-authority publication, diagnostics replacement, session-command revision broadcast) compares the current generation immediately before committing and discards stale work — generation N can never overwrite N+1 on any read surface. Covered by the deterministic race test IT-012.
