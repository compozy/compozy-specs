# ADR-008: Ecosystem frontmatter fields are recognized without warnings — and still not honored

## Status

Accepted

## Date

2026-08-20

## Context

The skill loader accepts `name`, `description`, `version`, `metadata` as top-level frontmatter and warns on anything else (`internal/skills/loader.go:25-30`). Skills authored for Claude Code routinely carry the Claude Code superset (`allowed-tools`, `context: fork`, `hooks`, `model`, `disable-model-invocation`, …), and the agentskills.io spec adds `license`, `compatibility`, `allowed-tools`. Enabling the `claude` or `agents` presets would flood diagnostics with "unknown field" warnings for perfectly normal ecosystem skills, burying real warnings.

## Decision

Extend the recognized-without-warning field list with the agentskills.io spec fields and the known Claude Code superset. CompozyOS does **not** honor these fields — no behavior is attached; they are simply not flagged. Warnings remain for genuinely unknown fields.

## Alternatives Considered

### Alternative 1: Keep warning on everything non-Compozy

- **Description**: Preserve the strict allowlist.
- **Pros**: Maximally honest "this field does nothing here" signal.
- **Cons**: One enabled preset makes diagnostics unusable at scale; the signal drowns.
- **Why rejected**: Noise cost exceeds honesty value; docs state which fields are inert.

### Alternative 2: Aggregated info-severity diagnostic listing ignored fields

- **Description**: One collapsible info entry per skill.
- **Pros**: Middle ground.
- **Cons**: Requires a new severity level in the diagnostics pipeline — disproportionate for v1.
- **Why rejected**: Cost/benefit.

## Consequences

### Positive

- Clean diagnostics with ecosystem presets enabled; warnings regain meaning.

### Negative

- A user may believe `allowed-tools` is enforced by CompozyOS — mitigated by explicit docs ("recognized, not honored") in the skills docs page and the official skill reference.

### Risks

- The Claude Code superset evolves — the allowlist is a plain string set in the loader; updating it is trivial and non-breaking.

## Implementation Notes

Exact field list frozen in Part II data-model section: spec floor (`license`, `compatibility`, `allowed-tools`) + Claude Code superset (`when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `disallowed-tools`, `model`, `effort`, `context`, `agent`, `background`, `hooks`, `paths`, `shell`, `aliases`).
