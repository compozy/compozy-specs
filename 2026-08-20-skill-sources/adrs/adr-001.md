# ADR-001: Two separate config keys — preset slugs plus free-form custom roots

## Status

Accepted

## Date

2026-08-20

## Context

CompozyOS only scans `.compozy/skills`-shaped roots today; the discovery roots are hardcoded (`internal/config/agent.go:195-202`, `internal/skills/registry_load.go:25`, `internal/skills/registry_workspace_cache.go:271-293`). The feature adds user-selectable skill source folder patterns (e.g. `.agents/skills`, `.claude/skills`) plus arbitrary extra directories. The config shape determines validation semantics, the settings UI model, and how agents drive it via `compozy config set`.

## Decision

Two independent list-valued keys under `[skills]`:

- `skills.sources` — preset **slugs** validated against a daemon-owned table (e.g. `["agents", "claude"]`). An unknown slug fails validation with a did-you-mean suggestion; it is never silently treated as a path.
- `skills.custom_sources` — free-form directory paths (absolute or `~`-prefixed; workspace-relative in workspace scope).

## Alternatives Considered

### Alternative 1: Single mixed list (slug or path per entry)

- **Description**: `sources = ["agents", "~/team-skills"]`; entries resolve as preset when the slug is known, else as a path.
- **Pros**: One key; shorter TOML.
- **Cons**: A typo'd slug (`"agnets"`) silently becomes a relative path; validation needs a slug-vs-path heuristic; UI must split the list anyway (toggles vs. taglist).
- **Why rejected**: Ambiguous validation converts user typos into silent misconfiguration.

### Alternative 2: Presets only in v1

- **Description**: Ship only `skills.sources`; defer custom paths.
- **Pros**: Smaller surface.
- **Cons**: Team-shared skill dirs outside known conventions (e.g. `~/team-skills`) stay unreachable; `AdditionalDirs` covers whole discovery roots, not skills-only dirs.
- **Why rejected**: Owner chose to ship custom roots in v1 (see ADR-004).

## Consequences

### Positive

- Deterministic validation with actionable errors; slugs and paths never collide.
- UI maps 1:1 — preset toggle table for `sources`, taglist editor for `custom_sources`.
- Agents can set each key independently (`compozy config set skills.sources agents,claude`).

### Negative

- Two keys to document and maintain instead of one.

### Risks

- Preset slug set becomes a compatibility surface — mitigated by the closed curated table (ADR-014) and validation errors that name valid slugs.

## Implementation Notes

Follow the `disabled_skills` template end-to-end: struct field, defaults, pointer-typed overlay with replace semantics, validation, lifecycle rule, `tool_surface` registration, CLI string-slice parsing (`internal/cli/config_value_parse.go:173-192`).
