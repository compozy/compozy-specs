# ADR-004: `custom_sources` ships in v1

## Status

Accepted

## Date

2026-08-20

## Context

Beyond ecosystem presets, teams keep shared skill directories in arbitrary locations (`~/team-skills`, monorepo-internal folders). The workspace `AdditionalDirs` mechanism adds whole discovery roots (agents + skills under `.compozy/`), not skills-only directories, so it does not cover this case. The question was whether free-form roots ship in v1 or wait.

## Decision

`skills.custom_sources` ships in v1 alongside the preset key (shape per ADR-001). Custom roots are scanned as skills-only directories at the `additional` precedence tier.

## Alternatives Considered

### Alternative 1: Defer to v1.x

- **Description**: Presets only; custom roots later.
- **Pros**: Smaller v1.
- **Cons**: Any team layout outside the curated conventions stays unreachable; pressure lands on the preset table (requests to add one-off "presets" that are really private paths).
- **Why rejected**: Owner selected the two-key shape including custom roots when explicitly offered the presets-only alternative (ADR-001 Alternative 2).

## Consequences

### Positive

- Arbitrary team layouts work day one without polluting the preset table.
- The settings UI taglist pattern already exists (`settings-taglist-field.tsx`) — low UI cost.

### Negative

- User-chosen directories can be huge; scanner caps (300 candidates / 20k entries per root) become reachable — truncation must be surfaced, not just logged.

### Risks

- Path traversal / symlink escape on user input — mitigated: reuse `expandUserPath`/`ResolvePath` (`internal/config/home.go:317-355`) plus the existing skillscan root hardening; validation rejects empty/duplicate/relative-outside-scope entries.

## Implementation Notes

Global scope accepts absolute and `~` paths; workspace scope additionally accepts workspace-relative paths resolved against the workspace root. Tier mapping and dedup follow ADR-007.
