# ADR-014: v1 non-goals — no remote installer/sync, skills only, closed preset table, symlinks never copies

## Status

Accepted

## Date

2026-08-20

## Context

The feature borders several adjacent capabilities that could silently inflate scope: vercel-labs-style remote installation, agent-definition discovery from ecosystem folders, extension-registered presets, and content mirroring into per-tool directories. Each was explicitly decided, not inferred.

## Decision

Out of scope for v1, recorded as explicit non-goals:

1. **Remote installer/sync** — no fetching skills from remote repositories, no lockfiles, no `skill update` against external sources, no vercel-labs-style `skills add <url>`. Remote acquisition remains exclusive to the Compozy marketplace. Users of external installers keep using them; their output appears via the scan (ADR-012).
2. **Skills only** — no agent-definition (AGENT.md) discovery from `.agents/` or any new root. Agent definitions keep their current Compozy roots. (`skills.extra_sources` also stays a rejected field in AGENT.md frontmatter — the new keys are runtime config, not agent-definition fields.)
3. **Closed preset table** — extensions cannot register presets (they keep `resources.skills`); new presets are curated code changes. OpenClaw's bare `<ws>/skills` project dir is permanently excluded — it collides with ordinary repo folders (this repo's own `skills/` is the canonical counter-example).
4. **No content mirroring** — CompozyOS never copies skill bodies into per-tool directories; the only write it performs into non-Compozy sources is the user-requested expose symlink (ADR-011). No background sync, no write without an explicit user/agent action.

## Alternatives Considered

### Alternative 1: Include a remote installer in v1

- **Cons**: Remote content security, provenance, marketplace overlap — roughly doubles the spec.
- **Why rejected**: Owner confirmed out.

### Alternative 2: Extension-registered presets

- **Cons**: Turns the internal preset table into a public extension contract before its shape has survived real use.
- **Why rejected**: Premature contract freeze; revisit after v1 evidence.

## Consequences

### Positive

- The spec stays scoped to discovery + exposure; marketplace remains the single remote-acquisition story.

### Negative

- Tools whose conventions aren't in the curated table wait for a code change or use `custom_sources`.

### Risks

- Non-goal pressure post-launch — each item is additive later without breaking v1 contracts.

## Implementation Notes

Non-goal 2 requires a docs touch, not code: `agents/definitions.mdx` and `agent-md.mdx` keep documenting `skills.extra_sources` as rejected, now with a pointer to the runtime `skills.sources` config.
