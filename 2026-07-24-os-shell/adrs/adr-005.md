# ADR-005: The global command palette owns ⌘K; the RuntimeSelector rebinds to ⌘J

## Status

Accepted

## Date

2026-07-19

## Context

The OS shell's keyboard entry point is a global command palette ("⌘K to open anything": apps, sessions, actions). Today ⌘K/Ctrl+K is globally bound to every mounted RuntimeSelector (runtime/model picker) through a singleton owner registry (`web/src/systems/runtime/components/runtime-selector/command-k-registry.ts` + `use-command-k-ownership.ts`). Two features cannot both own the global shortcut.

## Decision

- The **global palette owns ⌘K/Ctrl+K** unconditionally, from any focus context, matching the industry-canonical binding (Linear, Raycast, Slack, VS Code Quick Open family).
- The **RuntimeSelector rebinds to ⌘J/Ctrl+J**, scoped to the nearest form or dialog that actually hosts a visible, enabled selector (verified free: no current global ⌘J binding). Session creation, agent runtime configuration, and onboarding are truthful hosts; an active session composer is not, because the runtime does not support changing an established session's runtime per prompt.
- The `command-k-registry` singleton is **deleted**; the palette installs the single global `keydown` listener, and the RuntimeSelector uses a component-scoped handler.

## Alternatives Considered

### Alternative 1: Focus-sensitive ⌘K (composer → RuntimeSelector; elsewhere → palette)

- **Pros**: Reuses the existing registry; no relearning for composer users.
- **Cons**: Same shortcut doing two different things by focus is ambiguous UX and untrainable muscle memory.
- **Why rejected**: Ambiguity tax on the shell's most-used shortcut.

### Alternative 2: Palette on ⌘P or ⌘Space; RuntimeSelector keeps ⌘K

- **Pros**: Zero change for existing users.
- **Cons**: The shell's primary action loses the canonical industry binding; ⌘Space collides with OS Spotlight.
- **Why rejected**: The palette is the highest-frequency shell action; it gets the canonical key.

## Consequences

### Positive

- One global shortcut listener owned by one component; simpler than the registry arbitration.
- Palette matches user expectations imported from every comparable product.

### Negative

- Existing users must relearn the runtime picker shortcut (⌘J) — acceptable in alpha; the RuntimeSelector trigger button keeps its visible Kbd hint, updated.

### Risks

- Hidden consumers of the deleted registry → grep-verified sweep is part of the delete-targets task; oxlint/typecheck catch dangling imports.

## Implementation Notes

Palette shortcut set (v1): ⌘K palette · ⌘N new session · ⇧⌘S spaces overview · ⌘W close focused window · ⌘M minimize focused window · Esc closes overlays. ⌘W/⌘M are browser-reserved in some browsers/OSes; handlers use `preventDefault` where the browser allows and the palette lists the actions as a discoverable fallback (documented limitation).
