# ADR-008: Desktop state stays on the embedded KV; the public surface narrows to `desktop-state` with a typed envelope contract

## Status

Accepted

## Date

2026-07-19

## Context

Peer review round 1 (B-001, B-008, N-006) found a real self-contradiction in the TechSpec: the architectural boundary said "SQL-matchable **or contract-bearing** state belongs in SQLite", while the desktop state is a public, agent-writable, versioned, documented contract stored in the embedded KV. The review also flagged that the domain validator admitted arbitrary domain names despite the claim that non-`os_shell` domains were "reserved", that a per-domain quota could not implement the PRD's per-workspace quota, and that a generic public namespace without an extension API is prematurely generic. The reviewer's primary fix was a hard cut to SQLite; the program owner had explicitly vetoed SQLite for this state (high-churn presentation payloads must not drag Goose/Atlas ceremony per shape tweak).

## Decision

Keep the embedded KV (ADR-004) and repair the contract instead of the engine:

1. **Boundary rule rewritten.** SQLite owns state the daemon must *match, filter, join, or transact relationally*. The desktop state's **envelope** (workspace, key, revision, commit sequence, timestamps, tombstones, deterministic errors) is a typed public contract implemented by the KV service; **payloads stay opaque JSON** the daemon never interprets. Any field that ever needs server-side matching graduates to SQLite with a numbered migration; the KV service never grows query features.
2. **Public surface narrows to `desktop-state`.** Routes are `/api/workspaces/{workspace_id}/desktop-state[...]`; the CLI verb family is `agh desktop-state`; config section is `[desktop_state]`. No `domain` parameter exists on the public wire in v1 — the internal `clientstate` service keeps its domain axis (fixed to `os_shell` by the handlers) so a future consumer ships as its own TechSpec with its own surface. Nothing is "reserved" publicly, resolving the prematurely-generic finding.
3. **Quota is per workspace** (`max_keys_per_workspace`) and counts retained key identities, including tombstones, matching the PRD's business rule while strictly bounding storage growth.
4. Product-facing vocabulary is **desktop state** (N-006); `client state` survives only as the internal Go package name.

## Alternatives Considered

### Alternative 1: SQLite table + Goose migration (reviewer's primary fix)

- **Pros**: Removes the boundary contradiction at the root; workspace deletion cascades via foreign key; one storage engine.
- **Cons**: Migration ceremony for opaque presentation payloads; refetch-style sync unless a parallel event path is built; owner explicitly vetoed it.
- **Why rejected**: The contradiction lived in the boundary *wording* and the surface *shape*, not in the engine choice; the veto stands and the repaired contract is internally consistent.

### Alternative 2: Narrow bbolt to private, non-agent-manageable ephemeral state (reviewer's secondary fix)

- **Pros**: No public contract on KV at all.
- **Cons**: Kills US-017/US-018 and SD-011 (agents must be able to inspect/arrange the desktop); UI-only state is an incomplete feature in AGH.
- **Why rejected**: Agent manageability is a load-bearing product goal, not an accident of implementation.

## Consequences

### Positive

- Owner's storage decision preserved with an internally consistent boundary rule.
- The public wire is smaller and honest: one surface, one consumer, no dangling generic namespace.

### Negative

- Workspace lifecycle integrity must be enforced by the service (resolver + deletion gate — ADR-004 amendment) instead of a relational foreign key.
- A future second KV consumer pays a new-surface TechSpec instead of reusing a public generic API — accepted as the deletable-greenfield default.

### Risks

- Envelope-contract drift between transports → the canonical DTO is defined once in the contract package and every transport type generates from it (N-002).
