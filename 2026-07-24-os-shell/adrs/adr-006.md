# ADR-006: The desktop metaphor is the product identity of the AGH web experience

## Status

Accepted

## Date

2026-07-19

## Context

AGH's category is "a local-first agent operating system" and its public hook is "an open workplace for AI agents". The current web UI is a conventional sidebar dashboard — the category is a claim, not an experience. Market research (2026-07) shows every competitor supervising agent fleets picked a non-desktop metaphor (Devin: kanban command center; OpenAI Codex app: thread list; Cursor: agent grid; Google Antigravity: manager panel; Hermes: kanban), while the term "agent operating system" industry-wide means an invisible coordination layer, not a GUI. The research also documents the metaphor's risks: Figma reversed UI3 floating panels because they slowed users down, and web desktops historically read as skeuomorphic novelty. No product today fuses floating windows + dock + command palette + per-workspace spaces + live cross-device continuity into an operator cockpit for local agents — that fusion is open white space.

## Decision

The AGH web experience **is** a desktop operating system, as product identity first:

- The PRD's primary goal is the identity experience — windows, dock, menubar, spaces, palette, wallpapered desktop — making the "agent operating system" category literal and ownable. Operator-supervision outcomes (side-by-side sessions, attention visibility, exact resumption) are the strong second goal and the metaphor's proof of value.
- The metaphor's known risks are carried as explicit product bets with mitigations (ADR-007 posture: attention surfaces + anti-clutter tools), not silently ignored.
- **Vocabulary:** `space` enters the public vocabulary as a narrow presentation term — *a workspace's desktop arrangement (windows + wallpaper)*. `workspace` remains the runtime object; the overview surface is named "Spaces". The glossary and `COPY.md` record this boundary.

## Alternatives Considered

### Alternative 1: Supervision-cockpit-first framing

- **Description**: Lead the PRD with operator-supervision outcomes; treat the desktop as replaceable means.
- **Pros**: Directly answers the market's documented pain ("which agent needs me now"); lower positioning risk.
- **Cons**: Reduces the shell to yet another mission-control layout in a crowded field; abandons the identity differentiation AGH's category promises.
- **Why rejected**: Owner decision — the desktop is the brand bet; supervision value is a consequence, not the headline.

### Alternative 2: Adopt a market-proven non-desktop metaphor (kanban / thread list / grid)

- **Pros**: Validated by every competitor; cheapest path.
- **Cons**: Zero differentiation; discards the prototype and the category story.
- **Why rejected**: AGH would compete on layouts others already own.

## Consequences

### Positive

- A defensible, ownable product identity no competitor ships today.
- The PRD's goals, stories, and copy get a clear hierarchy (identity → supervision → continuity).

### Negative

- AGH carries the burden of proof that windowing reduces (not adds) supervision load — the Figma lesson.
- Public "agent operating system" wording collides with the industry's infra-layer meaning; positioning copy must navigate that (Open Question in the PRD, `COPY.md` owner).

### Risks

- Skeuomorphic-novelty perception → mitigated by ADR-007's operator-load posture and by truthful-UI discipline (the desktop renders only runtime truth).

## Implementation Notes

Implementation direction is already fixed by ADR-001..005 (`_techspec.md`); this ADR governs product framing, goal hierarchy, and vocabulary for `_prd.md` and downstream copy.
