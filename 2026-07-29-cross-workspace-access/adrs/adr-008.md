# ADR-008: Agent fleet and detail are index leaves under search-neutral parent layouts

## Status

Accepted

## Date

2026-07-29

## Context

Task 04 added routed confirmation state to the session child route as
`workspaceSwitch=confirm|declined`. Two existing files combined leaf and layout responsibilities:
`agents.tsx` owned the fleet and parented the entire agents subtree, while `agents.$name.tsx` owned
agent detail and parented settings and session routes. Their fleet/detail `validateSearch` functions
therefore ran for descendants and normalized away the session-owned confirmation key before the
session route could read it.

The outer `agents.tsx` component was also `createOsRouteSync("agents")`, which renders `null`. TanStack
Router renders a route component instead of its implicit outlet, so the entire `/agents/**` descendant
tree never mounted. Per-leaf settings/session sync and `OsRouteHold` were dead code; the outer sync
only appeared to work because app-path resolution classified descendant paths separately.

The first full Web E2E run reached 113 cases: 111 passed, while the cross-workspace confirmation
journey lost `workspaceSwitch=confirm` and the OS coordinator restored the agent-detail window. Two
controller patches to the combined boundary did not remove that ownership conflict. The repository
two-touch rule requires a structural design before another production change.

After the route split, the existing session-hardening journey exposed a second boundary race. A
document navigation to agent detail issued the correct `openOrFocus` command, but a restored session
focus frame arrived before that asynchronous command completed and replaced the URL. The session
route then reconciled the stale focus back into the window manager, undoing the operator's route
intent.

## Decision

Both `agents.tsx` and `agents.$name.tsx` become search-neutral structural layouts. They retain their
shared breadcrumbs and render only `<Outlet />`. A new `agents.index.tsx` leaf exclusively owns fleet
search validation, loader dependencies, preload, and `createOsRouteSync("agents")`; the existing new
`agents.$name.index.tsx` leaf exclusively owns agent-detail search validation, preload, and sync. The
session leaf exclusively owns `workspaceSwitch`, session loading, confirmation, and `OsRouteHold`.

The routing coordinator treats an accepted route reconciliation as authoritative until its semantic
window-manager command completes. Authoritative frames received during that interval cannot replace
the URL; duplicate reports for the same route cannot issue duplicate commands; a new route, route
hold, or workspace switch invalidates the older pending reconciliation.

No parent passthrough or shell-level route parsing is introduced. Search parameters belong to the
lowest route that gives them meaning.

## Alternatives Considered

### Alternative 1: Preserve child search in the parent validator

- **Description**: Teach the agent-detail validator to pass through `workspaceSwitch`.
- **Pros**: Small diff and no new route file.
- **Cons**: Couples the parent to one child and repeats whenever another child owns search state.
- **Why rejected**: It preserves the structural ownership defect and violates the two-touch rule.

### Alternative 2: Host the decision in the OS shell

- **Description**: Move foreign-session confirmation and pathname parsing into the desktop shell.
- **Pros**: Avoids nested route search interactions.
- **Cons**: Makes the shell own session params, owner projection state, and a decision that belongs to
  one route leaf; broadens coordinator risk.
- **Why rejected**: The session leaf already owns the complete decision and has a dedicated route hold.

## Consequences

### Positive

- Descendant search state reaches its owning leaf without ancestor normalization.
- Direct agent detail keeps closed, typed search validation in its index leaf.
- Parent layout, detail screen, settings screen, and session screen each have one responsibility.
- Restored topology cannot overwrite a newer accepted route intent while its focus command is in
  flight.

### Negative

- The generated route tree gains fleet and detail index routes and the Storybook route registry must
  cover both.
- The router integration harness must mirror the production parent/index/session topology.

### Risks

- TanStack Router may expose the generated index as `/agents/$name/`; generation, typecheck, the route
  registry suite, and the real E2E must prove that the canonical external URL remains `/agents/$name`.
- Moving the breadcrumb into the index would remove useful ancestry from descendants. It remains on
  the parent layout.

## Implementation Notes

- Delete fleet `validateSearch`, `loaderDeps`, pathname-parsing loader branch, and OS sync from
  `agents.tsx`; move them into `agents.index.tsx` without pathname heuristics.
- Delete `validateSearch`, the agent-detail loader, `AgentRouteSync`, and exact-match branching from
  `agents.$name.tsx`.
- Add `agents.$name.index.tsx` with route ID `/_app/agents/$name/` and the existing agent-detail
  validator, preload, and OS sync.
- Regenerate `web/src/routeTree.gen.ts`; never edit it manually.
- Register `/agents/` and `/agents/$name/` in `web/src/storybook/route-story-registry.ts` using the
  existing Agents Fleet and Agent Detail stories.
- Keep `OsRouteHold` in the session leaf.
- Keep in-flight route authority in `RoutingCoordinator`; do not add timing delays or E2E retries.
