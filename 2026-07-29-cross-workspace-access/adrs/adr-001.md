# ADR-001: Cross-workspace access is decided by one central policy consulted at the existing enforcement seams

## Status

Accepted (amended by ADR-007, 2026-07-28 — the central-policy-at-seams decision stands; the decision *inputs* changed: the chain's grant/toggle steps are replaced by the session `PermissionMode` mapping, and the round-2 DB-backed `ToggleSource`/grant-store notes below are historical)

## Date

2026-07-28

## Context

Workspace isolation for agent actors is enforced today by five independent families with no single funnel: agent identity (`internal/agentidentity/identity.go:151` `ValidateWorkspaceAccess`, 403/exit 77), the task domain (`internal/task/task_resource_authorizer.go:31`, `run_read_authorizer.go`, `lease_claim_hooks.go`, 403/404-masked), tool scope binding (`internal/tools/dispatch.go:111` `bindCallScopeField`, `internal/daemon/native_tool_scope.go:149`, `internal/daemon/native_workspace_input_binder.go:111`, `ReasonScopeMismatch`), route scoping (`internal/api/core/workspace_scope.go:100`, generic 404), and the extension Host API binding (`internal/extension/host_api_workspace_binding.go`). The product now needs an operator-controlled way to allow cross-workspace access for agent actors.

L-033 (workspace resolution is a boundary) documents the failure mode of the obvious alternative: per-site policy logic drifts, and a cross-cutting security decision ends up depending on every future author remembering every prior implementation. The 2026-07-28 fragmentation analysis (`docs/_refacs/20260728-workspace-resolution-fragmentation.md` F1/F2) traces the recently closed isolation bypasses to exactly that shape.

## Decision

Introduce `internal/workspaceaccess`, a small package owning one interface:

```go
type Policy interface {
    Authorize(ctx context.Context, actor ActorRef, targetWorkspaceID string) (Decision, error)
}
```

Every existing deny site that today hard-rejects a workspace mismatch for agent actors consults the injected `Policy` instead of denying inline. The default decision chain is: operator bypass → same-workspace fast path → persisted per-agent grant (allow or reject) → global toggle → deny. *(ADR-007 replaced the grant/toggle steps with the session `PermissionMode` mapping — `approve-all` allow, `deny-all` deny, `approve-reads` ask; the TechSpec owns the current chain.)* `internal/daemon` wires the implementation (composition root, SD-008); subordinate packages receive it via constructor options (pattern: `WithWorkAdmissionChecker`, `internal/task/manager_admission.go`). A nil policy fails closed to today's behavior.

Route scoping (`requireSessionInWorkspace`) and window-manager snapshot checks are explicitly NOT policy seams: the former is URL/data consistency (actor-independent), the latter is a store-integrity invariant. They stay unchanged.

## Alternatives Considered

### Alternative 1: Per-site config checks

- **Description**: Add `if cfg.WorkspaceAccess.CrossWorkspace { ... }` branches at each of the ~10 deny sites.
- **Pros**: No new package; each site keeps full local control.
- **Cons**: Recreates the exact shotgun-surgery anti-pattern L-033 documents; five families already diverge on sentinel, status code, and comparison semantics; every future deny site must remember the check.
- **Why rejected**: The repo's own institutional memory forbids it; the bypasses fixed this same week were caused by this shape.

### Alternative 2: HTTP/UDS middleware

- **Description**: Enforce cross-workspace policy in a Gin/UDS middleware layer.
- **Pros**: One choke point per transport.
- **Cons**: HTTP has no identity middleware today — actor identity is resolved per-handler; task/tool/spawn/coordination checks are not HTTP-shaped at all (they run inside domain services); a transport middleware cannot see tool input bodies or spawn options.
- **Why rejected**: The enforcement surface is domain-level, not transport-level; a middleware would cover a minority of the seams and give false confidence.

### Alternative 3: Relax enforcement to soft filters

- **Description**: Delete the hard blocks and rely on SQL `WHERE workspace_id = ?` filters plus frontend scoping.
- **Pros**: Least code.
- **Cons**: Destroys the security boundary entirely; the frontend is explicitly not a boundary; contradicts the 2026-05-12 hard-cut plan and requirement 10 of the resolution brief.
- **Why rejected**: The goal is an operator-controlled door in the fence, not removing the fence.

## Consequences

### Positive

- One place owns the allow/deny semantics; new deny sites get policy behavior by calling the same interface.
- Default behavior (no toggle, no grants) is byte-identical to today — the change is strictly additive.
- Audit events can be emitted from inside the policy, before per-family error masking (404 conversion) destroys the signal.

### Negative

- Each seam still needs a one-time edit to thread the policy handle (identity, task option, tool binder, spawn, coordination, claim hooks).
- Two actor structs (`task.ActorContext`, `tools.Scope`) must be mapped into `workspaceaccess.ActorRef` at call sites.

### Risks

- A seam is missed and keeps hard-denying: mitigated by the cross-seam parity test matrix in `_tests.md` (same scenario exercised through CLI, HTTP, native tool, task claim, and spawn).
- Policy consulted with a raw ref instead of a resolved registry ID: mitigated by the invariant that `Authorize` receives canonical `ws_*` registry IDs only, normalized via `Workspaces.Resolve` (fragmentation analysis F11).

## Implementation Notes

`workspaceaccess` is config-agnostic: it imports stdlib + `internal/logger` only, and receives config state through an injected `ToggleSource` interface (peer review round 1, N-001 — this supersedes the earlier "imports `internal/config` types" wording; the TechSpec's Architectural Boundaries section is the single dependency rule). It must not import `internal/config`, `internal/events`, `agentidentity`, `task`, `tools`, `session`, or `daemon`. Consumers import it downward. `magefiles/boundaries.go` gains the new package rule in the same commit.

Round-1 hardening (B-002, B-003, B-005): the policy takes a typed `Request{Actor, TargetWorkspaceID, Seam}`; `ActorRef` carries a daemon-validated `ActorKind` and only `agent_session` actors are eligible for cross-workspace allowance; constructor dependencies are required (`New(Deps) (…, error)`), the toggle accessor returns `(bool, error)`, grant-store errors deny before the toggle is consulted.

Round-2 hardening: request validation is step zero (before any policy branch); `ToggleSource` is implemented against the DB-backed `workspace_access_state` row (ADR-005), never config; `ActorRef` construction at the native seam goes through a daemon-owned session-actor resolver (never JSON-carried `tools.Scope` fields — those are conflict-checked transport hints only); audit is fail-closed for allows (an allow whose record cannot be durably appended becomes a deny) and best-effort for denies (a deny that cannot be recorded is still a deny), replacing the round-1 log-and-continue rule.
