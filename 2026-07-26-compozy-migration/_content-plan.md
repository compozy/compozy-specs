# Content and Naming Migration Plan (AGH → CompozyOS)

This document supplements [`_techspec.md`](_techspec.md). It owns the non-code naming, copy, and content surfaces that are outside the techspec's code-scoped delete targets and grep gates. Evidence: round-2 analyses [`05_analysis_repo-docs-copy-memory.md`](analysis/05_analysis_repo-docs-copy-memory.md), [`06_analysis_site-content-seo.md`](analysis/06_analysis_site-content-seo.md), and [`07_analysis_legacy-channel-assets.md`](analysis/07_analysis_legacy-channel-assets.md), plus `analysis/summary.md` (round-2 section). User decisions are recorded in `_brief.md`.

The legacy-source baseline is the official `../compozy` repository at stable **v0.2.15** (`8f8908afd70c731b815e20282bacad05aa026827`), with post-tag official HEAD `c202311c8430fc0d4a7442e2dc715cabfbdc68a1` audited separately. Do not infer behavior from older v0.2.x tags without recording the difference.

## Classification model

Every content artifact has exactly one class. The class determines ownership and timing.

| Class | Meaning | Typical verification |
| --- | --- | --- |
| **MECHANICAL** | A token sweep that ships with a code rename: paths, environment variables, IDs, URLs, or package names. | A scoped grep gate and co-shipped fixed-literal tests. |
| **REWRITE** | Authored CompozyOS copy replaces AGH copy: positioning, definitions, and narrative. A find-and-replace is not sufficient. | Copy review against `COPY.md` §§4–5 after the rewrite, then `make verify`. |
| **REGEN** | Generator output. Change the generator input and regenerate; manual output edits are prohibited. | Generator execution and `make codegen-check` or a clean generated diff. |
| **NEW** | Content that does not yet exist: migration guide, launch copy, redirects, or a front-door README. | The artifact exists, is linked, and the applicable gates pass. |

There is no **LEAVE-ALONE** class for brand tokens. Historical lessons, RFCs, blog posts, changelog receipts, and tweets receive the complete brand sweep while preserving their dates, facts, and structure. The sole path-name exception is the intentionally retained, versioned `agh-*` development-skill path set described in the verification gates; its bodies still receive a separate live-identifier scan.

## Recorded decisions and prerequisites

1. **Development skills:** `.agents/skills/eng/agh-*` retain their path names. Their bodies must replace live environment variables, paths, commands, and binary identifiers so the skills remain executable.
2. **Historical policy:** rewrite all brand references. RFC names, lessons, `_synthesis`, blog posts, changelogs, and tweets are included in the sweep.
3. **Hero and wordmark:** a full hero rewrite is approved. P1-f uses a simple provisional `Compozy` typographic lockup; P5 adds the designed Compozy wordmark.
4. **License narrative:** this is a distribution-metadata correction, not a relicensing. ADR-005 remains authoritative.
5. **Voice:** the canonical register is people-first, plain-spoken, and calm-confident (`COPY.md` §5). The primary audience is people who run agent work, technical or not (`COPY.md` §4). “Operator cockpit” is an anti-reference; use `control surface`, not `operator surface`.
6. **OS-first positioning:** the primary narrative is the locked hero, “The only true OS for AI agents.” Its adjacent definition must supply the test: “A window on top of an agent isn't an OS. An OS runs the work, keeps the memory, sets the permissions, connects agents to each other — and lets you build on it. That's the test, and Compozy is the only one built to pass it.” The claim is integrated completeness, not an unqualified feature list; extensibility is the second criterion of “true.” Institutional and comparison surfaces name the relevant competitors whenever they use “only.”
7. **Domain — RESOLVED (brief round-11, single cut):** `compozy.com` points at the `packages/site` deployment at the cut, replacing the legacy marketing deployment; `agh.network` retires. No redirect infrastructure ships in this repository (any courtesy DNS redirect is optional operator work), no canonical-URL staging exists, and the only redirect entry is Task 04's same-domain renamed launch-post slug mapping. Execution requires the DNS/hosting owner and is recorded in Task 10's single-cut runbook.
8. **Installer — RESOLVED (brief round-11, single contract):** the hosted `install.sh` implements only the v0.3 Sigstore contract and installs the documented beta version explicitly; it never validates legacy PEM assets and carries no dual-path fallback. Legacy installs belong to `legacy/v0.2` collateral. When 0.3.0 final ships, the default target becomes latest stable through normal post-beta release maintenance outside this migration.
9. **External web-assets authority — external decision required:** hard-cutting the external `github.com/compozy/agh-web-assets` module/package to `compozy-web-assets` needs repository ownership, publication authority, and release sequencing. Record the owner and publish order before the relevant P1 code task; do not assume that this repository can create the external release.

> **Dating note.** Analyses 05–07 predate the current voice and positioning locks. They remain dated evidence; this plan is the live authority when their wording conflicts.

## Verification gates

- **Versioned two-part Markdown brand gate:** the global Markdown/MDX sweep runs per content phase with the checked-in, versioned path-name exclusion for the intentionally retained `.agents/skills/eng/agh-*/**` development-skill paths. It is a path exception only, not a body exception. Example: `rg -in '\\bagh\\b|agh-network|agh\\.network|Artificial General Hivemind' --glob '*.md' --glob '*.mdx' --glob '!.compozy/**' --glob '!node_modules/**' --glob '!**/.agents/skills/eng/agh-*/**'`. Maintain the exact excluded path set with the v0.3.0 migration evidence; do not use a broad `agh` directory exclusion.
- **Live-identifier scan for retained development skills:** separately scan the bodies of every retained `agh-*` development skill and its references for live `AGH_*`, `.agh/`, `agh ` command, hosted-tool, and endpoint identifiers. Permit only the retained path/name identifiers and historical examples explicitly classified in the evidence. This scan has its own zero-unreviewed-results gate.
- **Migration-guide parity gate:** add a reproducible repository script that normalizes frontmatter and MDX-only markup, compares the canonical eight section IDs and their canonical content between A15 and B10, prints a useful diff, and exits nonzero on drift. The guides are a user-facing product contract, so this focused static gate is permitted; it does not replace runtime tests.
- **Copy-register review for REWRITE and NEW:** review each authored artifact against `COPY.md` §§4–5 and `PRODUCT.md` user/brand-personality sections. Verify the correct primary audience, plain first-line language, a mechanism one step behind the outcome, and no cockpit/control-room framing, hype, `we`, or emoji. This is review evidence, not a prose unit test.
- **Register anti-regression grep:** run `rg -in 'operator-first|engineer-to-engineer|operator cockpit|operator surface|As an operator' --glob '*.md' --glob '*.mdx' --glob '*.tsx' --glob '!.compozy/**' --glob '!node_modules/**'`. The result must be zero except documented technical uses such as `home_policy = operator`, `operator HOME`, and `operator_persona`.
- **Fixed-literal co-ship:** update each B5 suite in the same commit as the surface it pins. `protocol-rfc-hard-cut.test.ts` is the highest-risk cross-tree case because it couples the site test, root RFC filenames, and glossary.
- **Generated-content checks:** run `make cli-docs`, the OpenAPI generator, and `make codegen-check` after the corresponding inputs change. Regenerate changelog output through its existing script.
- **Cross-surface install gate:** `public-install-contract.test.ts` is the canonical gate for final channel identities across the root README, landing page, documentation, and launch post. During the beta window it asserts the beta channel paths (npm `@beta`, hosted installer, versioned `go install`) and the absence of Homebrew from every shipped install surface.
- **Single-cut live checks (Task 10 runbook):** the GitHub prerelease exists; `npm dist-tag ls @compozy/cli` shows `beta=0.3.0-beta.N` and `latest=0.2.15`; the Homebrew formula is unchanged; the hosted installer installs the documented beta with Sigstore verification; `go install github.com/compozy/compozy@v0.3.0-beta.N` builds in a clean environment; `compozy.com` serves the `packages/site` deployment and `agh.network` no longer serves the old site; `main` is the squash-merged v0.3 tree and `legacy/v0.2` carries its maintenance notice; `compozy/agh` is archived with its pointer README; `@compozy/agh` deprecation is verified after its terminal publish; no shipped install surface offers Homebrew and the tap formula carries its deprecation notice.
- **Post-beta stable release checks (outside this migration):** when Pedro exits beta, the `channel=stable` release moves `npm dist-tag ls` `latest` to `0.3.0`, `brew info compozy` reports 0.3.0, and beta install copy re-tags to stable — normal release maintenance, not a spec task.
