# CompozyOS Merge Brief (AGH → Compozy)

- **Accepted:** 2026-07-08
- **Status:** Product scope and architecture decisions are closed; implementation has not started. Three external release decisions remain explicitly unresolved below.
- **Legacy baseline:** stable Compozy `v0.2.15` at commit `8f8908afd70c731b815e20282bacad05aa026827`, plus an explicit audit of post-tag official HEAD `c202311c8430fc0d4a7442e2dc715cabfbdc68a1`.
- **Context:** Merge the AGH codebase (the stronger architecture and wider feature set; alpha `0.0.9`; zero users) into the Compozy product line (2,500+ stars and active users). AGH becomes the engine; Compozy’s brand and traction are preserved.

## Closed decisions

1. **Brand: CompozyOS.** The product brand is “CompozyOS”. All artifacts retain the `compozy` name: binary `compozy`, repository `github.com/compozy/compozy`, npm `@compozy/*`, and the eventual website/domain `compozy.com`.
2. **Protocol: `compozy-network/v0`.** Rename the wire protocol from `agh-network/v0`. This includes `RuntimePeerID` (`agh.runtime` → `compozy.runtime`), the envelope extension-key namespace (`agh.*` → `compozy.*`), and loop `apiVersion` (`agh.loop/v1` → `compozy.loop/v1`). There is no separate protocol brand. Reconsider a standalone protocol brand only when there is a first consumer outside the daemon: a second runtime, a published protocol SDK, or real cross-process transport.
3. **Version: `v0.3.0` — “The OS Release”.** This remains on the Compozy repository lineage: no reset to `0.0.x` and no jump to `1.0`.
4. **Breaking-change posture: no compatibility verbs.** `compozy tasks run` and `compozy reviews watch` are not recreated as vertical commands. Loops (`compozy loop run --workspace <ref> --name ... --input ...`) are the canonical surface. This explicit breaking release ships with a **migration guide** covering old-to-new commands, configuration translation, and what changed and why.

## Historical design question

1. **Per-task runtime-selection mechanism** (P0 item 2): the considered layers were (A) task front matter carrying `runtime: {provider, model, reasoning}` as authored and versioned intent; (B) a per-run override; and (C) workspace configuration rules, similar to legacy `--task-runtime type=...`, followed by agent defaults. The accepted design uses dedicated `--runtime` config overrides rather than loop inputs and owns the final precedence and implementation; this question originated with **Linear AGH-80** (<https://linear.app/compozy/issue/AGH-80>).

## Additional closed decisions (2026-07-26, round 12 — agent-authored `review-and-fix`)

These supersede the CodeRabbit-first review pipeline in P0-1, the P0-4 `fetch_reviews.provider` rationale, and the round-7 `reviews watch` command mapping, and they amend ADR-003 through ADR-008. The governing product intent: **`review-and-fix` is an internal Compozy journey with no external dependency.** A Compozy reviewer agent reviews the work and authors the round's issues; a fixer node remediates them. CodeRabbit is not the axis, the source, or a requirement of the loop.

- **The review source is a Compozy reviewer agent, not a fetched provider.** Each round the loop runs the dev-cycle `reviewer` agent, which emits source-agnostic `ReviewIssue[]` through its `output_schema`. The Go writer (`ext__dev_cycle__write_review_artifacts`) remains the only serialization authority and `ext__dev_cycle__finalize_review_round` closes the round (ADR-003 decisions 2–6 stand). The loop terminates when a review round emits zero issues; the next round's review is the verification of the previous round's fixes, so no separate judge/verify gate exists in the loop.
- **All CodeRabbit surface in dev-cycle is a delete target.** The CodeRabbit fetch/normalization/nitpick/REST code and its tool descriptors, the `new_review` PR watch source, GitHub thread resolution (`resolve_threads`), and the push tail (`should_push`/`push_changes`) are removed, not abstracted. The round-1 deferral of a review-provider abstraction stands; v0.3.0 ships **no** external review fetch/resolve at all, and no `gh` dependency remains in the loop.
- **Watch semantics die with the source.** The loop is `review-and-fix`, a run-to-completion remediation loop — not a renamed watch. The `pr`, `include_nitpicks`, `poll_interval`, `quiet_period`, `auto_push`, and `push_remote` inputs are deleted; `task_name` becomes the required input (no `pr-<N>` derivation), and `auto_commit` remains as the only execution-mode input because it is local-only. Pushing remediated work belongs to the operator or an outer loop, never to this loop. Round caps use the loop contract (`iteration_cap`/`no_progress`), not a new input.
- **Provider provenance leaves the artifact contract.** `ReviewIssue` drops the fields only a fetched provider ever filled — `provider`, provider reference, `review_hash`, source review ID, and source submitted-at — and the provenance-based history dedupe goes with them. What remains: the inspectable `reviews-NNN/issue_NNN.md` layout, deterministic Go serialization, monotonic `pending → valid|invalid → resolved` lifecycle, trusted-workspace containment, and append-only exclusive rounds. Legacy **byte**-parity ceases to be a goal; v0.3.0 owns its own golden fixtures. This is an accepted, documented non-parity with legacy Compozy v0.2.15.
- **Migration consequences.** The guide maps `compozy reviews watch` to the agent-authored `review-and-fix` run with an explicit semantic-change note. In the migrator (task 14), every `watch_reviews.*` and `fetch_reviews.*` key becomes a report-only drop; only `defaults.auto_commit` still translates to a `review-and-fix` input.
