# ADR-002: Per-Invocation Runtime Override Through Dedicated `--runtime`

## Status

Accepted

## Date

2026-07-11

## Context

The brief originally described per-invocation model overrides through loop
`--input`. Inputs belong to a loop author's declared namespace; reserving
runtime-shaped input keys would collide with that namespace and bypass normal
input validation. The existing per-run configuration layer is
`RunLoopRequest.ConfigOverrides`, which ADR-001 extends with runtime defaults
and rules.

## Decision

`compozy loop run` receives a repeatable `--runtime` flag:

```text
compozy loop run --workspace <ref> --name software-delivery \
  --runtime worker=claude/opus@xhigh \
  --runtime type=frontend:claude/opus \
  --runtime complexity=high:codex/gpt-5.5-codex@high \
  --runtime id=task_03:openrouter/anthropic/claude-opus-4-7@high
```

The runtime triple is `provider/model[@reasoning]`:

- the provider is the segment before the first `/`; `-` omits it;
- the model is the remaining text and may contain `/`;
- reasoning is the suffix after the final `@` and must be one of the canonical
  AGH values returned by `internal/reasoning.Values()`:
  `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, or `max`;
- a value without `/` is model-only sugar (`worker=opus` means
  `worker=-/opus`);
- match values cannot contain `:`; model IDs containing `@` use structural
  `--set` or `--config-file` instead.

The CLI parses the flag into per-run `runtime_defaults` and `runtime_rules`.
It is syntax sugar only: HTTP, UDS, native tools, and scripts use the same
structured `config_overrides` contract. Rule precedence, including
`id > type > complexity`, remains ADR-001's engine responsibility. Dry-run
human and JSON output show the parsed per-run layer.

## Alternatives Considered

### Only `--set` and `--config-file`

They remain supported for agents and scripts, but make the frequent migration
from `--task-runtime` unnecessarily opaque for interactive use.

### Reserved `--input` keys

This would intermingle engine configuration with author-defined inputs and
create shadowing and bimodal validation. It is rejected.

## Consequences

- The brief's intent is met without making runtime a loop input.
- The migration guide maps legacy task-runtime rules to `--runtime` and to
  structured runtime rules where a script needs values that this grammar cannot
  represent.
- The parser must reject malformed or ambiguous values deterministically;
  invalid reasoning is never silently absorbed into a model ID.

## Implementation Notes

Implement the parser beside `internal/cli/loop.go`, map it into contract types,
and co-ship completion, generated CLI reference, parser tests, and dry-run
output. No new engine override mechanism is introduced.
