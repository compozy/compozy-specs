# ADR-003: `reviews-NNN/` Artifacts — Source-Agnostic Dev-Cycle Writer, File-Based Fixer

## Status

Accepted — amended by [ADR-008](adr-008.md) (2026-07-26): the fetched-provider
context is superseded; review issues are agent-authored, provider provenance
fields and history dedupe are removed, and legacy byte-parity is no longer a
goal. Decisions 2–4 and 6–7 remain in force as written.

## Date

2026-07-11

## Context

P0 requires the inspectable markdown review layout that legacy users depend
on. The current `reviews-watch` loop can fetch, fix, verify, resolve, and push
but writes no on-disk artifacts. The legacy layout is
`.compozy/tasks/<name>/reviews-%03d/issue_%03d.md`, with deterministic
frontmatter and an in-place lifecycle of `pending → valid|invalid → resolved`.

Review issues can arrive from CodeRabbit or a reviewer agent. The artifact
format must not depend on agent prompting: it is a product contract, not a
best-effort instruction.

## Decision

1. **Source-agnostic input.** `ReviewIssue` carries the complete legacy
   `ReviewFileMeta` shape: title, body, file, line, severity, author, provider,
   provider reference, review hash, source review ID, and source submitted-at.
   CodeRabbit maps into it mechanically; a reviewer agent may emit
   `ReviewIssue[]` through its existing `output_schema`. Legacy v0.2.15 had an
   executable review-provider extension abstraction; this migration
   deliberately does not carry it forward, so CodeRabbit is the only fetched
   provider in v0.3.0 and the regression is documented in the migration guide.
2. **The writer owns all artifact authority.** The dev-cycle tools
   `ext__dev_cycle__write_review_artifacts` and
   `ext__dev_cycle__finalize_review_round` exclusively choose the round,
   timestamps, status transitions, and serialized bytes. Agents may edit only
   the Triage/Decision content of existing issue files; they never create,
   rename, timestamp, or finalize them. `fix_batch` receives issue paths, not
   issue bodies, and activates `cy-fix-reviews`.
3. **Writes use the trusted workspace identity, not a caller-supplied root.**
   The extension host resolves the active trusted workspace root, then resolves
   the task path beneath its existing `.compozy/tasks` ancestor. `task_name` is
   a validated relative logical name, never a filesystem root. The writer may
   resolve and canonicalize that already-existing trusted ancestor (including
   the macOS `/private` form), but every missing descendant is opened/created
   relative to an `os.OpenRoot`-equivalent directory handle with no symlink
   traversal. Controlled `reviews-NNN/issue_NNN.md` names and exclusive round
   directory creation close both prefix-check and time-of-check/time-of-use races.
4. **Round and history semantics are writer-owned.** The next round is
   `max(existing reviews-NNN) + 1`; concurrent calls cannot share a directory.
   Before the writer runs, the pipeline deduplicates repeated source-history
   entries by `review_hash`, prior status, and source review ID/submission time,
   so resolved comments do not reappear while a genuinely newer review of the
   same hash remains eligible.
   Finalization rewrites only `valid|invalid` to `resolved`, leaves `pending`
   untouched, and is idempotent.
5. **Exact legacy defaults are preserved.** Missing `file` and `author` write
   as `unknown`; a missing title writes `Review comment`; an empty body writes
   the documented legacy fallback body. Agent-authored issues omit
   `source_review_submitted_at` when it is empty. Golden fixtures own field
   order, omission rules, headings, and body shape.
6. **Hard cut.** `reviews-watch` is renamed to `review-and-fix`; its old
   directory, manifest entry, catalog copy, and references are delete targets.
   `_meta.md` is not read. Round metadata is reconstructed from issue
   frontmatter, while pre-existing `_meta.md` remains readable text.
7. **Skill authority is explicit.** The file-based fixer path requires the
   bundled `cy-fix-reviews` skill supplied by ADR-004. The loop's functional
   completion depends on that projection; a prompt cannot replace the writer
   or skill installation contract.

## Alternatives Considered

### Generic loop-engine artifact node

Only dev-cycle owns this domain today. Moving worktree I/O and path-safety into
the engine would add a generic primitive without a second consumer.

### Daemon review package and host API

Porting legacy storage into the daemon would expand core API surface for a
dev-cycle-specific contract.

### Agent-authored artifact files

Prompt-mediated serialization is not deterministic or byte-testable and is
therefore rejected.

## Consequences

- Two mutating extension tool descriptors, schemas, digests, and dispatch
  paths co-ship with the loop graph and golden tests.
- The review artifact store is the contained workspace filesystem; no SQLite
  table or `_meta.md` reader is introduced.
- `concurrency: forbid` complements, but does not replace, exclusive round
  creation as the correctness boundary.

## Implementation Notes

Add `extensions/dev-cycle/review_artifacts.go` and its focused contract tests
under the file-size cap. Evolve the graph to
`fetch_issues → write_artifacts → fix_batches(paths) → verify →
finalize_round → resolve_threads → should_push → push_changes`. An explicit
`task_name` wins; otherwise the writer derives `pr-<N>`. Workspace defaults for
declared review inputs arrive through ADR-007.
