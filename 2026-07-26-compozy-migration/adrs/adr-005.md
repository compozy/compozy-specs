# ADR-005: Distribution Identity — MIT Metadata and Active Legacy Channels

## Status

Accepted

## Date

2026-07-11

## Context

The legacy product ships `compozy`, the `compozy` Homebrew formula, and
`@compozy/cli`. Its GoReleaser AUR block is commented out and the repository
explicitly says the package is not active, so `compozy-bin` is collateral rather
than a v0.2.15 distribution channel. AGH ships under its own binary and package
identities, while retaining stronger release automation including nfpm, cosign
bundles, and installer contract checks.

The legacy repository license is MIT. `BSL-1.1` appears only in stale
distribution metadata and an archived release note; it is not a license change
to make. The legacy repository also exposes a public Go library facade that
the incoming runtime does not provide.

## Decision

1. **MIT is continuous; metadata is corrected.** v0.3.0 repository,
   GoReleaser, npm, nfpm, and package metadata state MIT. Release-facing copy
   says that published metadata was incorrectly stamped `BSL-1.1` while the
   project remained MIT. It must never call this a relicensing.
2. **Active legacy channel identities are adopted.** The binary is `compozy`; the
   formula is `compozy` in `compozy/homebrew-compozy/Formula`; npm is
   `@compozy/cli`; and nfpm packages are `compozy`. v0.3.0 does not activate or
   claim an AUR channel. `@compozy/agh` is retired through a final deprecation
   notice pointing to `@compozy/cli`.
3. **Release security is renamed, not replaced.** The pipeline keeps nfpm,
   signed bundles, and installer contract checks, with
   `RELEASE_REPO="compozy/compozy"`, a regenerated cosign certificate identity
   for the renamed release workflow, and `COMPOZY_VERSION`,
   `COMPOZY_INSTALL_DIR`, and `COMPOZY_SKIP_BOOTSTRAP` installer variables.
4. **Channel mechanics are architectural release contracts (amended, brief
   round-11 single cut).** The pinned workflow serves `beta|stable|legacy`
   channels: a beta tag is a GitHub prerelease and publishes npm only under
   `beta`; npm `latest`, Homebrew, and `go install @latest` remain on v0.2.x
   during the beta window. v0.3.0 ships through the beta channel at the single
   cut; moving npm `latest` and bumping Homebrew is the normal post-beta
   `channel=stable` release through the same workflow, outside the migration
   spec. The hosted `install.sh` serves only the v0.3 Sigstore contract and
   installs the documented beta version explicitly — it never validates legacy
   PEM assets and has no dual-path fallback; legacy installs belong to
   `legacy/v0.2` collateral. Homebrew is hidden from every shipped install
   surface during the beta window and the runbook marks the legacy tap formula
   deprecated, pointing at the beta install paths; the 0.3.0 stable bump
   restores it. `compozy.com` serves the site from the cut with no staged
   domain cutover. These mechanics define channels; the human runbook owns
   publishing and live operational checks.
5. **Self-update uses legacy channel identity and tracks the running
   channel.** Detection uses `/node_modules/@compozy/cli/` and the
   install-path probes. A beta build tracks the beta channel: the update check
   offers newer v0.3 prereleases, never the v0.2.x stable line, and its
   instruction strings point at the beta paths (`npm install -g
   @compozy/cli@beta`, the hosted installer). `brew upgrade
   compozy/compozy/compozy` instructions appear only once the formula ships
   0.3.0 (post-beta). Published homepages use `https://compozy.com`.
6. **The old Go module closes honestly.** The final
   `github.com/compozy/agh` tag contains a `Deprecated:` go.mod notice pointing
   at `github.com/compozy/compozy`; pkg.go.dev keeps its historic page. The
   archived `compozy/agh` repository receives a pointer README, not a git
   redirect. The legacy public Go library facade (`compozy.go`, `pkg/compozy/*`,
   `sdk/*`) is removed in v0.3.0; library users pin v0.2.x.
7. **Legacy npm deprecation is deterministic.** After the terminal legacy
   publication, the release runbook deprecates every published
   `@compozy/agh` version with a pointer to `@compozy/cli` and verifies the
   registry result. This is an operational step, not a new package alias.
8. **Public SDK package collisions are not overwritten.** The legacy
   `@compozy/extension-sdk@0.1.x` and `@compozy/create-extension@0.1.x` expose a
   different extension API from AGH's workspace SDK/scaffolder. The v0.3.0
   workspace packages are marked private and remain version-matched repository
   artifacts; the legacy registry lines receive no v0.3 successor or false
   API-preserving rename claim.

## Alternatives Considered

### Make BSL metadata true

That would be a new restrictive relicensing and contradict the canonical MIT
license and public project materials.

### Retain `@compozy/agh`

That would strand existing `@compozy/cli` users and violate the locked
in-place-channel identity.

## Consequences

- Active installation channels retain their names while gaining AGH's supply
  chain protections.
- No AUR automation or public SDK-package successor is added by this migration.
- The public-library removal is an intentional compile break and must appear in
  the migration guide.
- A release identity or cosign mismatch is security-critical and is covered by
  co-shipped installer contract checks.

## Implementation Notes

Update release configuration, workflow identity, installer, self-update paths,
package metadata, and the tap collateral together. The workflow and vendored
release skill pin `github.com/compozy/releasepr@v0.0.24`; its read-only `plan`
command validates explicit ref/version/channel inputs, checked-out commit
identity, and local/remote tag absence, then supplies the authoritative
GitHub/npm/Homebrew policy. The repository workflow still creates the annotated
tag and performs publication. Channel publishing, repository archival, and DNS
changes remain human-runbook operations after the required QA gate.
