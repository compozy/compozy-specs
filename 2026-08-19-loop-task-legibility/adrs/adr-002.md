# ADR-002: One loop run page, two registers via progressive disclosure

## Status

Accepted

## Date

2026-08-19

## Context

The loop run page is the canonical observability home (ADR-001 removes loop records from Tasks). Today it is an operator cockpit: 9+ sections competing in the main column plus a 4-card rail, exception-only node rows, mono ids in primary positions. PRODUCT.md names this exact texture as retired anti-reference ("Operator cockpits") and mandates principle 2: "Approachable first, deep on demand — the default read of every screen for someone meeting agent work for the first time: few elements, plain words, obvious next action." Market research adds a named anti-pattern: a "simple mode" that is the cockpit minus panels fails — two registers work when the simple register is a different artifact (narrative summary, derived rollups), not a subset toggle. Nielsen's briefing test: a returning user absorbs status, effort, and pending decisions in 30 seconds.

## Decision

One run page, no simple/advanced mode toggle. The **default register** is a plain-language narrative answering exactly four questions: what is running, what needs you, how far along it is (steps + rounds), and what it produced. The **operator register** (node roster, run-bound live DAG, generation history, attempts, raw events, ids) lives one step deeper behind progressive disclosure (Inspect surfaces and expandable sections). Failure and needs-you signals never collapse — they render in the default register regardless of disclosure state. Status copy reports meaning ("rejected the first approach after 3 tries"), never mechanics ("14 tool calls"). All rendered state maps to runtime truth (SD-007).

## Alternatives Considered

### Alternative 1: Simple/advanced mode toggle

- **Description**: A persisted per-user switch flips the page between a simplified layout and the current cockpit.
- **Pros**: Cheap; keeps the cockpit untouched.
- **Cons**: Two artifacts that drift; the "simple" one is the cockpit minus things (named market anti-pattern); default choice fights PRODUCT.md's approachable-first mandate.
- **Why rejected**: Disclosure keeps one truthful artifact with depth one step away.

### Alternative 2: Separate page for non-technical users

- **Description**: A second route with a consumer-grade view.
- **Pros**: Free rein on register.
- **Cons**: Splits the source of truth, doubles maintenance and QA scenarios, and PRODUCT.md frames non-technical users as future-served by making the default read plain — not by a parallel app.
- **Why rejected**: Same drift problem as Alternative 1, worse IA.

## Consequences

### Positive

- One page passes the briefing test for everyone; operators pay one click for depth (Nielsen: acceptable price).
- QA guards one surface contract instead of two.

### Negative

- Redesign cost on the run page (largest UI lift of this spec, per owner).

### Risks

- Over-simplification hiding real state → guardrails: SD-007 (never invent, never hide modeled failure/attention), L-004 (coordinator/system work stays distinguishable in the operator register).
