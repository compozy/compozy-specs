# ADR-004: Single authored permissions list; consent areas derived; `security.capabilities` deleted

## Status

Accepted

## Date

2026-07-28

## Context

Authors maintain three capability axes in one manifest: `capabilities.provides` (what the extension offers), `actions.requires` (Host API method paths), and `security.capabilities` (coarse grant areas) — the latter two are hand-kept lists that must agree, then are re-asserted by the SDK at `initialize` (`ensureSubset`), with `capability_denied` on mismatch. Validation is shape-only (`validateDottedIdentifiers`), so unknown strings (the scaffold's `message.read`/`message.write`, docs' `prompt.provider`) load as silent no-ops. "Capability" simultaneously means network artifact (glossary), provides-surface, and security grant. The audit counted this cluster as 4 of the 45 concepts, and the grant→method map even contains a truthfulness bug (`resources.write` mapped to a read path — `capability_host_api.go:52`).

## Decision

The authored surface is **one list**: `permissions` — the Host API method paths the extension calls, written with generated typed constants (ADR-003). In the generated manifest (ADR-001) this serializes as `[permissions] requires = ["sessions/list", …]`. The daemon:

- validates it **closed-set** at manifest load (unknown method = load error, never a no-op), same for `capabilities.provides` against the 5 registered provide surfaces;
- **derives** coarse consent areas for display (install consent, web UI, provenance) from the method list via the existing method→area mapping, inverted — the derivation table is generated from `internal/extension/contract`, fixing the `resources.write` mismap in the same change;
- keeps enforcement exactly where it is today (`CapabilityChecker.CheckHostAPI` per call), driven by the single list.

Deleted as authored concepts: `[security] capabilities`, `[actions] requires` (renamed), the SDK's `SecurityConfig`/`ActionsConfig` duplication, and the marketplace grant "ceiling" doc/code divergence (ceiling is re-derived from areas). Glossary gains entries: **Permissions** (extension → Host API), **Provides** (extension capability surfaces), and the network **Capability** entry gets a disambiguation note.

## Alternatives Considered

### Alternative 1: Coarse areas only

- **Description**: Author declares areas (`session.read`, `memory.write`); daemon allows every method in the area.
- **Pros**: Shortest list to write.
- **Cons**: Loses least-privilege per method; consent display and enforcement decouple from what the extension actually calls; areas are a Compozy-invented taxonomy authors must learn, whereas method paths are the API they already use.
- **Why rejected**: Grants more than the author asked for and teaches an extra vocabulary.

### Alternative 2: Keep both lists, validate consistency

- **Description**: Closed-set validate both and cross-check agreement at build.
- **Pros**: No manifest schema change.
- **Cons**: The two-lists-plus-agreement-rule concept survives; SDK re-declaration survives; concept bill unchanged.
- **Why rejected**: Validation without simplification fails R9 (concept bill ≤20).

## Consequences

### Positive

- One concept replaces four; consent UI stays human-readable via derivation; typo'd permissions fail loudly at build/load; docs ceiling can no longer diverge from code.

### Negative

- Manifest schema break (greenfield hard cut; delete targets listed in the TechSpec) — installed-extension registry rows re-shape; alpha wipe/reinstall of extensions is the accepted cost.

### Risks

- Derived areas surprising authors ("why does sessions/list show as Sessions read?") → `compozy extension validate` prints the derived consent summary so the author sees it pre-install.

## Implementation Notes

`PermissionsConfig{Requires []string}` replaces `ActionsConfig`+`SecurityConfig` in `internal/extension/manifest.go`; `CapabilityChecker` consumes methods directly and derives areas via generated table; registry persistence migrates (Goose, `eng-schema-migration`). `EffectiveGrant.Security` becomes derived-only output.
