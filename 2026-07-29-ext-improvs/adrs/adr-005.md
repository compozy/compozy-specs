# ADR-005: GitHub/git-first open distribution — source union, digest sidecars, `publish` verb; skills stay on ClawHub (recorded divergence)

## Status

Accepted

## Date

2026-07-28

## Context

Third-party distribution requires a pull request to `compozy/compozy`'s own `catalog/` (the whole marketplace holds 3 entries; `compozy-catalog` has no publish verb). `ExtensionInstalledFromGitURL` is declared (`internal/extension/provenance.go:17`) and implemented nowhere. The GitHub registry path exists (`internal/registry/github`) but is off by default, digest-less (permanently "unverified"), and invisible to search and the web UI. Competitors treat the registry as a discriminated union of sources rather than one hosted API: Claude Code accepts `url|github|git|npm|file|directory`; OpenClaw layers ClawHub + npm + marketplace URLs; pi accepts npm/git/URL/path. Skills meanwhile install from ClawHub (`internal/skills/marketplace/service.go:20`) — a second, disjoint pipeline behind the same browse surface.

## Decision

Extension install sources become a first-class union: `curated | github | git | local_path`. The dev lane is **not** an install source — it is a separate lifecycle overlay owned by ADR-002; `install` can never produce dev state.

- **`github:owner/repo[@ref]`** — resolves a release via the existing `internal/registry/github` client; **enabled by default** (anonymous API for public repos; `GITHUB_TOKEN` optional). Integrity, not trust: the `compozy extension publish` verb uploads the packaged archive **plus a `.sha256` digest sidecar** to the release; when the sidecar is present the installer records the neutral integrity fact `digest_matched: true` (a mismatch always aborts). A colocated sidecar is controlled by the same repository owner as the asset — it proves the archive arrived intact, never who published it — so **every non-curated GitHub/git install stays in the unverified tier and requires the same single explicit consent, sidecar or not**. `checksum_verified: true` remains exclusive to curated installs whose digest is pinned by the catalog.
- **`git:<url>[@ref]`** — new `internal/registry/gitsrc` source (shallow clone at ref → build-artifact archive expected in the repo, or resource-only tree); always unverified-tier unless a digest sidecar convention is present.
- **`compozy extension publish`** — packages (ADR-001 build output), digests, and creates/updates a GitHub release through the API client (token required); no PR to `compozy/compozy` anywhere in the flow.
- **Discovery** — `compozy extension search` fans out: curated catalog (existing store) + GitHub topic search (`compozy-extension` topic) through the registry source's `Search`; results carry their source, tier, and integrity badge (`digest_matched`) — the UI never renders an integrity fact as publisher verification; everything installed appears in `list`/`status`/web regardless of source.
- **Curated catalog** remains the `official` tier and the cross-kind (`mcp|extension|skill`) feed it is today.
- **Skills divergence recorded**: skills keep ClawHub in this program. Trust *semantics* (tiers, digest verification, consent language, provenance shape) are shared vocabulary across kinds; pipeline convergence is a separate future decision.

## Alternatives Considered

### Alternative 1: npm as the backbone

- **Description**: Extensions are npm packages with a keyword (pi/opencode model); publish = `npm publish`.
- **Pros**: Zero registry infra; versioning/yank solved.
- **Cons**: Forces npm accounts on Go authors; discovery lives outside the product; digest/trust delegated to npm; subprocess bundles (compiled Go binaries) are a poor npm fit.
- **Why rejected**: Wrong center of gravity for a Go-binary ecosystem; GitHub releases already model versioned binary artifacts.

### Alternative 2: Self-hostable registry index format

- **Description**: eve/shadcn-style: a JSON index format anyone hosts; `compozy registry add @acme=<url>`.
- **Pros**: Maximum openness/federation.
- **Cons**: A new format + trust story + hosting burden to specify now; GitHub-first already removes the gatekeeper.
- **Why rejected for MVP**: Deferred — the source-union architecture leaves room to add it later without rework.

## Consequences

### Positive

- Publish→discover→install works with zero Compozy-side gatekeeping; `git_url` provenance finally truthful; GitHub installs get corruption detection when published with the verb — without any false trust elevation.

### Negative

- GitHub API rate limits for anonymous discovery (documented; token raises limits).
- Topic search surfaces unvetted results — mitigated by explicit tier/verification badges and unchanged consent gates.

### Risks

- Misreading the sidecar as publisher trust → structurally prevented: the sidecar can only produce `digest_matched` (integrity) and never flips tier, `checksum_verified`, consent requirements, or badges; mismatch = `ExtensionArchiveDigestMismatchError` (existing 400 path) with no consent override. Identity-backed verification (independent pinned digests or signatures) is an explicit follow-up TechSpec, not this program.
- Name squatting on topics → curated tier remains the trust anchor; provenance always shows `owner/repo`.

## Implementation Notes

`InstallSourceKind` union (`curated|github|git|local_path` — no `dev` member) replaces the boolean-ish path/slug split in `contract.InstallExtensionRequest` (normalized parser accepts `github:`, `git:`, bare `owner/repo` = curated-then-github, filesystem path = local). `defaultDaemonExtensionMarketplaceSourceLoader` grows the git source. Search merge happens in the daemon extension service (curated store + registry `Search`), not in `internal/marketplace`.
