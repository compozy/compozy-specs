# ADR-006: One contract package unifies all five structured-output pipelines in this change

## Status

Accepted

## Date

2026-08-20

## Context

Five independent typed-return pipelines exist (loop run-agent `output_schema`, Goal, ask/review `expect`, native-tool descriptors, untyped task result) over three divergent schema resolvers plus a shorthand normalizer, an `output_ref` column overloaded five ways, conflicting byte budgets (16 KiB externalize vs 64 KiB reject), no compiled-schema cache, and a layering smell (`internal/store` importing loop validation — 157 files at HEAD). #438 added settle-time re-validation checkpoints to pipeline 1 but not a shared layer. Every new consumer (the call, subagents) would otherwise become pipeline six.

## Decision

Ship **one contract package** in this change and adopt it across **all five pipelines plus the new call**: schema registry with digest pinning, a single declared-output-schema resolver, admission-time validation inside the transaction, amendment-overlay provenance, bounded previews that never truncate the stored payload, `x-compozy-kind` entity annotation, and a per-digest compiled-schema cache. Hard cuts ride along: the `output_ref` 5-way union is replaced by an explicit `{kind, schema_ref, payload_ref}` shape, the three divergent resolvers collapse into one, and the byte-budget conflict becomes a single declared per-contract budget with an explicit overflow strategy.

## Alternatives Considered

### Alternative 1: Contract package for sessions only; loops/tasks migrate later

- **Description**: New call uses the new layer; existing pipelines keep theirs.
- **Pros**: Smaller immediate diff.
- **Cons**: Two validation regimes coexist; the Issue-5 class stays half-fixed; resolver divergence persists; greenfield policy forbids the bridge period.
- **Why rejected**: Same root cause everywhere; deferring the cut multiplies rework and violates SD-002.

## Consequences

### Positive

- One resolver, one validator, one budget model — the Issue-2/Issue-5 class becomes structurally impossible for every consumer.
- The subagents feature inherits its contract layer for free.

### Negative

- Wide blast radius: loops, goal, ask/review, descriptors, task result, store layer, contracts, generated types.

### Risks

- Regression surface across loops — mitigated by the #438 settle-validation tests already in place and by phased build order (safe extraction before behavior change).

## Implementation Notes

Package location, exact Go interfaces, and the store-boundary schema/digest transport are Part II decisions (L-012 markers apply).
