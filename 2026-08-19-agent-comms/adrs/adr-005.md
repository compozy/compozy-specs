# ADR-005: The call/mailbox mechanism is disjoint from Compozy Network by a type-level rule, with a one-directional bridge

## Status

Accepted

## Date

2026-08-20

## Context

Compozy Network is a 23-table, 18-tool conversation protocol whose cost is channel-shaped (enrollment, presence, containers, bounds) and whose value is substrate-shaped (identity, durability, wake/budget, audit). A `direct` room gets ~70% of a typed call and then stops: no schema, no await verb, no typed failure, presence-bound addressing that cannot address a not-yet-spawned child. The operator's constraint is explicit: simple parent↔child exchange must not require channel machinery. Prose conventions ("prefer the light path") do not survive contact with implementers.

## Decision

The lightweight mechanism is kept **mechanically disjoint** from Network by a structural, type-level rule: its envelope carries **no** `channel`, `surface`, `thread_id`, `direct_id`, or `work_id` field — if an exchange needs any of them, it *is* a Network conversation and belongs in Network. Addressing uses the existing owner taxonomy (`participation.OwnerRef`: session | task_run | loop_run | automation_run) — never a second peer identity. The mechanism **reuses** the substrate: wake/budget accounting (ADR-004), audit vocabulary, commit-then-notify durability. Bridging is explicit and **one-directional**: a completed call may be published into a Network conversation as evidence (`say`/`trace`); Network content is never promoted into a call. Loop `channel_result` is repositioned as that Network bridge ("post to a channel, await the group's decision"); the typed call owns 1:1 returns.

## Alternatives Considered

### Alternative 1: Build on Network `direct` rooms

- **Description**: Reuse envelope + direct containers for parent↔child.
- **Pros**: No new envelope; durable timeline exists.
- **Cons**: Drags mandatory `channel`, Live enrollment with seven bounds, in-memory presence (`ErrTargetPeerNotFound`), FKs requiring both sessions to pre-exist — forecloses call-then-spawn; no schema slot.
- **Why rejected**: Cost is concentrated exactly where the operator said the ceremony is unacceptable.

### Alternative 2: Convention-only separation

- **Description**: One shared envelope; documentation says when to use which.
- **Pros**: Less code.
- **Cons**: Unenforceable; features bleed together over time; overlap becomes permanent.
- **Why rejected**: A boundary that is not type-checkable is not a boundary.

## Consequences

### Positive

- Overlap is impossible rather than discouraged; testable in the type system.
- One activation substrate and one audit vocabulary keep usage/forensics truthful.

### Negative

- `channel_result`'s current 1:1 use is a hard-cut migration (delete targets in the spec).

### Risks

- Substrate reuse creating hidden coupling to `internal/network` internals — mitigated by consuming shared primitives through extracted neutral packages where needed (Part II decides extraction points).

## Implementation Notes

The boundary criteria lists (when Network is mandatory vs when the light path applies) from slice 02 go into the spec verbatim as business rules.
